The Three Message Roles
system
Sets behavior/persona for the whole conversation. Invisible to the user — like "whispering in the assistant's ear."
user
What the human types (in ChatGPT's web UI, this is your message).
assistant
The model's generated reply.
🧪 Scenario: System message: "You are an assistant that speaks like Shakespeare." → User: "Tell me a joke... why did the chicken cross the road?" → Assistant (in-character): "To get to the other side, fair sir or madam!"
Context = the Model's "Memory"

Each conversation is stateless — the model doesn't remember anything you didn't explicitly include in the message list this call.

❌ No context → "What's my name?" → model has no idea
✅ Prior turns included in messages[] → model "remembers" your name
🧪 Scenario: Every chatbot turn re-sends the entire conversation history (system + all past user/assistant turns) as the "context" — that's literally how memory works in these APIs.
Full Example — OrderBot (Pizza Restaurant)

System message defines the whole flow

You are OrderBot, an automated service to collect orders for a pizza restaurant. Greet the customer, collect the order, ask pickup or delivery, clarify toppings/sizes/extras, summarize, confirm, then collect payment. Respond in a short, friendly, conversational style. Menu: [pizza types, toppings, drinks, sides...]

Conversation builds up context turn by turn

User
Hi, I'd like to order a pizza.
Bot
Great! We have pepperoni, cheese, and eggplant. Which would you like?
User
Medium eggplant, no extra toppings. Add fries too.
Bot
Small or large fries?

The system prompt explicitly told the bot to clarify all extras and sizes — that's why it asks about fries size before moving on.

Handoff to a Backend System (Structured Output)

Once the order conversation is done, add a follow-up instruction asking for a JSON summary — ready to submit to an order system.

Create a JSON summary of the food order. Include: 1) pizza (with size), 2) list of toppings, 3) list of drinks, 4) list of sides, and the total price.
{ "pizza": "Medium Eggplant", "toppings": [], "drinks": [], "sides": [{"item": "fries", "size": "small"}], "total_price": "$XX.XX" }

Temperature tip: use a higher temperature for natural conversation, but switch to low/zero temperature for this final structured summary — you want it predictable and parseable, not creative.

💡 Interview/practical tip: A chatbot is just: (1) a system message defining persona/rules, (2) a growing list of user/assistant turns replayed every call, (3) optionally a final low-temperature "extract structured JSON from this conversation" step to hand off to another system. That's the whole pattern.
