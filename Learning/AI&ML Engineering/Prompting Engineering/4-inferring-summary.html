🔍 Inferring with LLMs

Video summary — one model, one prompt, many text-analysis tasks

⚙️ Traditional ML Workflow

  1. Collect & label a dataset
  2. Train a model
  3. Deploy it to the cloud
  4. Repeat separately for every task (sentiment, names, topics…)

⚡ LLM Prompting Workflow

  1. Write a prompt
  2. Get results immediately
  3. One model / one API handles many tasks
  4. Zero-shot — no labeled training data needed

What "Inferring" Means Here

The model takes text as input and analyzes it — extracting labels, names, sentiment, topics, etc. All examples in the video use one running case: a customer review for a lamp.

🧪 Tasks Demonstrated

😊

Sentiment Analysis

Classify a review as positive/negative. Adding "answer in one word" makes output easy to post-process.

Result: "positive"
💢

Emotion Extraction

List up to 5 emotions the reviewer expresses — useful for gauging customer feelings in detail.

🚨

Anger Detection

Binary classifier: is the writer angry? Helps route upset customers to support/success teams.

Result: Not angry
📦

Information Extraction

Pull structured facts: item purchased, brand/company. Output requested as JSON for easy parsing.

Result: {"Item": "lamp", "Brand": "Lumina"}
🧩

Multi-Task Single Prompt

Combine sentiment + anger + item + brand into ONE prompt instead of 3–4 separate calls. Anger returned as real boolean (no quotes).

📰

Topic Inference

Given a news article, generate 5 topic labels (1–2 words each), comma-separated.

Example article: government survey → topics: survey, job satisfaction, NASA, government, employees
🎯

Zero-Shot Topic Tagging

Given a fixed topic list, output 0/1 for whether each is covered — no training data required.

Topics: NASA(1), local govt(0), engineering(0), employee satisfaction(1), federal govt(1)

🧵 Multi-Task Prompt Example (Sentiment + Anger + Item + Brand)

Identify the following items from the review text: - Sentiment (positive or negative) - Is the reviewer expressing anger? (true/false as boolean) - Item purchased - Company that made the item Format response as JSON.
{ "Sentiment": "positive", "Anger": false, "Item": "lamp with additional storage", "Brand": "Lumina" }

🔔 Real-World Use Case: NASA News Alert System

1. New article arrives
→
2. Zero-shot topic tagging
→
3. Load result into dict
→
4. If NASA = 1
→
🚨 "ALERT: New NASA story!"
⚠️ Caveat mentioned in the video: Returning topics as a plain comma-separated list (rather than JSON) makes the pipeline brittle — LLM output formatting can be inconsistent. For production, prefer requesting JSON output for reliable parsing.
