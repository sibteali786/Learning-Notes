SETUP A Tiny Neural Network (Linear Regression as 1 Neuron)

a = wx + b   (linear activation)   |   J(w,b) = ½(a − y)²

Example values: w=2, b=8, x=−2, y=2

FORWARD PROP Left → Right: Breaking J into Steps

c = wx = −4 → a = c+b = 4 → d = a−y = 2 → J = ½d² = 2

BACKPROP Right → Left: Computing All Derivatives

Verified numerically: nudging w to 2.001 makes J drop from 2 to 1.996002 — a change of −4×ε, confirming ∂J/∂w = −4.

YOUR QUESTION 1 — Reminder: The Chain Rule

The chain rule tells you how to differentiate a function of a function. If J depends on a, and a depends on c, then:

∂J/∂c  =  ∂a/∂c  ×  ∂J/∂a

Intuition: "how much does nudging c ripple through to change J?" = (how much c moves a) × (how much a moves J).

Worked example from this lesson — computing ∂J/∂c:

PieceRelationshipValue
∂a/∂ca = c + b → nudging c by ε moves a by exactly ε1

A second, cleaner worked example (outside the lecture, to make the pattern concrete):

Let J = (3x + 1)². Think of it as J = u² where u = 3x + 1.

  • ∂J/∂u = 2u (power rule)
  • ∂u/∂x = 3 (derivative of 3x+1)
  • Chain rule: ∂J/∂x = ∂u/∂x × ∂J/∂u = 3 × 2u = 6u = 6(3x+1) = 18x + 6

Check at x=1: J=(3+1)²=16. Nudge x by ε=0.001 → J=(3.003+1)²=16.024009 → ΔJ ≈ 24×ε. Formula gives 18(1)+6=24. ✓ Matches.

YOUR QUESTION 2 — Why Reusing ∂J/∂a Leads to the N+P Insight

In this graph, both w and b feed into computing a (via c=wx then a=c+b). Backprop computes ∂J/∂a only once, then reuses that single number to get both ∂J/∂w and ∂J/∂b via the chain rule — instead of recomputing "how does J respond to a change" from scratch for each parameter.

∂J/∂a is the single "hub" value reused for both parameter derivatives

Mapping the terms to N and P:

TermWhat it means hereIn this small example
Nodes (N)Every computed intermediate box in the graph: c, a, d, J (the operations chained together)4 nodes (c, a, d, J)
Parameters (P)The learnable values you actually update via gradient descent — here just w and b2 parameters (w, b)
N + P stepsBackprop computes one derivative per node (right-to-left, once each) PLUS one final derivative per parameter, reusing the node derivatives4 + 2 = 6 total derivative computations
N × P (naive)If you recomputed "effect on J" separately from scratch for every single parameter, independently tracing all the way through every node4 × 2 = 8 (small here, but explodes at scale)

At real-world scale (from the lecture): N = 10,000 nodes, P = 100,000 parameters

ApproachSteps
Backprop: N + P110,000 (~1.1×10⁵)
Naive: N × P1,000,000,000 (10⁹)

The deduction, precisely: because the graph is a chain/DAG, every node's derivative w.r.t. J only needs to be computed once (right to left, one pass). Once you have ∂J/∂a for a node, any parameter that feeds into that node (directly or through earlier nodes) can get its derivative by one extra chain-rule multiplication — no need to re-walk the whole graph per parameter. That's why total work scales additively (N+P) instead of multiplicatively (N×P).

Real-world scenario: A network with 3 hidden layers has thousands of shared intermediate activations feeding into millions of weights. Without backprop's node-reuse trick, computing each weight's gradient independently from scratch would mean re-deriving "how does the loss respond to this activation" millions of times over — computationally infeasible. Backprop's single right-to-left sweep computes each node's sensitivity exactly once, then every weight downstream just does one cheap multiplication (chain rule) to get its own gradient. This is precisely why training deep networks with millions of parameters is tractable at all.
