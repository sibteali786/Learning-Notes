WHY

🤔 Why This Lab

  • Real-world multi-class problems look exactly like this shape: several input features → one of several output categories (e.g. photo → {dog, cat, horse, other}, or word → {noun, verb, adjective}).
  • Previous labs used 2 classes (0 vs 1). This lab bumps it to 4 classes to show how the architecture and loss generalize.
  • Rather than just training and accepting the result, this lab intentionally opens up the trained weights to build real intuition for what each hidden unit is actually doing — connecting back to the ReLU-stitching intuition from earlier.

OUTCOMES

📊 What the Trained Network Actually Learned

Layer 1 (2 ReLU units)

  • Unit 0 — separates classes {0,1} from {2,3}: outputs 0 for points on the left, positive for points on the right.
  • Unit 1 — separates classes {0,2} from {1,3}: outputs 0 for points above a line, positive below it.

Together, these 2 ReLU "cuts" act like two intersecting decision lines, carving the input space into 4 quadrant-like regions — one per class.

Layer 2 (4 linear/output units)

Output unitPeaks nearSelects class
Unit 0(a₁⁽¹⁾, a₂⁽¹⁾) ≈ (0, 0)Class 0
Unit 1upper-leftClass 1
Unit 2lower-rightClass 2
Unit 3upper-rightClass 3

🔑 Key subtlety: each output unit isn't just maximized for its class in isolation — it has to be the largest among all 4 outputs for that region. This cross-unit coordination is enforced by softmax being baked into SparseCategoricalCrossentropy during training — softmax uniquely looks at all outputs together, unlike ReLU/sigmoid.

🌍 Real-World Analogy

Think of Layer 1's two ReLU units as two independent yes/no gatekeepers asking "are you left or right?" and "are you above or below?" Combining their two binary answers creates exactly 4 possible combinations — one per quadrant, one per class. Layer 2 then acts like 4 specialized judges, each one trained to raise their hand highest only when the gatekeepers' combined answer matches their assigned quadrant — and softmax makes sure only one judge "wins" per point.

WHAT WE LEARNED

🧠 Concepts Reinforced

  • Multi-class architecture: output layer needs one unit per class (here, 4).
  • Numerically stable pattern: linear output activation + SparseCategoricalCrossentropy(from_logits=True), same trick from the lecture, now used in a real trained model.
  • Softmax is layer-wide: unlike ReLU/sigmoid, softmax coordinates across all outputs simultaneously — necessary for the "winner takes all" class selection to work.
  • Hidden layers build reusable features: Layer 1's ReLU outputs become new "coordinates" that Layer 2 uses — directly connects to the ReLU piecewise-stitching intuition from the earlier tax-bracket example, just now in 2D and combined with a linear output layer.
  • You don't need to inspect internals to use a model — but doing so once builds real intuition for what's happening "under the hood."
