Adam Optimizer — Adaptive Moment Estimation

Course 2 · Improving Deep Neural Networks · Optimization Algorithms

WHY Beyond Plain Gradient Descent

Gradient descent uses one fixed learning rate α for every parameter. That's inefficient in two common situations, visualized on a contour plot of the cost function J(w,b):

Same direction, tiny steps
→ increase α to go faster
Oscillating back and forth
→ decrease α for a smoother path

WHAT Adam = Adaptive Moment Estimation

Instead of one global α, Adam gives every single parameter its own learning rate that adapts automatically during training.

wj = wj − αj · ∂J(w,b)/∂wj   |   b = b − α11 · ∂J(w,b)/∂b

e.g. with w₁…w₁₀ and b, Adam tracks 11 independent learning rates (α₁ … α₁₁) — one per parameter, not one for the whole model.

Intuition rule: if a parameter keeps moving the same direction → raise its α (speed up). If it keeps oscillating → lower its α (calm down / smooth the path).

CODE Using Adam in TensorFlow/Keras

# model — architecture unchanged
model = Sequential([
  tf.keras.layers.Dense(units=25, activation='sigmoid'),
  tf.keras.layers.Dense(units=15, activation='sigmoid'),
  tf.keras.layers.Dense(units=10, activation='linear')
])

# compile — only the optimizer changes
model.compile(
  optimizer=tf.keras.optimizers.Adam(learning_rate=1e-3), # α = 0.001 (default starting point)
  loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)
)

# fit — unchanged
model.fit(X, Y, epochs=100)

Only the optimizer argument in .compile() changes — everything else in your workflow stays the same. Adam still needs an initial α (default guess: 1e-3); it's worth trying a few values, but Adam is far more forgiving of a "wrong" choice than plain gradient descent.

COMPARE Gradient Descent vs Adam

Gradient DescentAdam
Learning rateOne global α for all paramsSeparate α per parameter, auto-adjusted
Sensitivity to α choiceHigh — bad α badly hurts trainingLow — more robust, self-corrects
SpeedSlower, especially near elongated minimaTypically much faster convergence
Usage todayFoundational / pedagogicalDe facto default in practice
Real-world scenario: Training on MNIST digit classification, you notice loss plateauing with tiny wiggling improvements for many epochs using vanilla gradient descent. Switching only the optimizer line to tf.keras.optimizers.Adam(learning_rate=1e-3) — same architecture, same data — often converges in a fraction of the epochs because Adam automatically speeds up along consistently-improving directions and dampens oscillation on noisy ones.
Practical takeaway: when unsure which optimizer to pick — default to Adam.
