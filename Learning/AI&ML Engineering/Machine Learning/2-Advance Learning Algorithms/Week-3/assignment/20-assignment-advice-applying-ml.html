Lesson 20 — Assignment: Advice for Applying Machine Learning

The full end-to-end lab: polynomial regression evaluation, bias/variance diagnosis, and applying it all to a neural network classifier.

1 Part 1 — Polynomial Regression: Setting Up the Baseline

Data comes from gen_data(), which builds a noisy quadratic dataset (y = x² + noise) alongside a clean, noise-free reference curve.

X, y, x_ideal, y_ideal = gen_data(18, 2, 0.7)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.33, random_state=1)

A degree-10 polynomial fit to a small dataset produces a huge train/test gap — err_train low, err_test high — the classic overfitting signature from Lessons 5–8, now reproduced in code.

2 Part 2 — Three-Way Split & Finding the Optimal Degree

Split% of dataUsed for

X_train, X_, y_train, y_ = train_test_split(X, y, test_size=0.40, random_state=1)
X_cv, X_test, y_cv, y_test = train_test_split(X_, y_, test_size=0.50, random_state=1)

Sweeping polynomial degree 1 through 9, the lab plots J_train and J_cv against degree — reproducing the exact U-shaped J_cv curve from Lesson 5, with optimal_degree = np.argmin(err_cv) + 1 picking the winner automatically. It also reruns the same sweep on λ (Lesson 6) and on training-set size m (Lesson 8), directly confirming: more data helps a high-variance model, but wouldn't have helped a high-bias one.

3 Part 3 — Same Diagnosis, Now on a Neural Network

The second half applies identical reasoning to a 6-class classification problem (blob-shaped clusters) using a neural network instead of polynomial regression.

Complex Model
Dense(120, relu) → Dense(40, relu) → Dense(6, linear)

"Worked very hard to capture outliers" — low training error, but visibly overfit decision boundaries and higher CV error.

Simple Model
Dense(6, relu) → Dense(6, linear)

Slightly higher training error, but lower CV error than the complex model — a smoother, better-generalizing fit.

This is the neural-network low-bias-machine story from Lesson 10 in action: the complex network easily drove training error down, but that extra capacity turned into overfitting rather than better generalization — until regularization was added.

4 Part 4 — Regularizing the Complex Model

Dense(120, activation="relu", kernel_regularizer=tf.keras.regularizers.l2(0.1))
Dense(40, activation="relu", kernel_regularizer=tf.keras.regularizers.l2(0.1))
Dense(6, activation="linear")

With L2 regularization added to the same large architecture, results end up looking "very similar to the ideal model" — confirming Lesson 10's claim that a large, properly regularized network can match or beat a small one, rather than the smaller network being inherently safer against overfitting.

A final λ sweep ([0.0, 0.001, 0.01, 0.05, 0.1, 0.2, 0.3]) shows train and CV error converging as λ increases — the same regularization/bias-variance curve from Lesson 6, reproduced for a neural network this time.

5 Clarifying Q&A

Q: What are x_ideal and y_ideal in this lab?

The clean, noise-free quadratic curve that gen_data() generates before adding noise to create the actual dataset. They're pure plotting reference — never used in training or evaluation — showing visually how far a fitted model's predictions drift from the true underlying relationship.

Q: What does x = np.linspace(0, int(X.max()), 100) do?

Creates 100 evenly-spaced x-values spanning the data's range, purely for plotting a smooth prediction curve — not used in training or error calculation at all.

Q: What does np.zeros((100, max_degree)) do?

Pre-allocates a 100-row × max_degree-column array. Each column stores the predicted y-values (over those 100 plotting points) for one specific polynomial degree's model, so all degree curves can be overlaid on one plot afterward.

Q: Besides the initial train/test gap, how did we identify high variance?

Three additional signals: (1) the degree-vs-error sweep showing the classic U-shaped J_cv curve — CV error rising again past the optimal degree while training error kept falling; (2) visual inspection of the neural network's decision boundary, described as having "worked very hard to capture outliers"; (3) directly comparing the complex and simple models side by side — complex had lower training error but higher CV error than simple, isolating the variance effect from the regularization sweep, which then confirmed it by converging train/CV error as λ increased.

Q: What does "target values are the index of the category, not one-hot encoded" mean?

With 6 classes, a label could be represented as a one-hot vector ([0,0,0,1,0,0] for class 3) or as a plain integer (3). This lab uses the plain-integer form, which is why eval_cat_err can just do a direct yhat[i] != y[i] comparison rather than comparing full vectors or taking an argmax first.

6 Signals Worth Remembering

Rising CV error after the optimal-degree point on a degree sweep = variance, independent of any single number.
A visually "wiggly" or outlier-chasing decision boundary is a qualitative overfitting tell, alongside the quantitative J_train/J_cv gap.
Train/CV error converging as λ increases is direct evidence the original gap was a variance problem, not bias.
A bigger, well-regularized network matching a smaller network's performance confirms network size itself isn't the risk — lack of regularization is.

7 Key Takeaway

Same diagnostic toolkit, two different model types

This assignment is the practical proof that everything from Lessons 5–10 — bias/variance signatures, the degree/λ/m sweeps, and the neural-network recipe — applies identically whether the model is polynomial regression or a neural network classifier. The tools don't change; only the knob being tuned does.
