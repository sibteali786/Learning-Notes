Lesson 8 — Learning Curves

Watching J_train and J_cv as training set size grows — and why more data doesn't always help.

1 The Baseline Shape: Quadratic Model

Plot J_train and J_cv against m_train (training set size) for a plain quadratic fit:

J_cv goes down as training set grows (more data → better generalization). Counterintuitively, J_train goes UP as training set grows.
1 example → perfect fit
2-3 examples → still ~perfect
4 examples → slightly off in places
5+ examples → harder to fit all perfectly

Why J_train rises: with 1-3 points, a quadratic can pass through nearly all of them exactly — training error ≈ 0. As more points get added, it becomes geometrically harder for one smooth curve to hit every point — so training error creeps up. This is the opposite of what intuition ("more data = better") might suggest for J_train specifically.

J_cv is typically higher than J_train throughout, since parameters are fit to the training set — the model has a natural advantage there that it doesn't have on held-out data.

2 High Bias Learning Curve — Why More Data Won't Save It

Both J_train and J_cv flatten out (plateau) as m_train grows — and neither ever reaches human-level performance, no matter how far the curve extends right.

Why they plateau: fitting a simple straight line, more examples don't change the line much once it's roughly settled — there's just not enough model flexibility to keep improving. Both curves flatten, with a persistent large gap to the baseline (human-level) performance.

Getting more training data will NOT by itself fix high bias.
The counterintuitive lesson

"More data is good" is a common ML instinct — but if your model architecture itself is too simple (underfitting), throwing more examples at it just gives it more points to be equally bad on. The curve is already flat; extending it further right doesn't bend it downward. Fix the model's capacity first (more features, higher polynomial degree, less regularization) before investing months collecting more data.

3 High Variance Learning Curve — Where More Data Actually Helps

Large persistent gap between J_train (can even beat human level — overfit) and J_cv. But as m_train grows, J_cv trends downward toward J_train and toward human-level performance.

With a high-order polynomial and little/no regularization, J_train stays low (sometimes unrealistically low — even below human-level error, since it's memorizing training data rather than genuinely understanding the pattern). The huge J_cv−J_train gap is the high-variance signature. But extrapolating the curves to the right: J_cv keeps trending down as more examples are added, closing the gap with J_train.

Getting more training data IS likely to help with high variance.

4 Side-by-Side: When Does More Data Help?

High Bias

Both curves plateau early and stay far from baseline. More data → curves stay flat. More data alone won't help. Need more model capacity instead.

High Variance

Large gap between J_train and J_cv, but J_cv is still trending downward. More data → gap keeps closing. More data will genuinely help.

5 Practical Note

Rarely plotted in practice

Generating a real learning curve means retraining the model repeatedly on growing subsets (100, 200, 300... examples) and recording J_train/J_cv each time — computationally expensive, so it's not commonly done as an actual plotted artifact. Still, having this mental picture of what a high-bias vs. high-variance learning curve looks like is valuable for quickly reasoning about whether more data is worth collecting, without needing to generate the plot.

6 Key Takeaway

Before you collect more data...

Check whether your model has high bias or high variance. If it's high bias, more data is largely wasted effort — the model's ceiling is already visible in the flattened curves. If it's high variance, more data is one of the most reliable fixes available, since the J_cv curve is still actively trending toward J_train.
