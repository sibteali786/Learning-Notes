Lesson 14 — Adding Data

Practical techniques for growing your dataset efficiently — targeted collection, data augmentation, and data synthesis.

1 Targeted Data Collection > "More of Everything"

Add more data of everything

Works, but slow and expensive — e.g. a full honeypot project to collect all kinds of spam. Fine when feasible, but rarely the fastest path.

Add more data where error analysis points

If error analysis (Lesson 13) showed pharma spam was 21% of errors, go find more pharma spam specifically — e.g. have labelers skim unlabeled emails just for that category. Much cheaper, much higher impact.

This connects error analysis directly to action: it doesn't just tell you what's wrong, it tells you exactly what kind of data collection effort is worth funding.

2 Data Augmentation: Modify Existing Examples

Data augmentation takes an existing training example (x, y) and applies a transformation to x that preserves the label y — creating a new, valid training example without collecting anything new.

Original letter A → rotated, enlarged, shrunk, contrast-changed. All still unmistakably "A".

More advanced: overlay a grid on the letter and apply random warping to the grid — this can turn one image into dozens of distinct-looking but correctly-labeled training examples.

3 Data Augmentation for Audio

Same principle applied to speech recognition: take a clean recording and layer realistic noise on top.

🔊 Original: "What is today's weather?"
+ Original + crowd noise → sounds like it was said in a noisy room
+ Original + car noise → sounds like it was said while driving
+ Original + bad cellphone distortion → sounds like a poor connection

One clean clip became three additional realistic training examples. This was described as a genuinely critical technique for building more accurate speech recognizers in practice.

4 The Rule: Augmented Noise Must Resemble Test-Set Noise

Representative distortions help. Random noise usually doesn't.

Warping a letter's shape, or adding crowd/car/cellphone noise to audio, works because those distortions resemble what actually shows up in real-world test data. Adding meaningless per-pixel random noise to every pixel of an image, by contrast, creates examples that don't resemble anything in the test set — and tends not to help, since the model ends up learning to handle a type of corruption it will never actually see.

5 Data Synthesis: Creating Brand-New Examples

Different from augmentation — instead of modifying a real example, you generate an entirely artificial one from scratch. Example: Photo OCR (reading text out of photographs).

1
Open a text editor with many installed fonts.
2
Type random text, vary the font, color, and contrast.
3
Screenshot the result — this becomes synthetic training data that closely resembles real photographed text.

This can generate huge volumes of realistic-looking training examples cheaply — though writing the generation code well enough to look realistic can itself take real effort. Synthetic data generation has mostly proven useful for computer vision; less so for audio or other modalities.

6 Data-Centric vs. Model-Centric AI

AI = Code (algorithm/model) + Data

For decades, most ML research took a model-centric approach: hold the dataset fixed, spend effort improving the algorithm. Today's algorithms (linear/logistic regression, neural networks, decision trees) are already quite good for many applications — which shifts the highest-leverage work toward a data-centric approach: keep the algorithm mostly fixed, and put engineering effort into the data itself — targeted collection, augmentation, or synthesis.

Why this matters practically

All three techniques from this lesson — targeted collection, augmentation, synthesis — are examples of "engineering the data." They're often a more efficient use of time than continuing to tweak model architecture once you already have a reasonably good algorithm in hand.

7 Key Takeaway

When error analysis or a bias/variance check points toward needing more data, don't default to broad, expensive collection. Consider, in order of effort: targeted collection of the specific error category, augmenting existing examples with realistic distortions, or synthesizing entirely new examples. Next up: for cases where none of this is feasible — genuinely limited data — transfer learning offers a way to borrow strength from an unrelated task.
