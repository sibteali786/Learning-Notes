Lesson 13 — Error Analysis

The second key diagnostic after bias/variance — manually reading what your model actually gets wrong, so you stop guessing where to spend your time.

1 What Error Analysis Actually Is

Take the examples your algorithm misclassified in the cross-validation set, and manually read through them, grouping them by common traits. That's it — it's a manual, qualitative process, not another formula.

Worked example

With m_cv = 500 and 100 misclassified examples, you'd read through all 100 by hand and bucket them: how many are pharmaceutical spam? How many use deliberate misspellings? How many have unusual routing? How many are phishing attempts? How many hide the message inside an embedded image?

2 The Counts Tell You Where to Focus

Out of 100 misclassified emails — pharma spam and phishing dominate; misspellings barely register.
Pharmaceutical spam21 high impact
Phishing (steal passwords)18 high impact
Spam hidden in embedded image5
Unusual email routing7
Deliberate misspellings3 low impact

Categories can overlap — one email can be pharma spam and have unusual routing and contain misspellings. Counting isn't about clean mutually-exclusive buckets; it's about spotting which traits show up most often across the misclassified set.

3 The Lesson from a Real Mistake

A cautionary story from the instructor

Significant time was once spent building sophisticated misspelling-detection algorithms for a spam classifier — only to later realize misspellings accounted for just 3 out of 100 misclassified emails. Even a perfect misspelling detector would only have fixed 3% of the errors. Wishing this error analysis had been done first, before investing in that feature, is exactly the trap this technique prevents.

From the counts above: sophisticated pharma-detection and phishing-detection features could meaningfully help; misspelling detection would barely move the needle. This directly informs the "which idea to chase" decision from the iterative loop (Lesson 12).

4 What to Do With the Categories You Find

→
Targeted data collection — not "more data" generally, but specifically more pharma-spam examples or more phishing examples, so the model gets more signal exactly where it's weak.
→
Targeted features — e.g. features for specific drug/product names for pharma spam, or checking URLs against suspicious-link patterns for phishing.

5 Scaling It Up: Sampling When There's Too Much to Read

5,000 CV examples, 1,000 misclassified — now what?

Reading all 1,000 by hand often isn't realistic given time constraints. The practical move: randomly sample ~100–200 of the misclassified examples and analyze just that subset. That's usually enough to get reliable statistics on which error categories dominate, without requiring the full read-through.

6 The One Real Limitation

Where error analysis shines

Tasks humans are naturally good at — reading an email and judging "why did the algorithm get this wrong?" is intuitive when a human could do the task themselves.

Where it's harder

Tasks even humans struggle with — e.g. predicting exactly which ad someone will click. If a human reading the example can't say what the "right" answer should have been, categorizing the error is much less useful.

7 Key Takeaway

Bias/variance + error analysis = the full diagnostic toolkit

Bias/variance analysis tells you whether more data would help at all. Error analysis tells you what kind of data or features would help most. Used together, on tasks humans can reasonably judge, this combination can save months of effort spent chasing fixes that only address a handful of the actual errors.
