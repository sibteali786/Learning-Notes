Lesson 18 — Skewed Datasets: Precision and Recall

When 99% accuracy can mean nothing — and the two metrics that actually reveal whether a model is useful.

1 The Trap: Accuracy Lies When Classes Are Skewed

A rare-disease classifier (y=1 if disease present) achieves 1% error on the test set — sounds great. But if only 0.5% of patients actually have the disease, a program that just always prints y=0 — never diagnosing anyone — beats it.

Trained Model
1% error
99% accuracy
print("y=0")
0.5% error
99.5% accuracy — but useless
The core problem

The trivial "always predict 0" program wins on accuracy, despite never diagnosing a single patient. This makes it impossible to tell whether small changes in error (0.5% → 1% → 1.2%) reflect a genuinely better model, or just how aggressively the model avoids predicting the rare class. Accuracy alone can't distinguish "useful diagnostic tool" from "does nothing."

3 Precision — "When It Says Yes, Is It Right?"

Of all patients the model predicted as positive, what fraction actually have the disease?

Precision = True Positives / (True Positives + False Positives) = 15 / (15 + 5) = 0.75 (75%)

When this model flags a patient as having the rare disease, it's right 75% of the time.

4 Recall — "Of the Real Cases, How Many Did We Catch?"

Of all patients who actually have the disease, what fraction did the model correctly detect?

Recall = True Positives / (True Positives + False Negatives) = 15 / (15 + 10) = 0.6 (60%)

The model catches 60% of the patients who truly have the disease.

5 Why This Exposes the "Always Predict 0" Trick

The dumb algorithm gets caught immediately

If a model always predicts y=0, its number of true positives is exactly zero — it never predicts positive at all. That makes recall = 0 / (0 + actual positives) = 0, instantly flagging the model as useless. Precision technically becomes an undefined 0/0 in this case, but in practice is treated as 0 too. Accuracy couldn't catch this trick; precision and recall catch it immediately.

A model with either precision or recall at (or near) zero is not a useful model — no matter how good its raw accuracy looks.

6 Key Takeaway

Two numbers, both need to be decently high

For skewed classification problems, judge a model by precision (is it trustworthy when it predicts positive?) and recall (does it actually catch the real positive cases?) together — not by accuracy alone. A model that's reasonably confident when it flags something and catches a meaningful share of real cases is doing real work, unlike a model that just avoids predicting the rare class to game its accuracy score.
