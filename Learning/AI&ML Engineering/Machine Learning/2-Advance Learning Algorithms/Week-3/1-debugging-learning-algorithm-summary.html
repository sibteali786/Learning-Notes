Lesson 1 — Debugging a Learning Algorithm

What to try when your model makes unacceptably large errors — and how to stop guessing.

1 The Setup: Regularized Linear Regression on Housing Prices

You've trained a model to predict housing prices using regularized linear regression. The cost function combines the usual squared-error term with a regularization penalty:

J(w,b) = 1/2m · Σ(fw,b(x⁽ⁱ⁾) − y⁽ⁱ⁾)² + λ/2m · Σwj²

But when you test it, it makes unacceptably large errors in its predictions. The question every ML engineer eventually faces: what do you actually try next?

2 The Six Usual Suspects

There's a standard menu of things people reach for when a model underperforms. Each can help — but on any given problem, some will be fruitful and some will be a waste of months.

→
Get more training examples
Assumes the model needs more data to generalize
→
Try smaller sets of features
Assumes the model is overfitting on irrelevant/noisy features
→
Try getting additional features
Assumes the model is underfitting — missing signal
→
Try adding polynomial features (x₁², x₂², x₁x₂, ...)
Assumes the relationship isn't linear enough
→
Try decreasing λ
Assumes regularization is too strong, causing underfitting
→
Try increasing λ
Assumes regularization is too weak, causing overfitting

3 Why This List Is Dangerous Without a Plan

Real-World Scenario

A team spends months collecting more training data, assuming that's the bottleneck. Performance barely moves. It turns out the real problem was that the model was too simple (high bias) — no amount of extra data would've fixed that. A quick diagnostic run beforehand would have revealed this in an afternoon, not a quarter.

This is the core lesson: each fix targets a different root cause (mostly: bias vs. variance, covered in later lessons), and picking the wrong one wastes real time.

Fixes for High Variance (overfitting)
  • Get more training examples
  • Try smaller sets of features
  • Try increasing λ
Fixes for High Bias (underfitting)
  • Try getting additional features
  • Try adding polynomial features
  • Try decreasing λ

4 The Fix: Run a Diagnostic First

Definition — Diagnostic

A test you run to gain insight into what is/isn't working with a learning algorithm, in order to guide what to improve.

Diagnostics take upfront time to implement — but that time is almost always worth it, because they tell you which of the six fixes above is actually likely to help, before you commit weeks or months to it.

No diagnostic → guess a fix → months of work → maybe no improvement
Diagnostic first → identify root cause → targeted fix → time well spent

5 Key Takeaway

Efficiency in ML engineering isn't about knowing more algorithms — it's about repeatedly making good decisions about what to try next. The teams that ship fast aren't smarter about the math; they're better at diagnosing before they act. This week's material builds the diagnostic toolkit (starting with evaluating model performance properly) to make that decision-making systematic instead of guesswork.
