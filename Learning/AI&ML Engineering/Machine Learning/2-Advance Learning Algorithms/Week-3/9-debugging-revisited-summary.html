Lesson 9 — Debugging a Learning Algorithm, Revisited

Closing the loop: the six fixes from Lesson 1, now mapped precisely to bias vs. variance.

1 Back to the Original Question

Recall the opening scenario: regularized linear regression on housing prices, making unacceptably large errors.

J(w,b) = 1/2m·Σ(f(x⁽ⁱ⁾)−y⁽ⁱ⁾)² + λ/2m·Σwj²

Back in Lesson 1, six things were listed as possible fixes — but without a way to know which one actually applies. Now, armed with the bias/variance diagnostic, each one maps cleanly to a specific problem.

2 The Six Fixes, Finally Mapped

Get more training examplesFixes High Variance
Try smaller sets of featuresFixes High Variance
Try getting additional featuresFixes High Bias
Try adding polynomial features (x₁², x₂², x₁x₂, ...)Fixes High Bias
Try decreasing λFixes High Bias
Try increasing λFixes High Variance

3 Why Each One Works

High Variance fixes
  • More training examples — as shown in the learning curve lesson, more data directly shrinks the J_cv−J_train gap when the model is overfitting.
  • Smaller feature set — fewer features (e.g. dropping x³, x⁴, x⁵) means less flexibility to fit noise, reducing overfitting.
  • Increase λ — forces the algorithm to keep weights small, producing a smoother, less wiggly function — directly counteracts overfitting.
High Bias fixes
  • Additional features — e.g. predicting price from size alone will never fit well if price also genuinely depends on bedrooms, floors, age. More relevant info lets the model actually reduce training error.
  • Polynomial features — gives a straight-line model the flexibility to fit curved relationships, directly improving fit on the training set.
  • Decrease λ — less penalty on weight size means more attention goes to actually minimizing prediction error on the training set.

4 The Two-Sentence Summary

High Variance → Simplify

Get more data, or reduce model flexibility (fewer features, higher λ). The goal is to stop the model from fitting noise.

High Bias → Add Power

Give the model more capacity to fit the underlying pattern: more features, polynomial features, or lower λ.

5 A Trap to Avoid: Don't Shrink the Training Set for Bias

Reducing training set size does NOT fix high bias

It's tempting to think a smaller training set is "easier" to fit well, and it is — J_train may look better. But this comes at the cost of a worse cross-validation error and worse real-world performance. Throwing away training examples to patch a high-bias number is treating the symptom, not the cause — never do this.

6 Closing Thought

"Bias and variance is one of those concepts that takes a short time to learn, but takes a lifetime to master."

Recognizing high bias vs. high variance is a skill that sharpens with repeated practice on real projects — but the systematic habit itself (check J_train and J_cv before choosing a fix) is what separates fast, deliberate iteration from months of guessing. This same bias/variance lens applies directly to training neural networks too, which is the next topic.
