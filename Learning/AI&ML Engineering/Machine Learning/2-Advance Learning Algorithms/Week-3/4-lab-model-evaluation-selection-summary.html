The practical, code-level version of Lessons 2 & 3 — feature scaling pitfalls, polynomial degree selection, and classification error metrics.

1 Feature Scaling: fit_transform vs transform

Train gets StandardScaler().fit_transform(). CV and Test only get .transform(). This trips people up every time — here's the actual reason.

fit_transform (train only)

Computes the mean & std from this data, then applies them. This is the one time you're allowed to "learn" the scaling parameters.

transform (cv / test)

Reuses the mean & std already learned from train. Never recomputes new statistics from CV/test data.

Why this matters

Your model's weights were learned on features scaled using train's mean/std. If CV/test computed their own mean/std, the number "1.0" would mean something different in each dataset — the model's learned weights wouldn't map correctly anymore. It also leaks information: CV/test are supposed to simulate genuinely unseen future data, and computing statistics from them defeats that purpose, making your evaluation optimistically biased.

3 Classification Version: Fraction Misclassified

# Set the threshold for classification
threshold = 0.5

# Record the fraction of misclassified examples for the training set
yhat = model.predict(x_bc_train_scaled)
yhat = tf.math.sigmoid(yhat)
yhat = np.where(yhat >= threshold, 1, 0)
train_error = np.mean(yhat != y_bc_train)
nn_train_error.append(train_error)

# Record the fraction of misclassified examples for the cross validation set
yhat = model.predict(x_bc_cv_scaled)
yhat = tf.math.sigmoid(yhat)
yhat = np.where(yhat >= threshold, 1, 0)
cv_error = np.mean(yhat != y_bc_cv)
nn_cv_error.append(cv_error)

The loop trains several candidate NN architectures, records train/CV error for each, then (same as the neural-network model-selection from Lesson 3) you'd pick the architecture with lowest nn_cv_error and finally check it once on test.

1
Raw logits → tf.math.sigmoid() converts to a probability between 0 and 1.
2

3
np.mean(yhat != y) → fraction of examples where predicted label ≠ true label = the misclassification rate.

4 Clarifying Q&A

Q: Why fit_transform on train but only transform on CV — I still don't fully get it.

fit_transform = "learn the scaling rule from this data, then apply it." You only ever learn that rule once, from train. CV and test then get transform = "apply the rule you already learned" — they don't get to define their own rule. If they did, a raw feature value like 2000 sq ft could get scaled differently in train vs. CV depending on each set's own mean/std, so the model (which learned weights relative to train's scale) would misinterpret CV's scaled numbers. It also prevents information about "future" CV/test data from leaking into your preprocessing pipeline.

Q: Why degree-1 in polys[degree-1] — shouldn't it match the CV degree?

It does match the same degree — degree-1 is purely converting a 1-indexed degree number into a 0-indexed Python list position. If your winning degree (chosen via lowest CV MSE) is 3, its transformer object lives at list index 2, because index 0 held degree 1's transformer. No different polynomial is being used here than the one already selected.

Q: Why fraction of error here vs. MSE for regression?

Yes — same regression-vs-classification split from Lessons 2 & 3. Regression predicts continuous numbers, so squared error captures "how far off" you were. Classification predicts discrete labels, so distance doesn't apply — you either got the label right or wrong. np.mean(yhat != y) is literally the average of a 0/1 "was this wrong" indicator across all examples, i.e. the misclassification fraction.

Q: Why do we scale only X (features), not y (target)?

Scaling exists to fix mismatched relative scales between different features (e.g. square footage in thousands vs. bedroom count in single digits), which otherwise distorts gradient descent and regularization. y is a single target value — there's no other feature it needs to be scaled relative to. Scaling y would also force you to convert every error metric back into original units to make sense of it, adding a step with no real benefit.
