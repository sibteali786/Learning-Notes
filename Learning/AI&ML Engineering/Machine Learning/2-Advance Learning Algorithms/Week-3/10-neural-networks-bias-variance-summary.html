Lesson 10 — Neural Networks and Bias/Variance

Why deep learning largely sidesteps the classic bias-variance tradeoff — and the practical recipe that follows from it.

1 The Classic Bias-Variance Tradeoff

Before neural networks dominated, model complexity was a balancing act: too simple → high bias; too complex → high variance. Choosing the "just right" polynomial degree meant trading one off against the other.

The classic U-shaped tradeoff curve — J_cv minimized somewhere in the middle, never able to escape both problems at once.
f = w₁x + b
Simple model → High bias
↔ tradeoff ↔
f = w₁x+...+w₄x⁴+b
Complex model → High variance

2 Neural Networks Break the Tradeoff

Large neural networks trained on small-to-moderate datasets are low-bias machines — make the network big enough (more layers, more units per layer) and it can almost always fit the training set well. This decouples the two problems: instead of trading bias against variance, you can address each independently.

3 The Practical Recipe

Train on training set
Does it do well on training set? (J_train)
No — high biasBigger network
Yes ↓
Check cross-validation set
Does it do well on CV set? (J_cv)
No — high varianceMore data
Yes ↓
Done!

Both failed branches loop back: a bigger network gets retrained and re-checked against J_train again; more data gets the model retrained and re-checked against J_cv again. You cycle through this loop — sometimes fighting bias, sometimes variance, at different points in development — until both checks pass.

4 The Two Real Limits of This Recipe

Limit 1 — Computation

Bigger networks cost more to train. GPUs have made this recipe practical at scale, but beyond a certain size, training becomes infeasible even with hardware acceleration. This computational trade is arguably the real driver behind the modern rise of deep learning — the recipe works, but only where enough compute exists to keep looping through "bigger network."

Limit 2 — Data availability

"Get more data" is a straightforward fix for high variance — until you can't get more. Some domains have a hard ceiling on available data, at which point this branch of the loop isn't usable anymore.

5 "Isn't a Bigger Network Just... More Overfitting?"

A common worry: won't a larger network have more variance? Not if regularized appropriately.

10 → 10 → 1 units (3 layers)
→
30 → 30 → 30 → 1 units (4 layers)
Key finding

A large neural network with appropriate regularization will usually do as well or better than a smaller one — never meaningfully worse in performance. The real cost of going bigger isn't overfitting risk, it's compute time for training and inference.

6 Regularizing a Neural Network

J(W,B) = 1/m·Σ L(f(x⁽ⁱ⁾), y⁽ⁱ⁾) + λ/2m·Σ(w²) (sum over all weights W)

Same idea as linear/logistic regression regularization — penalize the sum of squared weights across the whole network. Biases (b) are typically left unregularized, though in practice this makes little difference either way.

# Unregularized MNIST model
layer_1 = Dense(units=25, activation="relu")
layer_2 = Dense(units=15, activation="relu")
layer_3 = Dense(units=1, activation="sigmoid")
model = Sequential([layer_1, layer_2, layer_3])

# Regularized MNIST model — add kernel_regularizer to each layer
layer_1 = Dense(units=25, activation="relu", kernel_regularizer=L2(0.01))
layer_2 = Dense(units=15, activation="relu", kernel_regularizer=L2(0.01))
layer_3 = Dense(units=1, activation="sigmoid", kernel_regularizer=L2(0.01))
model = Sequential([layer_1, layer_2, layer_3])

kernel_regularizer=L2(0.01) sets λ = 0.01 for that layer's weights. You can use a different λ per layer, but using the same value across all layers is common for simplicity.

7 Key Takeaways

1. It almost never hurts to go bigger

As long as you regularize appropriately, a larger network matches or beats a smaller one. The only real downside is slower training and inference.

2. Neural networks are (usually) low-bias machines

So long as the training set isn't enormous, a sufficiently large network fits it well — which is why, in practice, variance tends to be the more common problem to fight when training neural nets, not bias.

Bias and variance still matter for neural networks — measuring both and using them to guide next steps remains one of the most useful habits in developing any learning algorithm, deep or otherwise. Next: pulling everything together into the full development process for machine learning systems.
