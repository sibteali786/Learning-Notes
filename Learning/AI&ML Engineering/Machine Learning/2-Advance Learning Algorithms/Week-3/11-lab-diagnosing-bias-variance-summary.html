With just polynomial features, training error at degree >4 drops below the baseline — those models count as low-bias. But if the baseline is set stricter (250 instead of 400), those same models are still high bias — the diagnosis depends entirely on where the baseline sits, exactly as Lesson 7 emphasized.

Adding a second real feature to the input (going from 1 feature to 2) pushes training error even closer to baseline — a second genuinely predictive feature gives the model more real signal to reduce training error, which a bigger polynomial alone couldn't fully do.

Ridge and λ in code

Ridge is sklearn's L2-regularized linear regression — the same J(w,b) = MSE + λΣw² cost from the lectures, with λ passed as the alpha parameter. The lab sweeps reg_params = [10, 5, 2, 1, 0.5, 0.2, 0.1]: at λ=10 the penalty is so strong that training error sits worse than baseline (underfitting), and as λ decreases, training error approaches baseline — the model is allowed to actually fit the data instead of being forced toward near-zero weights.

4 The Random-ID Experiment: Irrelevant Features Hurt Variance

The lab adds a synthetic "patient ID" column — a random number with zero real relationship to the target — and compares polynomial regression with 2 real features vs. 3 features (2 real + 1 random ID):

Solid = 2 real features. Dotted = 2 real features + 1 random ID. Same training error trend, but CV error diverges sharply with the random ID included.

At degree 4: training error is actually lower with the random ID included — but the gap between training and CV error is far wider than with just the 2 real features. That widening gap is the overfitting signature from Lesson 5, and it's exactly why the random ID needs to be removed.

5 More Data Closes the Gap

Finally, the lab plots an actual learning curve (Lesson 8) for a 4th-degree polynomial model as training set size grows. CV error trends downward and approaches training error — but training error stays roughly flat throughout, confirming that if this were instead a high-bias problem, more data wouldn't have moved the needle — the flat training-error line is the tell either way.

6 Clarifying Q&A

Q: How does the Ridge class work — what's it actually doing?

Ridge is sklearn's built-in L2-regularized linear regression — a drop-in replacement for LinearRegression() that adds the same λ·Σw² penalty term from the lecture's cost function. In sklearn, that regularization strength is passed as alpha (their name for λ). Higher alpha shrinks weights more aggressively (simpler model, less overfitting risk, but too high causes underfitting); lower alpha lets weights grow more freely (more flexible, but more overfitting risk). Same .fit()/.predict() interface as any other sklearn regressor.

Q: If random patient IDs have no relationship to tumor detection, how does the model know to ignore them?

It doesn't know in advance — that's the key insight. The optimizer's only goal during training is minimizing error on the training set it sees. A random ID has no true relationship to the target, but with enough polynomial flexibility and a finite sample, the model can still find some coincidental numerical pattern between specific ID values and specific training labels — not a real relationship, just noise it happens to fit. That coincidental pattern doesn't hold on the cross-validation set, since there was never a real signal to generalize — it was specific to the training sample. So training error looks fine (or even better), while CV error gets worse. The widening train/CV gap is literally the mechanism that reveals a feature is irrelevant; there's no built-in filter that flags it beforehand. A genuinely predictive feature produces a pattern that holds up on unseen data; a random one only "works" on the exact sample it was fit to.
