How Data is Represented: NumPy vs TensorFlow

Lesson 7 · Matrices, shapes, and why double brackets matter

Why This Matters

NumPy (linear algebra library) and TensorFlow (Google's deep learning library) were built years apart by different teams, so their conventions for representing data don't perfectly match. Getting this straight avoids a huge class of shape-mismatch bugs.

Matrix Basics — Rows × Columns

A matrix's dimensions are always written as (number of rows) × (number of columns).

1  2  3
4  5  6
np.array([[1,2,3],[4,5,6]])
2 × 3 matrix
0.1  0.2
-3   -4
-.5  -.6
7    8
np.array([[0.1,0.2],[-3,-4],...])
4 × 2 matrix

Each inner [...] is one row; the outer [...] groups all rows together.

⚠️ Course 1 vs Course 2 convention shift

Course 1 (linear/logistic regression) used 1D arrays ([200, 17]) to represent feature vectors. TensorFlow (Course 2) prefers 2D matrices ([[200, 17]]) — because representing data as matrices lets TensorFlow run large datasets more computationally efficiently internally.

Applying This to the Coffee Example

For a single training example — temp=200°C, duration=17 min — written the TensorFlow way:

x = np.array([[200.0, 17.0]])   # shape (1, 2) — 1 row, 2 columns (1 example, 2 features)

The double bracket isn't a typo — it's deliberately making this a 1×2 matrix, not a bare 1D list, to match TensorFlow's expected input format of (num_samples, num_features).

Tensors: TensorFlow's Own Data Type

When a Dense layer processes input, its output isn't a NumPy array — it's a tensor, TensorFlow's internal data structure for efficiently storing/computing on matrices.

x = np.array([[200.0, 17.0]])
layer_1 = Dense(units=3, activation='sigmoid')
a1 = layer_1(x)
print(a1)
# tf.Tensor([[0.2 0.7 0.3]], shape=(1, 3), dtype=float32)
PieceMeaning
shape=(1, 3)1 row × 3 columns — matches layer_1's 3 units
dtype=float3232-bit floating point number (decimal-capable)
TensorTensorFlow's term for "matrix" (technically more general, but treat it as a matrix for this course)
layer_2 = Dense(units=1, activation='sigmoid')
a2 = layer_2(a1)
print(a2)
# tf.Tensor([[0.8]], shape=(1, 1), dtype=float32)

Even a single number like 0.8 comes back as a 1×1 matrix, not a bare scalar — TensorFlow is consistent about wrapping everything in matrix form.

Converting Between Tensor ↔ NumPy

a1.numpy()   # tf.Tensor → NumPy array
# array([[0.2, 0.7, 0.3]], dtype=float32)

a2.numpy()
# array([[0.8]], dtype=float32)

You'll go back and forth constantly: load/manipulate data in NumPy → pass into TensorFlow (auto-converts to tensor) → optionally convert results back to NumPy with .numpy().

❓ Recap Q&A

?Why does x need double square brackets?

Answer: Single brackets ([200, 17]) create a 1D array with no row/column structure — that's the Course 1 convention. Double brackets ([[200, 17]]) create a proper 2D matrix of shape (1,2), which is what TensorFlow expects: (num_samples, num_features).

🎯 Real-world reading

This isn't a quirky one-off — every time you feed a batch of data into a Keras model (even a batch of size 1), it must arrive as a 2D matrix. Forgetting this and passing a 1D array is one of the most common shape-related errors beginners hit, so it's worth internalizing: rows = samples, columns = features, always.
