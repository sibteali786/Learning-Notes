This shrinking pattern — more units early, fewer near output — is a common architecture choice.

Step-by-Step: Forward Propagation

1x → a[1] (Layer 1, 25 units, so a[1] is a 25-number vector)

a[1] = [ g(w1[1]·x + b1[1]) , … , g(w25[1]·x + b25[1]) ]

Note: x could equally be written as a[0], by convention.

2a[1] → a[2] (Layer 2, 15 units, so a[2] is a 15-number vector)

a[2] = [ g(w1[2]·a[1] + b1[2]) , … , g(w15[2]·a[1] + b15[2]) ]

3a[2] → a[3] (Layer 3 = output layer, 1 unit, so a[3] is a scalar)

a[3] = g( w1[3] · a[2] + b1[3] )

4Optional threshold to get a hard label:

is a1[3] ≥ 0.5 ? → yes: ŷ = 1 (digit is "1") | no: ŷ = 0 (not a "1")

The Full Pipeline

x
→
a[1]
→
a[2]
→
a[3] = f(x)

Just like f(x) denoted the output of linear/logistic regression, f(x) now denotes the neural network's output.

Why It's Called "Forward" Propagation

Computations flow strictly left → right: x → a[1] → a[2] → a[3]. Activations "propagate" forward through the network.

AlgorithmDirectionPurpose
Forward propagationLeft → rightInference — making predictions with a trained network
Backward propagationRight → leftLearning — training/updating the network's parameters (covered next week)
🎯 Real-world reading

Forward propagation is exactly what happens every time you use a pretrained model: you download someone else's trained weights (w, b for every layer), feed in your new data as x, and run this same left-to-right computation to get a prediction — no training required. This is the "inference" step you'll hit constantly when using any pretrained model, not just this toy digit classifier.

Recap

1Forward propagation = computing a[1], a[2], … a[L] in order, left to right.

2Each layer's computation only needs the previous layer's activation vector + its own w, b.

3The final activation a[L] = f(x) is the network's prediction.

4This is inference — using a trained network. Training the weights themselves uses backpropagation (next topic).
