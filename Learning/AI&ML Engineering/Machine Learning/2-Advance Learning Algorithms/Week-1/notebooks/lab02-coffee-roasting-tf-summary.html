❓ Normalization: axis=-1

?tf.keras.layers.Normalization(axis=-1) — what does axis=-1 do?

Answer: This layer standardizes each feature to zero mean / unit variance (subtracting the mean, dividing by std-dev) — same idea as feature scaling from Course 1.

axis=-1 tells it to normalize along the last dimension — i.e. treat each column (feature) independently and compute a separate mean/std for each. For your data shaped (num_examples, num_features), the last axis is the feature axis, so:

  • Temperature column gets its own mean/std
  • Duration column gets its own mean/std

This is the correct choice whenever features are on different scales (like temp in hundreds vs duration in tens/teens) — normalizing per-feature (not globally across the whole matrix) is what makes gradient descent converge well. axis=-1 is also the default and most common setting, since it works regardless of how many dimensions your data has.

❓ np.tile — duplicating the dataset

?np.tile(Xn,(1000,1)) — what is this doing, and what do 1000, 1 mean?
Xt = np.tile(Xn,(1000,1))
Yt = np.tile(Y,(1000,1))
print(Xt.shape, Yt.shape)

Answer: np.tile(array, reps) repeats an array's contents to build a larger array. The reps tuple (1000, 1) means:

PositionAxisRepeat factor
1st value: 1000rows (axis 0)Stack the whole array 1000 times vertically
2nd value: 1columns (axis 1)Leave columns unchanged (repeat once = no change)

If Xn is a small dataset, e.g. shape (200, 2), then np.tile(Xn, (1000,1)) → shape (200000, 2) — the same 200 examples copy-pasted 1000 times in a row.

🎯 Why the lab does this

The original coffee dataset is tiny (a few hundred points). Copying it artificially inflates the dataset size so model.fit runs enough total gradient-descent steps to converge in fewer epochs — a lab convenience for teaching purposes, not something you'd do with real independent data (it doesn't add new information, just repeats the same examples).

❓ tf.keras.Input(shape=(2,)) — the first Sequential argument

?I understand arguments 2 and 3 are layers — what is argument 1?
model = Sequential([
    tf.keras.Input(shape=(2,)),
    Dense(3, activation='sigmoid', name='layer1'),
    Dense(1, activation='sigmoid', name='layer2')
])

Answer: tf.keras.Input(shape=(2,)) is not a layer that transforms data — it's a declaration of what shape of input the model should expect: here, 2 features per example (temp, duration).

This lets TensorFlow immediately know how big layer1's weight matrix needs to be (2 inputs × 3 units), so it can build/size all the parameters right away — you can inspect model.summary() before ever calling fit.

⚠️ Optional in practice

The notebook itself notes: this line can be omitted. If you skip it, TensorFlow will instead infer the input shape automatically the first time you call model.fit(x, y), once it actually sees your data. Including it upfront is just convenient for exploring/inspecting the model structure before training.

❓ Counting Parameters (L1_num_params, L2_num_params)

?How are L1 and L2 params calculated?
L1_num_params = 2 * 3 + 3   # W1 parameters + b1 parameters
L2_num_params = 3 * 1 + 1   # W2 parameters + b2 parameters
print("L1 params = ", L1_num_params, ", L2 params = ", L2_num_params)

Answer: Every Dense layer has a weight matrix W of shape (inputs × units), plus one bias per unit. Total params = (inputs × units) + units.

LayerInputsUnitsW paramsb paramsTotal
Layer 12 (temp, duration)32×3 = 636+3 = 9
Layer 23 (output of layer 1)13×1 = 313+1 = 4

General formula: params = (num_inputs × num_units) + num_units — one weight for every input-to-neuron connection, plus one bias per neuron. This is exactly what model.summary() reports for each layer.

❓ Epochs and Batches — is 6250 the batch size?

?In each epoch 6250 is the batch size, right? We divided 200000 into 10, 6250 batches each?

Answer: Close, but the math is slightly different — 6250 is the number of batches, not the batch size, and the divisor isn't 10.

TermValue hereMeaning
Total examples (after tiling)200,000Xt.shape[0]
Batch size32TensorFlow's default batch size (not something set explicitly in this lab)
Batches per epoch6250200,000 ÷ 32 = 6250
Epochs10epochs=10

So the training log line 6250/6250 [====] loss: 0.1782 means: this epoch has finished processing all 6250 batches (each of 32 examples) — not that 6250 is the batch size. The "10" in epochs=10 means the entire 200,000-example dataset is passed through 10 times total, each time broken into those 6250 batches of 32.

🎯 Quick mental model

epoch = one full pass over all the data. batch = a small chunk of examples processed together before updating weights once. batches per epoch = total examples ÷ batch size.

❓ Y.reshape(-1,) — what does -1 mean here?

?plt_layer(X, Y.reshape(-1,), W1, b1, norm_l) — what does -1 mean in Y.reshape(-1,)?

Answer: Same -1 auto-infer trick covered earlier, but going the opposite direction this time — flattening a 2D array back into 1D.

Y is likely shape (n, 1) (a column vector — 2D, from earlier reshaping for Keras). reshape(-1,) collapses it into a flat 1D array of shape (n,):

Y            # shape (n, 1) — e.g. [[0],[0],[1],[1]]
Y.reshape(-1,)   # shape (n,)  — e.g. [0, 0, 1, 1]

Here -1 still means "figure out this dimension automatically" — since there's only one dimension being specified (a trailing comma with nothing after it means "1D output"), NumPy infers it should just be n, the total element count. This is done because the plotting function plt_layer expects a flat 1D array of labels, not a 2D column — matplotlib scatter/plot functions generally want simple 1D label arrays, not (n,1) matrices.
