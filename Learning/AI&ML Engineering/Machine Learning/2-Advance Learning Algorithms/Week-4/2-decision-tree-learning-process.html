🌳 Decision Tree Learning — How the Tree Gets Built

Advanced Learning Algorithms · Building a Tree from the Cat Classification Dataset

The Build Process, Step by Step

1Root split
All 10 examples. Choose Ear shape → split into Pointy (5) / Floppy (5).
2Left branch split
5 Pointy examples → split on Face shape → Round (4, all cats) / Not round (1, dog).
3Right branch split
5 Floppy examples → split on Whiskers → Present (1, cat) / Absent (4, dogs).
Once a subset is 100% pure (all cats or all dogs), stop splitting and create a leaf node instead.

Key Decision #1 — Which Feature to Split On?

Goal: maximize purity (minimize impurity) of the resulting subsets. Compare candidate splits at the root:

FeatureLeft branch purityRight branch purity
Ear shape4/5 cats1/5 cats

Cat DNA (hypothetical)5/5 cats0/5 cats
🐾 "Cat DNA" isn't a real feature we have — it's a thought experiment showing what a perfectly pure split would look like (100%/0%). Real features only get us partway there — the algorithm picks whichever gets closest. Entropy (next video) is the formal way to score this.

Key Decision #2 — When to Stop Splitting?

🟢 Node is 100% pure
All examples belong to one class → make a leaf node.
📏 Max depth reached
Depth = # of hops from root (root = depth 0). Capping depth limits tree size.
📉 Purity gain too small
If splitting barely improves purity, it's not worth the added complexity.
🔢 Too few examples left
E.g. a node with only 3 examples → not worth splitting further.
All four criteria share one motivation: keep the tree smaller — smaller trees are less prone to overfitting.

Understanding "Depth"

If max_depth = 2, the tree is not allowed to split anything below this level — forces a smaller, simpler model.

🎯 Why Smaller Trees Avoid Overfitting (the reasoning, not proof)

Deep tree
Keeps splitting until leaves have 1–2 examples → memorizes noise in training data → high variance → great on train, poor on new data.
Shallow tree
Forced to use only the strongest, most general splits → lower variance, slightly more bias → generalizes better.
This is the same bias-variance tradeoff as regularization (λ) in linear/logistic regression — depth here plays a structural role similar to a regularization penalty.

It's not proven mathematically in this lecture — it's a statistical-learning heuristic (also echoes Occam's Razor: prefer the simplest model that fits reasonably well). It gets validated empirically later via cross-validation, not derived here.

Why This Algorithm Feels "Patched Together"

Decision trees evolved over decades — different researchers added different splitting criteria and stopping rules independently. It works very well in practice, but there's no single unifying derivation (unlike, say, gradient descent).
