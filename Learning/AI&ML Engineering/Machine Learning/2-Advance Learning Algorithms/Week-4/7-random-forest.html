🌲🌲🌲 Random Forest — Tree Ensembles

Advanced Learning Algorithms · Combining many trees for a stronger model

Why Not Just One Tree?

A single decision tree is highly sensitive to small changes in training data — swap out a few examples and the whole tree structure can change, since an early split cascades into everything below it. Solution: build many trees and let them vote.

Generating the Ensemble — "Bagged Trees"

1Training set has m examples.
2For b = 1 to B (typically B ≈ 64–128, ~100 is common): use sampling with replacement to build a new training set of size m — some original examples repeat, some are left out.
3Train a full decision tree on this resampled set.
4Repeat B times → B different (but related) trees.
5To predict: every tree votes, take the majority (classification) or average (regression).
📛 Called "bagging" — putting examples in a virtual "bag" and sampling from it. Lowercase b = current tree index, uppercase B = total tree count.

Choosing B (number of trees)

More trees never hurts accuracy.
But returns diminish past ~100 — 1000 trees just wastes compute for little gain.

The Upgrade: Random Forest

Problem with plain bagging: resampling alone often isn't enough — if one feature is clearly the strongest, most/all trees still pick it at the root, making the trees too similar to each other.

At each split: instead of choosing from all n features → randomly restrict to a subset of k < n features → pick the best feature from just that subset
Typical choice: k = √n (used for larger feature counts — tens/hundreds of features; less relevant with only 3 features like our cat example).

💬 Deep Dive: Why Does This Actually Work Better?

The problem with one tree: it's "high variance" — one early split decision cascades into a totally different tree if the training data shifts even slightly. The tree is making one big bet.
What resampling does: generates B plausible "alternate universe" versions of your training data → B different trees, each overfitting to its own resample's specific noise/quirks.
Why voting helps (the real mechanism): the noise each tree overfits to is different and mostly uncorrelated across trees — so when you average/vote, random errors cancel out. The real signal (genuinely useful patterns like "pointy ears → cat") shows up consistently across nearly all trees regardless of resample, so it survives the averaging. This is the standard statistics result: averaging many noisy-but-unbiased estimates reduces variance without adding bias.
Why feature randomization is still needed: if every tree can always pick the strongest feature, they end up structurally similar (correlated) despite different data — and correlated errors don't cancel out when you average. Forcing random feature subsets at each split decorrelates the trees, so their mistakes become independent — that's what unlocks the real benefit of averaging.
🎯 Analogy: 100 people each seeing a slightly different, partial slice of the evidence, then voting → their individual blind spots cancel out. Versus one person who saw everything but has one systematic blind spot — nothing to average against.

Key Distinctions

Bagged trees
Random resampling of training data only. All features available at every split.
Random forest
Resampling + random feature subset at every split → more diverse, less correlated trees → typically better performance.
