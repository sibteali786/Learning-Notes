The Splitting Idea

Instead of splitting on discrete categories, split on a threshold: weight ≤ t? The algorithm must decide (1) whether to split on weight at all, and (2) which threshold t to use — that's the new piece.

Try many threshold values → compute information gain for each → keep the best one

How Many Thresholds to Try?

Convention: sort all examples by the feature value, then test the midpoints between every pair of consecutive sorted values.

n training examples → n − 1 candidate thresholds to test
With 10 examples here, that's 9 threshold values tested — compute information gain for each, keep the best.

Resulting Split

Recurse as usual: build subtrees on the left and right subsets, just like with any categorical split.

Summary: Handling Continuous Features

At every node, when considering splits: test candidate thresholds → compute standard information gain for each → if the best continuous-feature split beats every other feature's IG, split there.

No new theory — just more candidate splits to try. Information gain, entropy, and the recursive algorithm all stay exactly the same.
