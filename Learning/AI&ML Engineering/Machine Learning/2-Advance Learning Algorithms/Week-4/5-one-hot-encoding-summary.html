🎯 One-Hot Encoding — Features With >2 Values

Advanced Learning Algorithms · Extending decision trees beyond binary features

The Problem

So far, every feature had exactly 2 values (Pointy/Floppy, Round/Not round, Present/Absent). But what if Ear shape can now be Pointy, Floppy, or Oval — 3 values?

Option A — direct k-way split
Split into 3 branches at once. Works, but adds complexity/asymmetry to the tree-building logic.
Option B — one-hot encoding ✅
Convert to multiple binary features so the existing binary-split algorithm keeps working unchanged.

The Transform

Rule: a categorical feature with k possible values → replace with k new binary (0/1) features. In each row, exactly one of these new columns is 1 — that's the "hot" one, hence the name.

Original ear shapePointy earsFloppy earsOval ears
Pointy100
Oval001
Floppy010
After this, every feature is back to binary (0/1) — the same decision-tree splitting algorithm from earlier applies with zero modification.

Why This Works Seamlessly for Trees

A tree can now split on "Pointy ears = 1?" as its own yes/no decision node — same mechanics as splitting on Whiskers present?. No changes needed to information gain, entropy, or the recursive splitting algorithm.

💡 Bonus: Works Beyond Decision Trees Too

One-hot encoding isn't tree-specific — it's a general technique to turn any categorical feature into numbers, which is required input for neural networks, linear regression, and logistic regression (they all expect numeric inputs, not text labels).

FeatureEncoding
Ear shape (3 values)3 one-hot columns: Pointy / Floppy / Oval
Face shape (2 values)1 binary column: Round=1 / Not round=0

Total: 5 numeric input features ready to feed into a neural net for the same cat classification task.

Key Distinctions

Binary feature (2 values)
Encode directly as a single 0/1 column — no need for multiple one-hot columns.
Categorical feature (k > 2 values)
Needs k one-hot columns — one per possible value.
