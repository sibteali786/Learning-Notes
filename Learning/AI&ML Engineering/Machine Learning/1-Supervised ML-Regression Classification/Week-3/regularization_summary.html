Machine Learning · Regularization

Why shrinking the weights fixes overfitting

A high-order model can trace the training data perfectly and still be a bad model. Regularization is the fix: penalize large parameters in the cost function so the model stays only as complex as the data demands.

01 · The Intuition

Force the extra weights toward zero

Fitting a quadratic to house prices gives a sensible curve. Adding x³ and x⁴ terms lets the curve wiggle through every training point — a textbook overfit. But what if, instead of removing those terms, we just made w₃ and w₄ very small?

quadratic fit — w₁x + w₂x² + b

4th-order fit — wiggly (orange) vs. what we want (violet)

Take the ordinary squared-error cost and bolt on a penalty: +1000·w₃² + 1000·w₄². Minimizing the sum now only works if w₃ and w₄ are both close to 0 — any large value blows the cost up. The x³ and x⁴ terms effectively vanish, and the fit collapses back to the well-behaved quadratic.

min (1/2m) ∑ (f(xⁱ) − yⁱ)² + 1000·w₃² + 1000·w₄²
Key idea

Smaller parameter values → a simpler effective model → less prone to overfitting. You don't have to delete features to simplify a model — shrinking their weights does the same job.

02 · Scaling It Up

Penalize every weight, not just the suspicious ones

With 2 features you can eyeball which ones to shrink. With 100 features — size, bedrooms, floors, age, average income, distance to the nearest coffee shop … — you have no idea in advance which ones are causing the overfit. So regularization penalizes all of w₁ … wₙ together, and lets the optimizer decide how much to shrink each one.

03 · The Regularized Cost Function

One equation, two competing goals

J(w⃗,b) = (1/2m) ∑i=1..m (fw,b(x⃗ⁱ) − yⁱ)²  +  λ/2m ∑j=1..n wj²

Term 1 — Mean Squared Error

Fit the training data well. Minimizing this alone is what plain linear regression already does.

Term 2 — Regularization

Keep every wj small. On its own, this alone would push the model toward doing nothing at all.

λ (lambda), the regularization parameter, is the dial between the two: how much do you care about fitting the data versus keeping the weights small? Two conventions worth remembering:

Convention

Both terms are scaled by 1/2m. This keeps the same λ roughly appropriate even as your training set size m grows — without it you'd have to re-tune λ every time you added data.

Convention

By convention, b is not penalized — only w₁ … wₙ. Some implementations do add a λ/2m·b² term, but in practice it makes very little difference either way.

04 · Choosing λ

Too little, too much, and just right

λ = 0

No regularization

The penalty term vanishes. The model is free to wiggle through every training point — classic overfitting.

λ ≈ right

Balanced

Weights are small but not zero. The curve smooths out while still tracking the real trend — the goal.

λ = 10¹⁰

Way too much

Every w₁…wₙ is crushed to ≈0. f(x) collapses to f(x) = b — a flat line. Classic underfitting.

The whole point of λ is to sit between these extremes: small enough that the model can still fit real structure, large enough that it can't chase noise. Later, model-selection techniques give a systematic way to pick a good value rather than guessing.

Takeaways

  • Small weights ≈ a simpler model. You don't need to know which features are "bad" — shrinking every wj lets the optimizer figure that out.
  • The cost function trades off two goals: fit the data (MSE term) vs. keep parameters small (regularization term), balanced by λ.
  • λ = 0 → overfit. λ too large (e.g. 10¹⁰) → underfit, model degenerates to f(x) = b.
  • Both cost terms are scaled by 1/2m; by convention b is excluded from the penalty.
