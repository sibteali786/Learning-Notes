Addressing Overfitting

Once a model is overfit — high variance, wiggly, memorizing rather than learning — there are exactly three levers to pull. Each one trades off something different.

Three options

1
most direct, not always possible

Collect more training data

More examples let even a high-order, many-feature model settle into a smoother, less wiggly fit — you don't have to simplify the model at all. The catch: sometimes there just isn't more data to collect (only so many houses have sold in a given location).

2
throws information away

Select fewer features

Use intuition (or, later, automatic feature selection) to keep only the most relevant features and drop the rest. Fewer features means less room to overfit — but any useful signal carried by a dropped feature is lost for good.

3
keeps every feature

Regularization

Keep all the features, but shrink the size of their weights w₁…wₘ instead of eliminating any outright. Gentler than feature selection — nothing is thrown away, its influence is just dialed down.

Number one tool against overfitting: when more labeled data is available, this is usually the highest-leverage fix — the model itself doesn't need to change.

Option 2, visualized feature selection

A house-price model with 100 candidate features and too little data to support all of them will overfit. Picking a smaller, intuition-guided subset removes that pressure — at a cost.

The disadvantage: useful features can get lost. If all 100 actually carried some signal, throwing 97 of them away throws that information away too — permanently, unless you go back and re-add them. (Automatic feature-selection algorithms, covered later in the specialization, do this more systematically than intuition alone.)

Option 3, visualized regularization

Regularization doesn't remove any feature — it shrinks the weights. Eliminating a feature is really just the extreme case of setting its weight to exactly 0; regularization achieves the same calming effect more gently, without forcing any weight all the way to zero.

Overfit

Large parameter values swing the curve wildly between points.

f(x) = 28x − 385x² + 39x³ − 174x⁴ + 100

Regularized

Same polynomial, same features — just much smaller weights.

f(x) = 13x − 0.23x² + 0.000014x³ − 0.0001x⁴ + 10

By convention, regularization shrinks w₁…wₘ only. Whether you also regularize b makes very little practical difference — most implementations, this one included, just leave it alone.

Why regularization is the default choice

Unlike feature selection, regularization keeps every feature's information available to the model — it just prevents any one of them from having an outsized effect. That's why it's used constantly in practice, including later in neural networks: you get the safety of a simpler-behaving model without deciding in advance which features to sacrifice.

Worked scenario

The same house-price model, three fixes

A model overfits on 50 house sales using a fourth-order polynomial of size. Team A waits and collects 500 more sales — the curve settles down on its own. Team B instead drops down to just size and age, sacrificing whatever signal distance to coffee shop might have carried. Team C keeps every feature but adds regularization, shrinking the higher-order weights toward zero without deciding by hand which features matter. All three curves end up far less wiggly than the original — they just got there by different trade-offs.

Recap

1 · More data
Best when available; model stays as complex as it needs to be
2 · Feature selection
Simple, but risks discarding genuinely useful signal
3 · Regularization
Keeps all features, gently shrinks their influence — the workhorse default
