Gradient Descent for Logistic Regression

Same update rule you already know from linear regression — one different ingredient hiding inside f(x) changes everything about what the model can do. Theory below, then the two hands-on labs: a from-scratch numpy implementation and the one-call scikit-learn version.

The cost function starting point

Before gradient descent can minimize anything, it needs a cost J to minimize. For logistic regression that's the log loss — it penalizes confident wrong predictions much harder than linear regression's squared error would.

cost
J(w⃗, b) = −1m mΣi=1 [ y(i) log(fw⃗,b(x⃗(i))) + (1−y(i)) log(1−fw⃗,b(x⃗(i))) ]

The update rule repeat until convergence

Gradient descent takes the familiar shape: each parameter moves opposite its own partial derivative, scaled by learning rate α. Both lines update simultaneously — compute both right-hand sides first, then overwrite both parameters together.

repeat {   j = 1…n   }
wj = wj − α ∂∂wj J(w⃗, b)
b = b − α ∂∂b J(w⃗, b)
simultaneous updates — not sequential

Working out the calculus for each partial derivative gives a surprisingly clean result:

the gradients
∂∂wj J(w⃗,b) = 1m mΣi=1 (fw⃗,b(x⃗(i)) − y(i)) xj(i)
∂∂b J(w⃗,b) = 1m mΣi=1 (fw⃗,b(x⃗(i)) − y(i))

Each term is the model's error on example i — predicted probability minus actual label — averaged over all m examples, and (for the weight gradient) weighted by that feature's value xj.

Wait — is this secretly linear regression? the twist

Squint at those two gradient formulas and they're identical in form to linear regression's. That's not a coincidence, and it's not a mistake either — it's the whole point of this lecture.

Linear regression

fw⃗,b(x⃗) = w⃗·x⃗ + b

Logistic regression

fw⃗,b(x⃗) = 11 + e−(w⃗·x⃗+b)

The update equations look the same because both were derived the same way. What's different — and it's everything — is what f(x) actually computes. Linear regression's f is a raw number that can run to ±∞. Logistic regression squashes that same linear combination through a sigmoid, so f is always a probability between 0 and 1. Same-looking gradient descent loop, two genuinely different algorithms living inside it.

What carries over unchanged reuse, don't relearn

Because the mechanics of gradient descent didn't change, neither did the tooling around it:

  • 1
    Monitor convergence with a learning curvePlot J(w,b) against iteration count. It should fall every iteration; if it doesn't, α is usually too large.
  • 2
    Vectorize the implementationReplace the per-feature, per-example loops with matrix operations — same math, far faster in code.
  • 3
    Scale your featuresRescaling features to a comparable range (e.g. −1 to 1) still speeds up convergence, exactly as it did for linear regression.

Why this matters in practice

Because logistic regression reuses the exact gradient descent machinery you already trust, debugging it means debugging one thing at a time: if the learning curve misbehaves, the fix is almost always α or feature scaling — not the algorithm itself. That's what makes logistic regression such a dependable first classifier to reach for.

Worked scenario

Tumor classification, revisited

A hospital trains this model on patient records — tumor size and patient age as features x⃗, malignant/benign as label y. After gradient descent converges (learning curve flattens), a new patient arrives with a given tumor size and age. The trained w⃗ and b plug into the sigmoid fw⃗,b(x⃗), producing not a yes/no but a probability — e.g. 0.83 — that the tumor is malignant, which the clinician then acts on.

Lab 06

Gradient descent, from scratch numpy

The optional lab implements equations (2) and (3) directly in numpy, then runs the update loop on the same two-feature tumor data set used earlier in the course.

y = 1  (malignant) y = 0  (benign)

Step 1 — compute the gradient. For every example, get the sigmoid prediction, subtract the true label to get the error, then accumulate that error into dj_dw (weighted by each feature) and dj_db:

compute_gradient_logistic.py
def compute_gradient_logistic(X, y, w, b):
    m, n = X.shape
    dj_dw = np.zeros((n,))
    dj_db = 0.

    for i in range(m):
        f_wb_i = sigmoid(np.dot(X[i], w) + b)   # prediction
        err_i  = f_wb_i - y[i]                  # error
        for j in range(n):
            dj_dw[j] += err_i * X[i, j]
        dj_db += err_i

    dj_dw = dj_dw / m
    dj_db = dj_db / m
    return dj_db, dj_dw
verified against expected outputdj_db: 0.49861806546328574 dj_dw: [0.498333393278696, 0.49883942983996693]

Step 2 — the outer loop. This is the same simultaneous-update pattern from the equations above, just wrapped to also log cost for a learning curve:

gradient_descent.py
for i in range(num_iters):
    dj_db, dj_dw = compute_gradient_logistic(X, y, w, b)
    w = w - alpha * dj_dw
    b = b - alpha * dj_db
    J_history.append(compute_cost_logistic(X, y, w, b))

Lab 07

The same model, three lines of scikit-learn

Every piece built by hand above — the sigmoid, the gradient, the update loop, the convergence check — is exactly what sklearn.linear_model.LogisticRegression does internally. The lab fits it on the identical data set:

scikit_learn_logistic.py
from sklearn.linear_model import LogisticRegression

lr_model = LogisticRegression()
lr_model.fit(X, y)

y_pred = lr_model.predict(X)
print("Prediction on training set:", y_pred)
print("Accuracy on training set:", lr_model.score(X, y))
outputPrediction on training set: [0 0 0 1 1 1] Accuracy on training set: 1.0

Perfect recovery of the labels on this small, clean, linearly-separable set — consistent with the near-zero cost the from-scratch run converged to.

  1. fit() replaces the entire hand-written gradient descent loop — scikit-learn picks its own solver and convergence criteria internally.
  2. predict() applies the learned decision boundary (probability ≥ 0.5 → class 1) to return hard labels, not raw probabilities.
  3. score() reports mean accuracy on whatever X, y you pass in — here it's re-scored on the training set itself, so this isn't a held-out estimate.

From-scratch vs. library, side by side

The from-scratch run needed 10,000 iterations, a chosen learning rate, and a hand-written gradient function to land near-zero cost. LogisticRegression() reaches the same decision boundary in one call — useful for production work, but the manual version is what makes it clear why the library call works, and what to debug if a learning curve elsewhere doesn't converge.
