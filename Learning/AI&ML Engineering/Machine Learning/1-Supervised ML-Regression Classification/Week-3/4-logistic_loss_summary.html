m = number of training examples (i = 1…m), n = number of features (j = 1…n). Target y is binary: 0 or 1. Question: given this data, how do we choose parameters w, b?

2. Why Squared Error Doesn't Work Here convex vs non-convex

J(w,b) = (1/m) Σᵢ [ ½ (fw,b(x⁽ⁱ⁾) − y⁽ⁱ⁾)² ] ← same squared-error form used in linear regression

Linear regression: f(x) = w·x + b (linear)

Convex "soup bowl" → gradient descent always finds the global minimum

Logistic regression: f(x) = sigmoid(w·x + b) (non-linear)

Non-convex, wiggly surface → gradient descent can get stuck in a local minimum
Plugging the sigmoid into the squared-error cost makes J(w,b) non-convex — many local minima, no guarantee of reaching the best (global) solution. We need a different loss function.

3. The Logistic Loss Function piecewise definition

Loss = error on a single example. Cost = average loss over the whole training set.

L(fw,b(x⁽ⁱ⁾), y⁽ⁱ⁾) =
  −log(fw,b(x⁽ⁱ⁾))    if y⁽ⁱ⁾ = 1
  −log(1 − fw,b(x⁽ⁱ⁾))  if y⁽ⁱ⁾ = 0

Case y = 1

As f(x)→1: loss→0 (correct). As f(x)→0: loss→∞ (heavily penalized for confidently predicting wrong when y=1).

Case y = 0

As f(x)→0: loss→0 (correct). As f(x)→1: loss→∞ (heavily penalized for confidently predicting wrong when y=0).

Real-life analogy: a tumor is truly malignant (y=1) but the model says "99.9% chance benign" (f≈0.001) → loss ≈ −log(0.001) ≈ huge, a strong penalty. If instead the model says "95% malignant," loss is tiny — barely any penalty, correctly rewarding a confident, correct call.

4. Combined Behavior two curves = one loss

Together, the y=1 curve and the y=0 curve behave like the squared-error parabola: 0 loss when prediction matches target, loss shoots up as prediction gets further away — but now shaped correctly for probabilities bounded in (0,1), keeping the overall cost convex.

5. Unified (Single-Line) Loss Formula easy to code

The piecewise definition can be rewritten as one algebraic expression — this is what you'll actually implement in code:

L(fw,b(x⁽ⁱ⁾), y⁽ⁱ⁾) = −y⁽ⁱ⁾·log(fw,b(x⁽ⁱ⁾)) − (1 − y⁽ⁱ⁾)·log(1 − fw,b(x⁽ⁱ⁾))

Because y is only ever 0 or 1, one of the two terms always vanishes:

  • When y=0 → the first term (multiplied by y=0) disappears, leaving −log(1−f(x)).
  • When y=1 → the second term (multiplied by (1−y)=0) disappears, leaving −log(f(x)).
Cost: J(w,b) = (1/m) Σᵢ L(fw,b(x⁽ⁱ⁾), y⁽ⁱ⁾) ← convex ⇒ gradient descent reaches the global minimum
Goal: find w, b that minimize this cost J. Because the logistic loss makes J convex (unlike squared error), gradient descent is now guaranteed to converge on the best parameters.

Goal of the lab: (1) show squared error is unsuitable for classification, (2) build & visualize the logistic loss.

Setup

import numpy as np %matplotlib widget import matplotlib.pyplot as plt from plt_logistic_loss import plt_logistic_cost, plt_two_logistic_loss_curves, plt_simple_example from plt_logistic_loss import soup_bowl, plt_logistic_squared_error plt.style.use('./deeplearning.mplstyle')

Step 1 — Recall the linear regression "soup bowl"

soup_bowl()

Reminder: squared error cost for linear regression is a smooth convex bowl — gradient descent trivially finds the bottom.

J(w,b) = (1/2m) Σ (fw,b(x⁽ⁱ⁾) − y⁽ⁱ⁾)², where fw,b(x⁽ⁱ⁾) = wx⁽ⁱ⁾ + b

Step 2 — Try squared error WITH the sigmoid (classification data)

x_train = np.array([0., 1, 2, 3, 4, 5], dtype=np.longdouble) y_train = np.array([0, 0, 0, 1, 1, 1], dtype=np.longdouble) plt_simple_example(x_train, y_train) plt.close('all') plt_logistic_squared_error(x_train, y_train) plt.show()

Now fw,b(x⁽ⁱ⁾) = sigmoid(wx⁽ⁱ⁾ + b). The resulting cost surface is not a smooth bowl — it's wiggly with potential local minima, confirming squared error is a poor fit for logistic regression.

Step 3 — Visualize the two logistic loss curves

plt_two_logistic_loss_curves()

Shows the −log(f) curve (for y=1) and −log(1−f) curve (for y=0) side by side — same intuition as Section 3/4 above. x-axis is fw,b, strictly between 0 and 1 (sigmoid output range).

Step 4 — Plot the resulting cost surface with logistic loss

plt.close('all') cst = plt_logistic_cost(x_train, y_train)

This new cost-vs-(w,b) surface is smooth and convex — no plateaus, local minima, or discontinuities — well suited to gradient descent. (Both the cost and log(cost) are plotted to show the surface still has a usable slope even where cost is small.) The plot is interactive — rotate it with the mouse to inspect the shape.

Lab conclusion: squared error loss is unsuitable for classification (non-convex once sigmoid is involved); the logistic loss function fixes this and produces a convex cost surface, which is exactly what gradient descent needs to reliably converge.
