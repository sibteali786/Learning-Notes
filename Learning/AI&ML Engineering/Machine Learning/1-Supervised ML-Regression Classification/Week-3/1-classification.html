📊 Classification & Why Linear Regression Fails

Week 3 · Lecture + Optional Lab (C1_W3_Lab01_Classification)

1. What is Classification?

Classification predicts y, which can only take a small handful of discrete values — unlike regression, which predicts any number in a continuous range.

📧 Is this email spam?
no / yes
💳 Is the transaction fraudulent?
no / yes
🩺 Is the tumor malignant?
no / yes
Binary classification = exactly two possible output classes/categories (terms used interchangeably).

Negative class (0) = absence of the thing  ·  Positive class (1) = presence of the thing

⚠️ "Negative"/"positive" ≠ "bad"/"good"! It's arbitrary which class is called 1 — e.g. spam=1 vs. not-spam=1 are both valid choices depending on the engineer.

3. Why Linear Regression Fails for Classification

Try fitting a straight line f(x) = wx + b to malignant (1) vs. benign (0) tumor data (x = tumor size), then apply a threshold at 0.5:

if f(x) < 0.5  →  ŷ = 0  (not malignant)
if f(x) ≥ 0.5  →  ŷ = 1  (malignant)
✅ With the original dataset: the best-fit line crosses 0.5 at a reasonable point — the decision boundary looks fine.
❌ Add ONE more malignant example far to the right (large tumor): the best-fit line tilts/shifts to accommodate it. The 0.5-crossing point (decision boundary) shifts right too — and now a previously-correctly-classified point (a real malignant tumor near x=3) gets misclassified as benign, even though nothing about that point changed!
Real-world scenarioImagine a hospital's tumor model correctly flags a 3cm tumor as malignant. A new patient is added to training data with a 10cm obviously-malignant tumor. Just by adding that one clear-cut case, linear regression's line shifts enough that the 3cm tumor now gets predicted "benign" — a dangerous false negative caused purely by an unrelated data point.

Root cause: linear regression outputs any real number (even <0 or >1), and a single outlier can drag the whole best-fit line, moving the decision boundary in unintended ways.

4. The Fix: Logistic Regression (preview)

Linear Regression
output: any real number
✕ unstable boundary
Logistic Regression
output: always between 0 and 1
✓ stable boundary

Despite the word "regression" in its name (kept for historical reasons), logistic regression is a classification algorithm. Its output is constrained to [0, 1], which avoids the "outlier drags the line" problem seen above. This is one of the most widely used ML algorithms for binary classification.

Plotting convention

ax[0].scatter(x_train[pos], y_train[pos], marker='x', c='red', label="y=1")
ax[0].scatter(x_train[neg], y_train[neg], marker='o', label="y=0",
              facecolors='none', edgecolors=dlc["dlblue"], lw=3)
  • Red "X" = positive examples (y=1)
  • Blue "O" = negative examples (y=0)
  • In the 1-variable plot, y=0/1 is on the vertical axis. In the 2-variable plot, there's no y-axis for the label — only marker shape/color conveys the class (since both axes are used for x₀, x₁).

Interactive linear regression demo

w_in = np.zeros((1))
b_in = 0
addpt = plt_one_addpt_onclick(x_train, y_train, w_in, b_in, logistic=False)

This launches an interactive widget where you can:

  1. Click "Run Linear Regression" → best-fit line doesn't match binary data well.
  2. Toggle the 0.5 threshold → predictions suddenly look reasonable.
  3. Click to add a new malignant point far right (~x=10) → rerun regression → the line shifts, and the x=3 point flips to incorrectly predicted "benign".
This hands-on step is the lab's core lesson: linear regression's decision boundary is not robust to new data, which is why it's unsuitable for classification.

Lab takeaways
