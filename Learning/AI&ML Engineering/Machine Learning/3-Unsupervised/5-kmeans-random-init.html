🎲 Random Initialization & Multiple Restarts

How to pick starting centroids, and why one attempt isn't enough

The Standard Way to Initialize

Always choose K < m — you need at least as many training examples as clusters. The most common initialization method: randomly pick K actual training examples and set μ₁...μ_K to sit exactly on top of them (not arbitrary random points, as earlier illustrations simplified).

Two training examples are picked at random and become the initial μ₁, μ₂ directly
Different random picks → K-means can converge to genuinely different final clusterings.

The Problem: Local Optima

With K=3 on a dataset, a lucky initialization finds a good split. But an unlucky one — say two centroids landing inside the same true group — gets K-means stuck in a worse solution.

K-means always converges — but not necessarily to the global best clustering. It can get trapped wherever it starts.

The Fix: Run It Many Times, Keep the Best

for i = 1 to 100:
    # Randomly initialize K-means (pick K random examples)
    Run K-means to convergence → get c⁽¹⁾..c⁽ᵐ⁾, μ₁..μ_K
    # Compute the cost function (distortion) for this result
    Compute J(c⁽¹⁾,...,c⁽ᵐ⁾, μ₁,...,μ_K)

# After all 100 runs:
Pick the set of clusters that gave the lowest cost J

Since J measures average squared distance to assigned centroid, comparing J across runs is an apples-to-apples way to pick the winner — lower J = tighter, better-separated clusters.

Typical range: 50–1000 random initializations. Fewer than 50 risks missing a good solution; beyond ~1000 you hit diminishing returns for the extra compute.

💡 Key Takeaways

Init = K random training examples Risk: local optima, not global best Fix: 50–1000 restarts, keep lowest J
