🔗 Finding Related Items & Limitations of Collaborative Filtering

"Similar to this one" · Squared distance between learned feature vectors · Cold start · Side information · Lead-in to content-based filtering

The Problem

You're looking at a book or movie and the site says "Here are some other books/movies similar to this one." How does it pick them? Collaborative filtering gives a nice way to do it, using the features it already learned.

Real-life scenario: on a bookstore page for one novel, a "Customers also viewed / Similar books" strip appears. Under the hood, each book has a learned feature vector, and the strip shows the books whose vectors are closest.

Learned Features: Hard to Read, Still Useful

Earlier hypothetical example

  • x₁ = how romantic, x₂ = how much action: neat and interpretable

In practice (learned automatically)

  • Individual features x₁, x₂, x₃… are quite hard to interpret ("x₁ = action movie, x₂ = foreign film" doesn't happen)
  • Collectively they still convey what the movie is like

The Method: Nearest Neighbours in Feature Space

To find items related to item i, find items k whose feature vector x⁽ᵏ⁾ is similar to x⁽ⁱ⁾, i.e. with the smallest distance:

distance(k, i) = Σl=1..n ( xl⁽ᵏ⁾ − xl⁽ⁱ⁾ )²  =  ‖ x⁽ᵏ⁾ − x⁽ⁱ⁾ ‖²

i

  • Each other item you test as a possible "related item"

Why it works: features x⁽ⁱ⁾ give a sense of what item i is about, so items with similar features turn out to be similar. The lecture says this idea of finding related items becomes a small building block for an even more powerful recommender later this week.

import numpy as np

def related_items(X, i, top_k=10):
    dist = np.sum((X - X[i])**2, axis=1)   # ‖x⁽ᵏ⁾ − x⁽ⁱ⁾‖² for every item k
    dist[i] = np.inf                              # exclude the item itself (distance 0)
    return np.argsort(dist)[:top_k]                # indices of the closest items

Limitations of Collaborative Filtering

1. Cold start problem

  • New item (e.g. a just-published movie nobody has rated): how do you rank it?
  • New user who has rated only a few items: how do you show them something reasonable?
  • With few ratings, results for that item or user may not be very accurate
  • Mean normalization (earlier video) helps a lot, but there may be even better ways to show interesting items to such users

2. No natural way to use side information

  • Only ratings are used, though you often know much more about items and users (below)

Side information you might have

About items

  • Genre
  • Movie stars
  • Studio
  • Budget
  • … and more

About users

  • Demographics: age, gender, location
  • Expressed preferences: e.g. likes some genres, not others
  • IP address → location, which may hint at interests
  • Device: mobile vs desktop
  • Web browser: Chrome vs Firefox vs Safari vs Edge users behave differently
All of these cues can be surprisingly correlated with a user's preferences. Once you've collected enough data, even the browser can hint at what a user may like.

Where This Leads: Content-Based Filtering

Collaborative filtering

  • Recommends using ratings from users who rated similar items
  • Strong, but suffers from cold start and ignores side information

Content-based filtering (next)

  • Can address many of these limitations
  • Described as a state-of-the-art technique used in many commercial applications today

💡 Key Takeaways

Related items = nearest feature vectors dist = Σ (xₗ⁽ᵏ⁾ − xₗ⁽ⁱ⁾)² = ‖x⁽ᵏ⁾ − x⁽ⁱ⁾‖² Take the 5–10 smallest Cold start: new items/users Side info is ignored → content-based filtering
Practical tips (beyond the lecture): for a large catalog, precompute each item's top-K neighbours offline instead of scanning every item per page view. Squared Euclidean distance is sensitive to feature scale, so cosine similarity or approximate nearest-neighbour search are common alternatives. Not covered in the video.
