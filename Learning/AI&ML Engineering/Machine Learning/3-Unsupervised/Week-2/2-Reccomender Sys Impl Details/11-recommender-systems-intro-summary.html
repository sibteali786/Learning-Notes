Why Recommender Systems?

Shopping sites (Amazon), streaming sites (Netflix), food-delivery apps: they recommend things you may want to buy, watch or try. Academia gives the topic some attention, but its commercial impact and practical use cases are vastly greater.

🛒 Products

  • "You may want to buy…"

🎞️ Movies

  • "You may want to watch…"

🍜 Restaurants

  • "You may want to try…"
For many companies a large fraction of sales is driven by their recommender system, so the economic value is very large. The same logic works for items like products, websites, restaurants, or which social-media articles to show.

Running Example: Predicting Movie Ratings

Users rate movies 0 to 5 stars (the lecture changes "1 to 5" to "zero to five" to make examples easier). ? = not yet rated.

Notation

  • n_u = number of users (4)
  • n_m = number of movies/items (5)
  • r(i,j) = 1 if user j has rated movie i, else 0
  • y(i,j) = rating by user j on movie i (defined only if r(i,j) = 1)

Examples from the slide

  • r(1,1) = 1: Alice rated Love at last
  • r(3,1) = 0: Alice has not rated Cute puppies of love
  • y(3,2) = 4: Bob gave Cute puppies of love 4 stars
Why r(i,j) matters: not every user rates every movie, so the system must know which ratings exist. The goal: predict the "?" entries, then recommend movies a user is likely to rate 5 stars.
Temporary assumption: we first assume we have features of each movie (romance? action?). Later in the week: what if we don't?

The Model: One Linear Regression per User

predicted rating of user j for movie i = w⁽ʲ⁾ · x⁽ⁱ⁾ + b⁽ʲ⁾
  • Each user gets their own parameters w⁽ʲ⁾ (a vector with n numbers) and b⁽ʲ⁾.
  • x⁽ⁱ⁾ is the feature vector of movie i, shared by all users.
  • It's just linear regression, fit separately for each of the n_u = 4 users.
Worked example (Alice): w⁽¹⁾ = [5, 0], b⁽¹⁾ = 0, x⁽³⁾ = [0.99, 0] → 5 × 0.99 + 0 × 0 + 0 = 4.95. Plausible: Alice loves the two romance movies and gave 0 to the two action movies, so she'd likely love Cute puppies of love (high romance, no action).
Intuition: w⁽ʲ⁾ encodes how much user j likes each kind of movie (weight on romance, weight on action).

Cost Function

Let m⁽ʲ⁾ = number of movies rated by user j. For one user j:

J(w⁽ʲ⁾, b⁽ʲ⁾) = 1/(2m⁽ʲ⁾) · Σi : r(i,j)=1 ( w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾ )²  +  λ/(2m⁽ʲ⁾) · Σk=1..n (wk⁽ʲ⁾)²

Squared error

  • Prediction vs actual rating

Only rated movies

  • Sum only over i where r(i,j) = 1; unrated entries have no y

Regularization

  • λ term over the n weights prevents overfitting
Simplification for recommenders: drop the 1/m⁽ʲ⁾ factor. It's a constant for user j, so the minimizing w and b are the same.

All users together

J(w⁽¹⁾…w⁽ⁿᵘ⁾, b⁽¹⁾…b⁽ⁿᵘ⁾) = ½ Σj=1..n_u Σi : r(i,j)=1 ( w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾ )²  +  λ/2 · Σj=1..n_u Σk=1..n (wk⁽ʲ⁾)²
Minimize with gradient descent (or any optimizer) over all w⁽¹⁾,b⁽¹⁾ … w⁽ⁿᵘ⁾,b⁽ⁿᵘ⁾ at once. The term w·x + b plays the role of f(x) in linear regression.
import numpy as np

def cost_all_users(W, b, X, Y, R, lam):
    # X: (n_m, n)   W: (n_u, n)   b: (1, n_u)   Y, R: (n_m, n_u)
    pred = X @ W.T + b                       # (n_m, n_u): every user's prediction for every movie
    err  = (pred - Y) * R                    # R masks out unrated entries (r(i,j) = 0)
    return 0.5 * np.sum(err**2) + (lam/2) * np.sum(W**2)

💡 Key Takeaways & What's Next

n_u users, n_m movies r(i,j) says who rated what pred = w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ Sum only where r(i,j) = 1 One regression per user
Open question for the next video: where do the features x₁, x₂ come from? What if you don't have features that describe the items in enough detail? The next video modifies the algorithm so you can still make recommendations.
Pros/cons of this per-user approach (beyond the lecture): it's simple, interpretable (w⁽ʲ⁾ says what a user likes) and works when good item features exist. But it needs hand-made features, can't learn from other users' behaviour, and a brand-new user with zero ratings has nothing to fit (the cold-start problem).
