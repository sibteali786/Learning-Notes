⚖️ Mean Normalization for Recommender Systems

Implementation tip · Better predictions for users with few or no ratings · Slightly faster optimization

Why Bother?

In Course 1, feature normalization helped linear regression run faster. For recommender systems with numeric ratings (1–5 or 0–5 stars), mean normalization makes the algorithm run more efficiently and perform a bit better, most of all for users with no (or very few) ratings.

Benefit 1: better predictions

  • Sensible guesses for a brand-new user

Benefit 2: faster optimization

  • Each movie's ratings now average to zero, so gradient descent runs "just a little bit faster"

The Problem: Eve Has Rated Nothing

Add a fifth user, Eve (5), who hasn't rated any movies. Look at the cost:

½ Σ(i,j):r(i,j)=1 ( w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾ )² + λ/2 Σ Σ (wk⁽ʲ⁾)² + λ/2 Σ Σ (xk⁽ⁱ⁾)²
1

Eve has no r(i,5) = 1, so none of her parameters appear in the squared-error term
→
2

Only the regularization term touches w⁽⁵⁾, so minimizing pushes it to [0, 0]
→
3

b⁽⁵⁾ isn't regularized, but initialized at 0 it stays 0
→
4

Prediction w⁽⁵⁾·x⁽ⁱ⁾ + b⁽⁵⁾ = 0 for every movie
Result: the algorithm says a new user will rate every movie 0 stars. Not helpful.

The Fix: Subtract Each Movie's Average Rating

  • μᵢ = average rating of movie i, averaged only over the users who rated it (the ? entries are ignored).
  • Every rated entry becomes y⁽ⁱ'ʲ⁾ − μᵢ (e.g. 5 − 2.5 = 2.5; 0 − 2.25 = −2.25). The ? entries stay ?.
  • These new values are the y⁽ⁱ'ʲ⁾ you train on, so each movie's ratings now have zero mean.
Data note: this lecture's matrix shows Dave's rating of Swords vs. karate as 0 (earlier lectures had it as ?). That's what makes μ₅ = 1.25 = (0+0+5+0)/4.

How Training and Prediction Change

1

Compute μᵢ per movie (rated entries only)
→
2

Subtract: y ← y − μᵢ
→
3

Learn w, b, x exactly as before on the new y
→
4

Predict w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ + μᵢ
Why add μᵢ back? The model now predicts the deviation from the movie's average. Adding μᵢ converts it to a real star rating, so you can't get an impossible negative star rating.

Eve, without normalization

  • w⁽⁵⁾ = [0,0], b⁽⁵⁾ = 0
  • Predicts 0 for every movie

Eve, with normalization

  • w⁽⁵⁾ = [0,0], b⁽⁵⁾ = 0 still
  • Movie 1: 0 + μ₁ = 2.5
  • Her first guesses = the average rating other users gave each movie
import numpy as np

def normalize_ratings(Y, R):                       # Y, R: (n_m, n_u)   R = 1 where rated
    mu = (Y * R).sum(axis=1, keepdims=True) / np.maximum(R.sum(axis=1, keepdims=True), 1)
    Ynorm = (Y - mu) * R                             # unrated entries stay 0 and are masked by R anyway
    return Ynorm, mu                                 # mu: (n_m, 1), one average per movie

Ynorm, mu = normalize_ratings(Y, R)
# ... train W, b, X on Ynorm ...
pred = X @ W.T + b + mu                              # add the mean back for real star ratings

Normalize Rows or Columns?

Per-movie mean (used here)

  • Each movie's ratings get zero mean (the "rows" of the matrix)
  • Helps a new user who has rated few or no movies
  • The lecture sees this as more important
  • Recommended for this week's practice lab

Per-user mean (the alternative)

  • Each user's ratings get zero mean (the "columns")
  • Would help a brand-new movie nobody has rated
  • Judged less important: you probably shouldn't show a movie with no ratings to many users anyway, since you know little about it

Next video: implementing collaborative filtering in TensorFlow.
Practical tips (beyond the lecture): guard against a movie with zero ratings when computing μ (division by zero). Mean normalization gives a popularity baseline for cold-start users, but it can't personalize until they rate something. For a stronger cold-start, combine it with content features (genre, demographics) or ask new users to rate a few items on sign-up.
