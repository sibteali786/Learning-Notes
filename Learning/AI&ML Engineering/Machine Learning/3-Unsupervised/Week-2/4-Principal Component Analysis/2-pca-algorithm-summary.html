The PCA algorithm

Last video: PCA finds new axes so you can use fewer features. This video shows how it chooses them: preprocess, project examples onto a candidate axis, and prefer the axis where the projections are most spread out. It also covers the math for one example, extra axes, why PCA is not linear regression, and reconstruction.

1. Setup and preprocessing

Slide: “PCA algorithm”.

The data

  • Five training examples with two features, x1 and x2. One example has coordinates x1 = 10, x2 = 8.
  • Unsupervised: only x1 and x2, no label y.
  • Goal: replace the two features with one new axis z that still represents the data well.

Preprocess first

  1. Normalise to zero mean: subtract each feature’s mean (already done in the video’s plots).
  2. Feature scaling if the features have very different ranges. Example from Course 1, Week 2: x1 = house size (1,000 to a couple of thousand sq ft) vs x2 = number of bedrooms (a small number).

After this, the origin (0, 0) is the centre of the data.

2. Choose an axis by projecting onto it

Slides: “Choose an axis” (three versions).

What “project” means

Take an example and drop a line segment at 90° to the z-axis down to the axis. The foot of that segment is the projection, and its position along z is the one number that now represents the example (instead of two).

Not bad

Axis = the x1 axis

For this dataset the x1 axis already keeps the five projected points pretty spread apart, so quite a lot of the variation is still captured.

Not a good axis

Projections squished together

A tilted axis makes the five projected points bunch up. Their variance is much smaller, so you capture much less of the original information.

Best: principal component

Projections far apart

The axis along the data’s long direction. Projected dots are far apart, capturing the most information. It is called the principal component: the axis with maximum variance.

Rule: if you want one feature, PCA picks the principal component, the axis where the projected data has the largest possible variance.

Lecture’s link between the two views: maximising the spread of the projections corresponds to minimising the distances each point has to move to be projected onto z (the short 90° segments). They are two ways of saying the same thing.

3. The math for one example

Slide: “Coordinate on the new axis”. Suppose PCA gave the z-axis a direction, described by a length-1 vector. Here it is [0.71, 0.71] (really [0.707…, 0.707…], rounded).

z = x · v = [2, 3] · [0.71, 0.71] = 2×0.71 + 3×0.71 = 3.55
  • Projection formula: the dot product of the example’s coordinates with the unit vector along z.
  • 3.55 is the distance from the origin to the projected point along z. This one number now represents the example (it had two: 2 and 3).
Rounding detail (my check): with the exact 0.7071…, z = 5 × 0.7071 = 3.5355, which the lecture shows as 3.55 because it used the rounded 0.71. The idea is unchanged.

At 45° with the point (2, 3) you get z ≈ 3.54, reconstruction ≈ (2.5, 2.5), error ≈ 0.71 (the lecture’s rounded numbers: 3.55 and 2.52).

4. Reconstruction: going back from one number

Slide: “Approximation to the original data”.

  • Given only z = 3.55, can you recover the original (x1, x2)? Not exactly, because one number holds less information than two. You can approximate it. This step is called reconstruction.
(x̂₁, x̂₂) = z × [0.71, 0.71] = 3.55 × [0.71, 0.71] = [2.52, 2.52]
  • The original was (2, 3); the approximation (2.52, 2.52) is “not that far”. The gap is the little line segment between them (the lost part).
  • So one number gives a reasonable approximation of the two original coordinates.

5. More principal components

Slide: “More principal components”.

  • The second axis is always at 90° (perpendicular) to the first. A third is at 90° to both the first and second, and so on for every extra axis.
  • “Perpendicular” is just the mathematician’s word for 90°.
  • Example: 50 features, 3 principal components. The data is then described by three numbers (z1, z2, z3) per example.

6. PCA is not linear regression

Slides: “PCA is not linear regression” (two slides). A very common question, and the lecture’s answer is: totally different algorithm.

Linear regressionPCA
TypeSupervisedUnsupervised
DataFeatures x and a label yFeatures x1…xn only (up to x50 or more)
Special feature?Yes: y is treated speciallyNo: all features are treated equally
GoalFit a line so predictions are close to the true yFind an axis z that retains as much variance (information) as possible
Distance minimisedVertical, along the y-axis (prediction vs true label)Perpendicular to the axis z (the projection segments)
Use it to…Predict the value of yReduce the number of features, e.g. to visualise

Symmetric four-point example (slide 2)

Regression can only fit a flat line here (f(x) = 0). PCA picks the vertical direction, where the points are most spread out.

Why the two look alike in 2D

With only two features drawn on a flat screen, a fitted line and a principal axis can look similar. With more than two features, which is most cases, the difference is very large, and the algorithms are used for totally different purposes and give very different answers.

Alternatives and trade-offs

My additions, not from the lecture. The scikit-learn video is next.

ChoiceProsCons
Preprocess with mean-centering onlySimplest; fine when features are on similar scalesWith very different scales (square feet vs bedrooms) the large-range feature can dominate the variance. The lecture says to scale first in that case
Mean-centre and scale featuresNo feature wins just because of its unitsAn extra step, and you lose the original units when interpreting axes
Keep more principal components (2 or 3 vs 1)Reconstruction is closer to the original; 2 to 3 can be plottedLess compression. The lecture does not say here how to choose how many
Predicting y after PCAFewer inputs for a supervised model (a common use, not covered here)The axes are chosen without looking at y, so a high-variance axis is not guaranteed to be useful for predicting y

Project and reconstruct in NumPy (illustrative, not from the lecture)

import numpy as np

x = np.array([2.0, 3.0])
v = np.array([1.0, 1.0]) / np.sqrt(2)     # unit vector for the z-axis (0.7071, 0.7071)

z     = x @ v                             # projection: 3.5355
x_hat = z * v                             # reconstruction: [2.5, 2.5]
error = x - x_hat                         # what was lost: [-0.5, 0.5]

With the lecture’s rounded 0.71 you get 3.55 and [2.52, 2.52]. The exact vector gives 3.5355 and [2.5, 2.5]. In practice scikit-learn finds v for you (next video).

Key takeaways

  • PCA is unsupervised. Preprocess with zero mean, and feature scaling if ranges differ a lot.
  • It chooses an axis, projects each example onto it at 90°, and prefers the axis whose projections have the largest variance (most information kept). That axis is the principal component.
  • Projection formula: z = x · v, with v a length-1 vector. Lecture: [2, 3] · [0.71, 0.71] = 3.55.
  • Reconstruction gives an approximation: z × v = [2.52, 2.52], close to the original (2, 3), from one number.
  • Extra axes (z2, z3…) are always perpendicular to the earlier ones. 50 features can be reduced to 3 principal components.
  • PCA ≠ linear regression: no label y, all features treated equally, perpendicular rather than vertical distances. Regression predicts y; PCA reduces the number of features.
