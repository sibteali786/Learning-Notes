👍 Collaborative Filtering with Binary Labels

From star ratings to like / engage · Linear regression → logistic regression, again · Binary cross-entropy loss · J(w, b, x)

Why Binary Labels?

Many important recommender applications don't get a 0–5 star rating. The user just somehow signals "liked / engaged with this item" or "didn't". The generalization is very reminiscent of going from linear regression to logistic regression in Course 1: from predicting numbers to predicting a binary label.

What 1, 0 and ? Mean

1 = engaged

  • Engaged after being shown the item

0 = did not engage

  • Was shown the item but did not engage

? = not yet shown

  • The user hasn't seen it, so they couldn't decide

Step 1: The Model — Wrap It in a Sigmoid

Previously (ratings)

predict y⁽ⁱ'ʲ⁾ as w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾

Now (binary labels)

P( y⁽ⁱ'ʲ⁾ = 1 ) = g( w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ )
g(z) = 1 / (1 + e−z)  (the logistic function)
Output is now a probability that user j engaged with / liked item i, always between 0 and 1.

Step 2: The Cost Function — Binary Cross-Entropy

Previous cost (squared error), where w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ plays the role of f(x):

½ Σ(i,j):r(i,j)=1 ( w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾ )² + λ/2 Σ Σ (xk⁽ⁱ⁾)² + λ/2 Σ Σ (wk⁽ʲ⁾)²

For binary labels, the prediction becomes f(w,b,x)(x) = g(w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾) and the loss for a single example is the one from logistic regression:

L( f, y⁽ⁱ'ʲ⁾ ) = − y⁽ⁱ'ʲ⁾ · log( f )  −  ( 1 − y⁽ⁱ'ʲ⁾ ) · log( 1 − f )
Also called the binary cross-entropy cost. It's the standard loss for logistic regression, binary classification and training neural networks.

Summed over every (user, item) pair that has a label:

J( w, b, x ) = Σ(i,j) : r(i,j)=1 L( f(w,b,x)(x), y⁽ⁱ'ʲ⁾ )
Only labeled pairs count: r(i,j) = 1 now means "item was shown and we have a 0/1 outcome". The "?" entries are excluded, same as before.
Regularization note (my addition): the slide writes J as just the sum of losses. In practice you typically keep the same λ terms on w and x as before, the same idea as in the previous version.
import numpy as np

def cost_binary(X, W, b, Y, R, lam):
    # X: (n_m, n)  W: (n_u, n)  b: (1, n_u)  Y, R: (n_m, n_u)   R = 1 where a 0/1 label exists
    f = 1 / (1 + np.exp(-(X @ W.T + b)))                  # g(w·x + b) for every user/item pair
    eps = 1e-12
    L = -(Y*np.log(f + eps) + (1 - Y)*np.log(1 - f + eps)) * R   # mask out '?' entries
    return L.sum() + lam/2 * (np.sum(X**2) + np.sum(W**2))

Pros/cons (beyond the lecture): binary engagement data is plentiful and cheap to collect, and the probabilities let you rank items. But a "0" is ambiguous (not interested vs. just didn't notice), clicks can be biased by what was shown, and with all-positive data you need to sample negatives or treat the problem carefully.
