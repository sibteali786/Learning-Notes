Q1"x_movie must satisfy all the users while w_user must satisfy all the movies"

In plain words: a movie's feature vector x⁽ⁱ⁾ is one single vector, but it appears in the prediction for every user who rated that movie. A user's vector w⁽ʲ⁾ is likewise one single vector used for every movie that user rated. Each rating gives one requirement:

w⁽ʲ⁾ · x⁽ⁱ⁾ + b⁽ʲ⁾ ≈ y⁽ⁱ'ʲ⁾    (one equation per rating, where r(i,j) = 1)
  • Movie i rated by 4 users ⇒ x⁽ⁱ⁾ has to produce 4 good predictions at once (one against each user's w).
  • User j rated 50 movies ⇒ w⁽ʲ⁾ has to produce 50 good predictions at once (one against each movie's x).
  • Each unknown is shared between many equations, and the unknowns are learned simultaneously, so none can be set in isolation. Everything is a compromise that minimizes the total squared error.
Why that gives the name: all the users "collaborate": your ratings help pin down movie vectors, which in turn help predict other users' ratings. A single user couldn't determine the features alone (the lecture's point).

Q3How does cofi_cost_func_v work?

def cofi_cost_func_v(X, W, b, Y, R, lambda_):
    j = (tf.linalg.matmul(X, tf.transpose(W)) + b - Y) * R
    J = 0.5 * tf.reduce_sum(j**2) + (lambda_/2) * (tf.reduce_sum(X**2) + tf.reduce_sum(W**2))
    return J

tf.linalg & matmul

  • tf.linalg = TensorFlow's linear-algebra module (matrix multiply, inverse, etc.).
  • tf.linalg.matmul(A, B) is matrix multiplication (same as tf.matmul or A @ B): rows of A dotted with columns of B.
  • Not the same as *, which multiplies element by element.

Why transpose W?

  • X is (movies, features), W is (users, features). Matrix multiply needs inner sizes to match: (m×n)·(n×u).
  • tf.transpose(W) is (features, users), so X @ Wᵀ is (movies, users).
  • Entry (i, j) = row i of X · row j of W = x⁽ⁱ⁾·w⁽ʲ⁾, the prediction for every movie/user pair at once.

tf.reduce_sum

  • "Reduces" a tensor by adding its elements. With no axis given it adds everything into one scalar.
  • x = [[1,2],[3,4]] → reduce_sum(x) = 10
  • axis=0 → [4, 6] (down each column); axis=1 → [3, 7] (across each row)
  • Here it turns the error matrix into the single cost number.

The other pieces

  • + b: b is (1, users); it broadcasts down the rows, adding b⁽ʲ⁾ to every entry of column j.
  • − Y: element-wise prediction − actual.
  • * R: element-wise mask: zeroes the errors of unrated pairs (Y holds fake 0s there).
  • j**2: square every error; 0.5 * the sum = the squared-error term.
  • (lambda_/2)(ΣX² + ΣW²): regularization. b is not regularized.
J = ½ Σi,j Rij·( x⁽ⁱ⁾·w⁽ʲ⁾ + b⁽ʲ⁾ − Yij )² + λ/2 ( ΣX² + ΣW² )
With the lab's training shapes: X (4778, 100) @ Wᵀ (100, 444) → (4778, 444), one prediction for each of the 2,121,432 movie/user cells, all computed in one matrix multiply instead of three nested loops. Why TensorFlow ops (not NumPy)? So GradientTape can record them (Q4).
Spot the quirks: the docstring says "content-based filtering", but this is the collaborative filtering cost (a docstring slip). The local variable j is the error matrix, unrelated to the user index j in the loop version. During training, Y is passed as Ynorm.

Q4What does GradientTape do behind the scenes?

Course 1 (by hand)

  • You derived ∂J/∂w = (1/m) Σ (f−y)·x and ∂J/∂b = (1/m) Σ (f−y) and coded loops

Course 2 (neural nets)

  • Backprop on a computation graph (if you did the optional derivative / backprop labs)
  • model.fit hides it; internally Keras uses a GradientTape too

This lab

  • You write only the cost; the tape produces ∂J/∂X, ∂J/∂W, ∂J/∂b

Diagram note: a simplified picture of the graph for this cost. TensorFlow's real graph has more fine-grained nodes, and the reverse pass is conceptually backpropagation applied to any computation.

The gradients you would have derived by hand for this cost

Let E = (X·Wᵀ + b − Y) ⊙ R (the masked error matrix). Since R is 0/1, ∂/∂(prediction) of ½ΣE² is just E. Then, by the chain rule:

∂J/∂X = E · W + λX   |   ∂J/∂W = Eᵀ · X + λW   |   ∂J/∂b = column sums of E 
# what tape.gradient(cost_value, [X, W, b]) returns, written out by hand (shapes in comments)
E  = (X @ W.T + b - Y) * R            # (n_m, n_u)
dX = E @ W   + lambda_ * X            # (n_m, n)
dW = E.T @ X + lambda_ * W            # (n_u, n)
db = E.sum(axis=0, keepdims=True)     # (1, n_u)
Same idea as Course 1's loop-written gradient, just for matrices. The tape gets the same numbers without anyone deriving or coding these formulas.

Four ways to get a derivative

MethodHowProsCons
By handderive and code formulasfull understanding; fast codeerror-prone; redo for every new cost
Numerical (finite differences)(J(w+h) − J(w−h)) / 2htrivial to write; great for checkingone or two cost evaluations per parameter, hopeless for 522,644 parameters; approximate
Symbolicmanipulate the formula as an expressionexact formula outexpression blow-up on big programs
Autodiff (GradientTape)record ops, apply chain rule on numbers in reverseexact, about the cost of a few forward passes for all parametersstores intermediates (memory); you must use TF ops inside the tape
Details worth knowing: trainable tf.Variables are watched automatically. A plain tensor needs tape.watch(t). After one tape.gradient() call the tape's resources are released unless you create it with persistent=True (that's why a fresh tape is built every iteration).
Adam step (after the gradients): for each variable it keeps running averages of the gradient and of the squared gradient, then moves by lr · m̂ / (√v̂ + ε), giving each parameter its own step size. Here lr = 0.1, 200 iterations, λ = 1.

💡 What We Learned

Concepts

  • Ratings live in a sparse matrix Y with a mask R; only R = 1 cells count.
  • Prediction = X·Wᵀ + b for every movie/user pair.
  • Movie vectors and user vectors are learned together and constrain each other (Q1).
  • Mean normalization: train on Y − μ, add μ back for predictions, so a new user starts at the movie averages.
  • The cost = masked squared error + λ/2 on X and W (not on b).

Skills

  • Loop version vs vectorized cost, verified against the same expected values.
  • Boolean masking in NumPy (Q2) and broadcasting / reduce_sum in TensorFlow (Q3).
  • A custom training loop: GradientTape → gradients → Adam (Q4), because the cost doesn't fit Dense layers + model.fit.
  • Turning raw predictions into usable recommendations by filtering on popularity.

🚀 What More Can Be Learned From This Lab

1. Honest evaluation

  • Hide ~10% of known ratings, train on the rest, report RMSE on the hidden ones
  • Tune λ, number of features (10 vs 100) and learning rate on that validation set
  • Watch for over-fitting: training loss falls forever, validation loss does not

2. Related movies (last lecture)

  • Use the learned X to find movies similar to one you like
  • Check whether neighbours "make sense" (sequels, genre)

3. Cold-start experiments

  • Keep only 1, 3, 5 of your 13 ratings and see how the recommendations change
  • Run once without mean normalization and compare

4. Engineering

  • Wrap the training step in tf.function for speed
  • Try plain gradient descent vs Adam, other learning rates
  • float32 instead of float64 to halve memory

5. Better recommendation logic

  • Exclude movies already rated, require a minimum rating count, blend with popularity
  • Evaluate lists with precision@k / NDCG, not just rating error
