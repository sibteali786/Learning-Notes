Deep learning for content-based filtering: the lab, explained

The lab builds the two-tower network from the lectures on real MovieLens data, trains it, and uses it three ways: recommend for a new user, compare predictions for an existing user, and find similar movies. This page walks the whole notebook, decodes the snippets that are easy to trip on, and answers your four questions first.

Your questions, answered

1. “Is the author saying the per-genre average rating per user is derived/engineered?”

Yes. MovieLens only gives raw ratings (user, movie, stars). It has almost no user information. So the lab computes the user content from those ratings: for each user and each of 14 genres, the average rating that user gave to movies of that genre. That is feature engineering (the lab points back to Course 1, Week 2, Lab 4).

  • User content = entirely engineered: 14 per-genre averages. Three more columns (user id, rating count, rating ave) are carried only for interpreting the data and are not fed to the network.
  • Movie content = original + one engineered: original = release year and the 14-genre one-hot vector; engineered = ave rating, derived from all users’ ratings of that movie. movie id is not used in training.
  • A genre the user never rated shows 0.0, which means “no data”, not “dislikes”.

3. “Where does 'y' is 4 … user 2 rated movie 6874 as a 4 come from?”

It is not computed anywhere. It comes from row alignment. The three arrays have the same number of rows, and row k of each is one training example:

  • user_train[0] is user 2 (first row of your user table).
  • item_train[0] is movie 6874 (first row of your movie table).
  • y_train[0] is 4.0 (the first value in y_train[:5]: [4. 3.5 4. 4. 4.5]).

The lab states this in section 3.1: the training set is split into a user array and an item array “with the same number of entries”, and a single example is a row from both plus a rating from y_train. Try the row picker in section 2 below. Do not confuse it with the movie’s average rating column. That is a different number that just happens to also be 4.0 here.

4. “How does the scaling snippet work, step by step?”

See section 3. In one line: StandardScaler turns each input column into “how many standard deviations from its mean”, and MinMaxScaler(−1, 1) squeezes the ratings into −1…1 to match the network’s output range. Each scaler learns from the data once (fit) and is then reused (transform) for new data and for undoing (inverse_transform).

Lab at a glance

1. The dataset

MovieLens “ml-latest-small”, reduced

  • Original: roughly 9000 movies, 600 users, ratings 0.5 to 5.0 in 0.5 steps.
  • Reduced to movies since 2000 and popular genres: 397 users, 847 movies, 25,521 ratings.
  • Per movie: title, release date, one or more genres (for example Toy Story 3: Adventure, Animation, Children, Comedy, Fantasy).
  • Almost nothing about users beyond their ratings, which is why user features are engineered.

Why 50,884 training rows from 25,521 ratings?

The lab says some ratings are repeated to boost examples of under-represented genres. That is why there are 50884 training vectors. Genre counts show why: Action has 10,377 ratings, but Documentary only 280.

Side effect to be aware of (my observation): if a duplicated row is shuffled into both train and test, the test set contains “twins” of training rows. That can make test loss look a little better than real generalisation.

3. Preparing the data (§3.2): the scaling snippet, step by step

# 1. keep untouched copies
item_train_unscaled = item_train
user_train_unscaled = user_train
y_train_unscaled    = y_train

# 2. scale movie inputs
scalerItem = StandardScaler()
scalerItem.fit(item_train)
item_train = scalerItem.transform(item_train)

# 3. scale user inputs
scalerUser = StandardScaler()
scalerUser.fit(user_train)
user_train = scalerUser.transform(user_train)

# 4. scale the target to -1..1
scalerTarget = MinMaxScaler((-1, 1))
scalerTarget.fit(y_train.reshape(-1, 1))
y_train = scalerTarget.transform(y_train.reshape(-1, 1))

# 5. prove nothing was lost
print(np.allclose(item_train_unscaled, scalerItem.inverse_transform(item_train)))
print(np.allclose(user_train_unscaled, scalerUser.inverse_transform(user_train)))
  1. Keep the originals. You need the unscaled arrays later to display readable results (section 5 prints unscaled movies).
  2. StandardScaler on movies. fit measures, per column, the mean μ and standard deviation σ. transform then replaces each value with (x − μ) / σ. Every column ends with mean 0 and spread 1, so a column in the thousands (year) cannot swamp a 0/1 flag. This speeds up training (as in Course 1, Week 2).
  3. StandardScaler on users. Same, with its own μ and σ. The two scalers are separate because user and movie columns are different.
  4. MinMaxScaler((−1, 1)) on ratings. reshape(−1, 1) turns the 1-D list into a column, because scikit-learn expects 2-D input (rows × features). It learns the min and max rating, then maps:
    y′ = −1 + 2 · (y − min) / (max − min)
    With min 0.5 and max 5.0 (the lab’s rating scale, assuming the data spans it): 0.5 → −1, 5.0 → +1, 4.0 → 0.556. Why −1…1? The network’s output is a dot product of two unit-length vectors, which can only be between −1 and 1, so the targets must live in that range. (This confirms what I flagged earlier about the TensorFlow lecture video.)
  5. Check reversibility. inverse_transform undoes the scaling, and np.allclose tests “equal up to tiny float error”. True means no information was lost.

4. The network (Exercise 1)

Same architecture as the lecture. Only the three Dense layers per tower are yours to write. Everything else is provided.

num_outputs = 32
tf.random.set_seed(1)
user_NN = tf.keras.models.Sequential([
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(num_outputs)
])
item_NN = tf.keras.models.Sequential([
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(num_outputs)
])
# provided: Input -> tower -> l2_normalize -> Dot -> Model   (see my TensorFlow lecture summary)
  • Why the last layer has no activation: it outputs the raw 32-number vector, which is then L2-normalised.
  • Parameter counts: the notebook prints 41,376 for item_NN. By the same arithmetic (inputs × units + units per layer) user_NN has 40,864. Example: 16·256+256 + 256·128+128 + 128·32+32 = 41,376. The towers differ only in input width (14 vs 16).
  • “The networks do not need to be the same.” If user content were much bigger than movie content, you could give the user tower more capacity.

Training

cost_fn = tf.keras.losses.MeanSquaredError()
opt = keras.optimizers.Adam(learning_rate=0.01)
model.compile(optimizer=opt, loss=cost_fn)

model.fit([user_train[:, u_s:], item_train[:, i_s:]],
          y_train, epochs=30)

[:, u_s:] means “all rows, columns from index 3 onward”. That is how the 3 ID columns are dropped for users (u_s = 3), and 1 for items (i_s = 1).

Results

  • Loss falls from 0.1232 (epoch 1) to 0.0973 (epoch 6), and keeps going for 30 epochs.
  • Test loss: 0.0815, comparable to training loss, so the lab concludes no substantial overfitting.
  • In stars (my conversion): loss is in scaled units. √0.0815 ≈ 0.285, times 2.25 (= 4.5/2) ≈ 0.64 stars typical error, assuming the 0.5 to 5.0 range. That fits the lab’s “generally within 1 of the actual rating”.

5.1 A new user

You type a user’s taste in the same 17-column layout as the training data. The example: Adventure 5.0, Fantasy 5.0, every other genre 0.0, rating count = 3, user id = 5000. Zeros mean “not rated”, the same convention as the training table.

user_vecs  = gen_user_vecs(user_vec, len(item_vecs))   # same user row repeated for all 847 movies
suser_vecs = scalerUser.transform(user_vecs)           # scale with the TRAINED scalers
sitem_vecs = scalerItem.transform(item_vecs)
y_p  = model.predict([suser_vecs[:, u_s:], sitem_vecs[:, i_s:]])   # one score per movie
y_pu = scalerTarget.inverse_transform(y_p)             # back to stars
sorted_index = np.argsort(-y_pu, axis=0).reshape(-1).tolist()      # best first
sorted_items = item_vecs[sorted_index]                 # unscaled, for display

Step by step

  1. Repeat the one user 847 times, so each movie gets paired with this user.
  2. Scale user and item arrays with the trained scalers (transform only).
  3. Slice off the ID columns with [:, 3:] and [:, 1:] and call predict.
  4. Inverse-scale predictions back to the 0.5 to 5 star range.
  5. Sort high to low. argsort returns positions that would sort ascending. Negating the scores (-y_pu) flips that to descending. .reshape(-1).tolist() turns the column into a flat Python list. Using it as item_vecs[sorted_index] reorders the movies in that order.
# verified toy example
yp = np.array([[3.2],[4.6],[2.1],[4.9]])
idx = np.argsort(-yp, axis=0).reshape(-1).tolist()   # [3, 1, 0, 2]
yp[idx].ravel()                                      # [4.9, 4.6, 3.2, 2.1]

Real-life case: a brand-new user on a streaming site who ticks “adventure” and “fantasy” in onboarding gets sensible suggestions immediately, with no rating history. That is the cold-start strength of content-based filtering.

5.3 Finding similar items (Exercise 2)

‖ vm(k) − vm(i) ‖2 = Σl ( vm,l(k) − vm,l(i) )2
def sq_dist(a, b):
    d = 0
    rng = a.shape[0]
    print(rng)                                   # (in the solution as uploaded)
    for i in range(rng):
        d += np.sum(np.square(a[i] - b[i]))
    return d
  1. Reuse the trained movie tower. Build a small model Input → item_NN → l2_normalize (model_m) so the vectors are produced exactly as in training, including normalisation.
  2. Run all 847 movies (scaled) through it: vms.shape = (847, 32), one 32-number vector per movie.
  3. Build an 847×847 distance table with two nested loops calling sq_dist.
  4. Mask the diagonal with ma.masked_array(dist, mask=np.identity(...)). A movie’s distance to itself is 0, so without masking it would always be its own nearest match.
  5. Nearest neighbour: np.argmin(m_dist[i]) is the column with the smallest distance in row i. The lab prints 50 movies next to their nearest match. Result: the model “will generally suggest a movie with similar genres”.
# verified toy example: 3 movies
d = [[0,2,1],[2,0,3],[1,3,0]]
np.argmin(d[i]) per row         -> [0, 1, 2]   (each is its own nearest!)
with diagonal masked            -> [2, 0, 0]   (true nearest neighbours)

Real-life case: “because you watched X” rows on a streaming homepage. The lecture’s tip applies: compute this table once after training and reuse it, with no retraining.

Alternatives and trade-offs

My additions, not from the lab. Most are only worth trying after you have passed the graded cells.

Choice in the labAlternativePros / cons
Scale all data, then splitSplit first, fit scalers on the training part onlyPro: no test-set information leaks into the scaling (cleaner evaluation). Con: a few more lines. The effect with 40k+ rows is probably small.
Three separate train_test_split calls with one seedOne call: train_test_split(user, item, y, …)Pro: impossible to misalign the arrays. Con: returns six arrays in a fixed order, which is easy to unpack wrongly.
Double loop of sq_distVectorised: np.sum(np.square(a - b)), or all at once with scipy.spatial.distance.cdist(vms, vms, 'sqeuclidean')Pro: orders of magnitude faster. Con: the graded function must still pass the lab’s tests as written. The lab’s own hint suggests the vectorised form.
Squared distance tableSince vms rows are unit length: dist = 2 − 2·(vms @ vms.T)Pro: one matrix multiply (identity verified numerically on random unit vectors). Con: only valid because of the L2 normalisation, and tiny float differences near 0.
Repeat ratings of rare genresClass/sample weights instead of duplicating rowsPro: no duplicate rows crossing the train/test split. Con: needs a weighting scheme and changes the loss.
Zeros for “not rated” genresAdd a “rated this genre?” flag, or fill with the user’s overall averagePro: the model can tell “no data” from “rates it 0”. Con: more features or an extra assumption.

Key takeaways

  • User content is engineered from ratings (per-genre averages). Movie content is year + genre flags + average rating.
  • Row k of user_train, item_train, y_train is one example. That alignment is where “user 2 rated movie 6874 as 4” comes from, and splitting with one shared seed preserves it.
  • Scale inputs with StandardScaler and the target to −1…1 to match the cosine-style output. Fit once, reuse for everything, invert to read predictions.
  • Drop ID columns with [:, u_s:] and [:, i_s:]. The network sees 14 user and 16 movie features.
  • Two towers (256→128→32), L2-normalised, dot product, MSE, Adam (lr 0.01), 30 epochs. Test loss 0.0815, about 0.64 stars typical error by my conversion.
  • New-user predictions need no history. Similar movies come from small squared distance between movie vectors, with the diagonal masked.
  • Two quirks in your copy: the stray print(rng) and the movie-1-genres-twice display bug. The “3.9 vs 4.0” sentence also does not match the table.
