Deep learning for content-based filtering

Last lesson left one question open: how do we compute vu and vm from the raw features? Answer: two neural networks, trained together. The lecture says this is how many state-of-the-art commercial content-based systems are built today.

1. Two networks, one dot product

Slide: “Neural network architecture”. The user network turns xu into vu. The movie network turns xm into vm.

Output layer ≠ 1 unit. Unlike earlier networks, the final layer here has 32 units, so vu is a list of 32 numbers.
Networks may differ in number of hidden layers and units per layer (slide: 128→64→32 vs 256→128→32). Only the output size must match.

2. What the network predicts

Star ratings (0–5 or 1–5)

ŷ(i,j) = vu(j) · vm(i)

Same as last lesson. Superscripts i and j just stress “user j’s prediction for movie i”.

Binary labels (like / favour)

P(y(i,j) = 1) = g( vu(j) · vm(i) )

g is the sigmoid. Real-life case: “did the user like or favourite this item?” in a streaming or shopping app.

3. Drawn as one network, trained as one

Slide 2: the two networks are drawn together. The user network is the upper part, the movie network the lower part, and the dot product sits at the join.

J = Σ(i,j): r(i,j)=1 ( vu(j) · vm(i) − y(i,j) )2 + NN regularization term
  • Sum only over rated pairs, where r(i,j) = 1. This is the same style of cost as collaborative filtering.
  • It is a squared error between the dot-product prediction and the real rating.
  • No separate training for the user and movie networks. This one cost function trains all parameters of both networks. Each network is judged by how well vu and vm together predict y(i,j).
  • Minimise J with gradient descent or another optimiser.
  • Optional: the usual neural-network regularisation term, which keeps the parameter values small.
Why this works: different network parameters give different vectors. Training searches for parameters whose vectors make the squared errors small.

4. Finding similar items

Slide: “Learned user and item vectors”. vu(j) (length 32) describes user j. vm(i) (length 32) describes movie i. To find movies similar to movie i, look for movies k where this is small:

‖ vm(k) − vm(i) ‖2  small

This plays the same role as ‖x(k) − x(i)‖2 in collaborative filtering.

Try it (my illustration)

Real vectors have 32 numbers. These fictional movies use 2 (romance, action) so you can see the distances. Pick a movie to get its 3 nearest by squared distance.

Pre-compute it. Run a server overnight, find the 10 or 20 most similar movies for every movie, and store them. Tomorrow, when a user browses a movie, the “similar movies” list is already waiting. The lecture says this matters later for scaling to very large catalogs.

5. Practical notes from the lecture

Neural networks compose well

Recall the decision tree vs neural network comparison: networks are easy to combine into a bigger system. Here a user network and a movie network are joined by an inner product, a more complex and quite powerful architecture.

Invest in features

Developers often spend a lot of time designing the input features. For a commercial system, engineering good user and movie features is worth the effort.

Limitation: as described, the algorithm can be computationally very expensive for a large catalog. The next video covers how to modify it to scale to very large item catalogs.

6. Alternatives and trade-offs

Everything in this section is my addition, not from the lecture.

OptionProsCons
Two separate networks + dot product (this lesson)Item vectors can be pre-computed; each side can have its own architecture; simple to reason aboutThe only user-item interaction is a dot product, which limits what it can express
One network on concatenated [xu, xm]Can learn richer interactions between user and item featuresMust be run for every user-item pair, so there is little to pre-compute and it is slower on big catalogs
Binary labels: sigmoid + cross-entropy lossStandard choice for probability outputsThe lecture’s squared-error J is written for ratings; switching loss is a design decision to check against your course notebook

Sketch in Keras (illustrative, not from the lecture)

import tensorflow as tf

num_user_features = 14   # example sizes, replace with yours
num_item_features = 16

user_nn = tf.keras.Sequential([
    tf.keras.layers.Dense(128, activation="relu"),
    tf.keras.layers.Dense(64, activation="relu"),
    tf.keras.layers.Dense(32),            # v_u: 32 outputs
])
item_nn = tf.keras.Sequential([
    tf.keras.layers.Dense(256, activation="relu"),
    tf.keras.layers.Dense(128, activation="relu"),
    tf.keras.layers.Dense(32),            # v_m: 32 outputs
])

input_user = tf.keras.layers.Input(shape=(num_user_features,))
input_item = tf.keras.layers.Input(shape=(num_item_features,))
vu = user_nn(input_user)
vm = item_nn(input_item)
output = tf.keras.layers.Dot(axes=1)([vu, vm])   # v_u . v_m

model = tf.keras.Model([input_user, input_item], output)
model.compile(optimizer="adam", loss="mse")      # squared-error cost J

Both networks sit in one model, so one loss trains both. For binary labels, add a sigmoid after the dot product.

Key takeaways

  • User network: xu → vu. Movie network: xm → vm. Both end in 32 units, and hidden layers can differ.
  • Prediction is vu · vm for ratings, or g(vu · vm) for the probability that y = 1.
  • One cost J (squared error over rated pairs + regularisation) trains both networks together.
  • Similar movies: small ‖vm(k) − vm(i)‖2, and it can be pre-computed overnight.
  • Good feature engineering pays off. Large catalogs are expensive, which the next video addresses.
