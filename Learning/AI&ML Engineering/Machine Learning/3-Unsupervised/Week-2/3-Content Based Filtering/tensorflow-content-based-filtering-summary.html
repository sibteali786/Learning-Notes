1. The pipeline in code terms

2. The code from the slide

Reproduced from the slide, with my numbered notes after it. The hidden sizes shown here (256, 128, 32 for both networks) differ from the earlier slide (128, 64, 32 and 256, 128, 32), because the lecture treats the sizes as free to choose.

user_NN = tf.keras.models.Sequential([
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(32)
])

item_NN = tf.keras.models.Sequential([
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dense(32)
])

# create the user input and point to the base network
input_user = tf.keras.layers.Input(shape=(num_user_features))
vu = user_NN(input_user)
vu = tf.linalg.l2_normalize(vu, axis=1)

# create the item input and point to the base network
input_item = tf.keras.layers.Input(shape=(num_item_features))
vm = item_NN(input_item)
vm = tf.linalg.l2_normalize(vm, axis=1)

# measure the similarity of the two vector outputs
output = tf.keras.layers.Dot(axes=1)([vu, vm])

# specify the inputs and output of the model
model = Model([input_user, input_item], output)

# Specify the cost function
cost_fn = tf.keras.losses.MeanSquaredError()

What each part does

  1. Two Sequential networks: dense layers as in earlier networks. Hidden layers use ReLU (the default choice). The last layer has 32 units and no activation, so it outputs the 32 numbers of vu or vm. Lecture calls movies “items”, hence item_NN.
  2. Input(...) says what shape of features will enter each network (section 4).
  3. user_NN(input_user) feeds those features through the user network to get vu. Same for the item side.
  4. l2_normalize rescales each vector to length 1 (section 3). The lecture calls this an extra step that makes the algorithm work a bit better.
  5. Dot(axes=1)([vu, vm]): a special Keras layer (layers.Dot, not layers.Dense) that takes the dot product of the two vectors. This is the prediction.
  6. Model([input_user, input_item], output) declares the model’s two inputs and its one output.
  7. MeanSquaredError is the cost: the same squared-error idea as J from the earlier lesson.

3. Your question 1: what does l2_normalize do?

Short answer: it divides the vector by its own length (its L2 norm), so the result points in the same direction but has length exactly 1.

v ← v / ‖v‖  ,   ‖v‖ = √(v₁² + v₂² + … + v₃₂²)
  • axis=1: the data arrives as a batch, shape (num_examples, 32). Axis 0 is the examples, axis 1 is the 32 numbers. So each row (each user or movie) is normalised separately.
  • Effect on the prediction: the dot product of two unit-length vectors is the cosine of the angle between them, so the prediction depends only on the direction of vu and vm, not their size. Same direction gives +1, perpendicular gives 0, opposite gives −1.
  • Why the lecture does it: it makes the algorithm “work a bit better”. The lecture gives no deeper reason, so treat the next bullet as my interpretation.
  • My interpretation: without it, a network can raise a prediction just by making a vector longer. Normalising forces it to learn matching directions.
  • Link to similar items: for unit vectors, ‖a − b‖² = 2 − 2·(a·b). So small squared distance (the “find similar movies” test) and high dot product mean the same thing.

4. Your question 2: what does tf.keras.layers.Input do, and why use it twice?

Short answer: Input creates a symbolic placeholder for the data that will be fed in later. It holds no data. It only tells Keras “inputs of this shape will arrive here”, so you can wire layers and networks together before any training data exists.

  • Why it is needed here: this model is built with Keras’s functional style: call a network on a tensor to get a new tensor (vu = user_NN(input_user)). You need a starting tensor, and Input provides it. A plain Sequential has one input and one output, so it does not need this. Our model has two separate inputs that merge at the dot product.
  • Why two statements: the user side and item side are different inputs with different feature counts: num_user_features and num_item_features. Recall from the first lesson that user and movie features can differ in size.
  • shape describes one example. The batch size is not included. A user with 14 features is shape=(14,).
  • Where they come back: in Model([input_user, input_item], output), which declares both as the model’s inputs. At training time you pass two arrays in that same order.

Detail: the slide writes shape=(num_user_features) without a trailing comma. In Python that is just a number in brackets, not a tuple. The slide form works in the lab as written, and (n,) is the strictly correct tuple.

Real-life analogy

Think of a restaurant kitchen with two order slots, one for “drinks” and one for “food”. Input builds the slots and labels what size ticket each takes. The tickets (real data) only arrive when you call fit or predict. The two stations (user_NN, item_NN) are wired to their slots first, and the Dot layer combines what comes out.

5. Training it (not shown in this video)

The lecture stops at the cost function and leaves the rest to the lab. This sketch is my reconstruction of the usual next steps, so match it to your lab notebook.

opt = tf.keras.optimizers.Adam(learning_rate=0.01)
model.compile(optimizer=opt, loss=cost_fn)

# two inputs, passed in the same order as Model([...])
model.fit([user_train, item_train], y_train, epochs=30)

The names user_train, item_train, y_train and the optimizer settings are placeholders. y_train should be rescaled to match the −1 to 1 output range (section 3).

Variant with the Keras layer (illustrative)

vu = user_NN(input_user)
vu = tf.keras.layers.UnitNormalization(axis=1)(vu)   # replaces tf.linalg.l2_normalize

vm = item_NN(input_item)
vm = tf.keras.layers.UnitNormalization(axis=1)(vm)

Key takeaways

  • Two Sequential networks, each ending in a 32-unit layer with no activation. Hidden layers use ReLU.
  • Input(shape=...) makes a placeholder per input (user features, item features, which may differ in size) so the functional model can be wired up.
  • l2_normalize(axis=1) scales each vector to length 1. The dot product becomes a cosine similarity in [−1, 1], and the lecture says this works a bit better.
  • layers.Dot(axes=1)([vu, vm]) gives the prediction. Model([input_user, input_item], output) ties it together.
  • Cost: MeanSquaredError. One loss trains both networks.
