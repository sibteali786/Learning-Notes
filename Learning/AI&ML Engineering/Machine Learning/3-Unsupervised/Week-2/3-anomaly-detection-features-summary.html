🧰 Choosing Features for Anomaly Detection

Make features more Gaussian · Error analysis · Inventing new features · (end of the Week 1 unsupervised learning material)

Why Features Matter Even More Here

Supervised learning

  • Extra or poorly scaled features are often okay
  • The labels give a supervised signal, so the algorithm can work out which features to ignore and how to rescale them

Anomaly detection

  • Learns from unlabeled data
  • Much harder for the algorithm to know which features to ignore
  • So careful feature choice matters even more
Two practical tools in this lecture: (1) make features more Gaussian, and (2) error analysis on the CV set to invent new features.

Tool 1: Make Features More Gaussian

The model fits a Gaussian p(xⱼ; μⱼ, σⱼ²) to each feature, so it fits best when the feature is roughly bell-shaped.

TransformationLecture notationNotes
x₁ ← log(x₁)logRight-skewed feature becomes symmetric (slide example)
x₂ ← log(x₂ + c)e.g. log(x₂ + 1)Larger c transforms the distribution less. Try several values of c
x₃ ← √x₃ = x₃^(1/2)square rootMilder than log
x₄ ← x₄^(1/3)cube root / any powerTune the exponent (the lab uses x^0.4)
Automatic measures exist in the ML literature for how close a distribution is to Gaussian, but in practice trying a few values and picking what looks right works well enough.

log(0) trap: the lab data contains values of exactly 0, so np.log(x) errors (log 0 is negative infinity, undefined). The fix is to add a small constant: np.log(x + 0.001), or a larger c if you want less distortion.

In Code (plus the Important Reminder)

import numpy as np, matplotlib.pyplot as plt

plt.hist(x, bins=50, color='r')             # look at the raw feature
plt.hist(x**0.4, bins=50)                   # try a power transform
plt.hist(np.log(x + 10), bins=50)            # try log(x + c); x has zeros, so c > 0

# once you pick one, fit it on TRAIN and use the SAME transform everywhere
c = 10
X_train_t = np.log(X_train + c)
X_cv_t    = np.log(X_cv    + c)      # same c, same function
X_test_t  = np.log(X_test  + c)
mu, var   = estimate_gaussian(X_train_t)
Reminder from the lecture: whatever transformation you apply to the training set, apply the same transformation to the cross-validation and test sets (and to production data).

Tool 2: Error Analysis

Goal: p(x) ≥ ε (large) for normal examples and p(x) < ε (small) for anomalous ones. The most common problem: p(x) is comparable, i.e. large, for both normal and anomalous examples, so the anomaly isn't flagged.

One feature (x₁ = number of transactions): the anomalous user makes about as many transactions as everyone else → high p(x) → missed.
Add x₂ = typing speed: this user has an insanely fast typing speed, far from the normal cluster → low p(x) → flagged.

Example: Monitoring Computers in a Data Center

Choose features that might take on unusually large or small values in the event of an anomaly (hardware failure, a hacked machine…).

Starting features

  • x₁ = memory use
  • x₂ = disk accesses/sec
  • x₃ = CPU load
  • x₄ = network traffic

Combined features

  • x₅ = CPU load / network traffic
  • x₆ = (CPU load)² / network traffic
  • Play with different choices; keep p(x) large for normal and small for CV anomalies
The story: one machine behaves very strangely, yet neither its CPU load nor its network traffic is individually unusual. What is unusual is a very high CPU load with very low network traffic. In a video-streaming data center, machines normally have high CPU and high traffic, or low CPU and no traffic. A ratio feature exposes the odd combination.
Why this works: the algorithm multiplies independent per-feature Gaussians, so it can't see that two features are individually normal but weird together. A combined feature puts that relationship into a single axis.

Practical Checklist

  • Histogram every feature before trusting it.
  • Skewed? Try log(x + c), x^power; pick by eye.
  • Apply the same transform to train, CV, test (and live data).
  • After training, list the CV anomalies you missed; ask "what made me think this was anomalous?"
  • Turn that answer into a feature (often a ratio or combination of existing ones).
  • Re-check on CV: normal examples should keep p(x) ≥ ε, anomalies should drop below ε.
Real-life scenario (fraud): normal-looking transaction counts, but each account is created and used within seconds. A new feature "time between signup and first purchase" separates it from normal users even though the old features looked fine.

Pros/cons of manual feature work: eyeballing histograms is quick and interpretable, but doesn't scale to hundreds of features. A formal skewness or normality check (beyond the lecture) lets you screen many features at once, at the cost of an extra step and less intuition about why a feature helps.
