🧮 Anomaly Detection Algorithm — Multiple Features

Density estimation with n features · Product of Gaussians · Flag if p(x) < ε

Setup

Training set x⁽¹⁾ … x⁽ᵐ⁾, where each example is a vector with n features: x = [x₁, x₂, …, xₙ].

Engine example

  • x₁ = heat, x₂ = vibration
  • Each x⁽ⁱ⁾ is 2-D, so n = 2

Real applications

  • n can be dozens or even hundreds of features
Goal: density estimation, i.e. build a model for p(x), the probability of any given feature vector.

The Model: Multiply Per-Feature Gaussians

p(x) = p(x₁; μ₁, σ₁²) · p(x₂; μ₂, σ₂²) · … · p(xₙ; μₙ, σₙ²)

= ∏j=1..n p(xj; μj, σj²)

Each feature gets its own Gaussian

  • x₁ (heat) → μ₁, σ₁²
  • x₂ (vibration) → μ₂, σ₂²
  • … up to μₙ, σₙ²

∏ symbol

  • Like Σ, but multiplies the terms for j = 1…n instead of adding

Independence

  • Multiplying probabilities assumes features are statistically independent
  • Works fine in practice even when they aren't
  • Not required to complete the course
Why multiply? (intuition) Suppose an engine has a 1/10 chance of running unusually hot and a 1/20 chance of vibrating really hard. The chance of both is 1/10 × 1/20 = 1/200: very unlikely.

The Algorithm (3 Steps)

1

Choose features xⱼ you think are indicative of anomalies
→
2

Fit parameters μ₁…μₙ, σ₁²…σₙ² on the unlabeled training set
→
3

Compute p(x) for a new example; anomaly if p(x) < ε

Step 2: parameter fitting

μⱼ = (1/m) Σᵢ xⱼ⁽ⁱ⁾
average of feature j over all examples
σⱼ² = (1/m) Σᵢ (xⱼ⁽ⁱ⁾ − μⱼ)²
average squared difference from μⱼ
Vectorized: μ = (1/m) Σᵢ x⁽ⁱ⁾ where x and μ are vectors, so this computes μ₁…μₙ all at once.

Step 3: compute p(x)

p(x) = ∏ⱼ [ 1 / (√(2π) σⱼ) · exp( −(xⱼ − μⱼ)² / (2σⱼ²) ) ]
import numpy as np

def estimate_gaussian(X):                 # X: (m, n)
    mu  = X.mean(axis=0)                      # shape (n,)  vectorized μ₁…μₙ
    var = X.var(axis=0)                       # shape (n,)  1/m by default (ddof=0)
    return mu, var

def p_of_x(x, mu, var):
    per_feature = np.exp(-(x - mu)**2 / (2*var)) / np.sqrt(2*np.pi*var)
    return np.prod(per_feature)               # ∏ over j

mu, var = estimate_gaussian(X_train)
is_anomaly = p_of_x(x_test, mu, var) < epsilon

Intuition: One Weird Feature Is Enough

The algorithm tends to flag an example as anomalous if one or more features are either very large or very small relative to the training set.

  • Each feature has its own bell curve. If even one feature of the new example sits far out in a tail, that p(xⱼ) is tiny.
  • One tiny term in the product drags the whole product down, so p(x) is small.
  • That is a systematic way of quantifying whether x has any features that are unusually large or unusually small.
Real-life example: a server with normal memory use and CPU load but a disk-access rate 10× higher than any other machine gets flagged, because that single feature's p(xⱼ) is near zero.

💡 Key Takeaways & What's Next

  p(x) = ∏ p(xⱼ; μⱼ, σⱼ²)
  Fit μⱼ, σⱼ² per feature
  p(x) < ε → anomaly
  One extreme feature → small product
  Independence assumption is forgiving
  
Open question: how do you choose ε, and how do you know the system is working well? Next video: developing and evaluating an anomaly detection system.

  
Pros/cons of this approach: simple, fast and needs only unlabeled data; but it assumes roughly bell-shaped features, and because it ignores correlations between features it can miss anomalies that are only unusual in combination (e.g. high heat with low vibration, if the two normally move together). Engineered ratio features (like CPU load ÷ network traffic) help with that.
