🛰️ Anomaly Detection — Intro & Density Estimation

Unsupervised Learning · 2nd unsupervised algorithm (after clustering) · Learn from "normal", flag the unusual

The Problem

Given an unlabeled dataset of normal events, the algorithm learns what "normal" looks like, then raises a red flag when a new event is unusual (an anomaly).

Unlabeled dataMostly normal examplesFlags, doesn't decide
Why this setup? Aircraft-engine makers rarely produce bad engines, so the easy data to collect is m engines that are almost all fine. You can't gather a big labeled pile of defects — so you model "normal" and detect deviations.

Stakes: an aircraft engine failure has very negative consequences, so extra inspection of suspicious units is worth it.

Density Estimation — Model p(x)

Most common approach: density estimation. From the training set, build a model of p(x) = "probability of x being seen in the dataset". It learns which feature values are likely (high p) and which are unlikely (low p).

Inner ellipse = highest probability Next ring = lower Outer ring = lower still Beyond = very unlikely → anomaly
How the training set is turned into these probability regions (via a Gaussian distribution) is covered in the next videos.

Decision Rule with ε (epsilon)

1

Train on m examples → learn p(x)
→
2

New engine arrives → compute p(x_test)
→
3

Compare to ε (small threshold)

p(x_test) < ε

  • This x was very unlikely vs. everything seen before
  • Raise flag → possible anomaly

p(x_test) ≥ ε

  • Near the high-probability middle
  • OK (normal) — not an anomaly
def is_anomaly(x_test, p, epsilon):
    return p(x_test) < epsilon     # True → flag for inspection
ε is a small number you choose. Bigger ε → more things flagged (more false alarms). Smaller ε → fewer flags (risk of missing real anomalies).

Where It's Used

🕵️ Fraud detection

x⁽ⁱ⁾ = features of user i's activity. Model p(x) of typical behavior; flag users with p(x) < ε.

  • How often do they log in?
  • How many web pages visited?
  • Number of transactions?
  • Forum posts?
  • Typing speed (chars/sec)?

🏭 Manufacturing

x⁽ⁱ⁾ = features of product i. Check whether the unit just built behaves strangely before shipping.

  • Airplane engine
  • Printed circuit board
  • Smartphone
  • Motor, and many more

🖥️ Data-center monitoring

x⁽ⁱ⁾ = features of machine i.

  • x₁ = memory use
  • x₂ = disk accesses/sec
  • x₃ = CPU load
  • x₄ = CPU load / network traffic ratio feature
Tip: features can be ratios (e.g. CPU load ÷ network traffic), which can expose oddities a raw feature alone would miss. A machine behaving very differently from the rest → check for hard-disk failure, network-card failure, or a hack.

Real-World Workflow: Flag ≠ Punish

In fraud detection you don't automatically disable an account just because it looks anomalous. The flag triggers a follow-up:

User activity looks unusual
p(x) < ε
→
Security team takes a closer look
→
Extra checks: verify identity via phone number, or pass a CAPTCHA
→
Separate real fraud from false alarms
Used to find fake accounts and financial fraud (e.g. a very unusual pattern of purchases worth a security team's closer look).
