⚖️ Anomaly Detection vs Supervised Learning

Few positives (y = 1), many negatives (y = 0): which algorithm should you pick?

The Question

You have a few positive examples (y = 1) and a large number of negative examples (y = 0). Should you use anomaly detection or supervised learning? In some applications the decision is subtle.

The previous video showed you can use a few labeled anomalies to tune an anomaly detector. That raises this question: if you have those labels, why not just train a supervised classifier?

Side-by-Side

🔍 Anomaly detection

  • Very small number of positives (0–20 is common)
  • Large number of negatives, used to model p(x)
  • Parameters of p(x) are learned only from negatives
  • Positives only appear in the CV and test sets (tuning and evaluation)
  • Many different "types" of anomalies; hard for any algorithm to learn what anomalies look like from a few positives
  • Future anomalies may look nothing like any seen so far
  • Example: fraud

🏷️ Supervised learning

  • Large number of positives and negatives
  • Enough positives for the algorithm to get a sense of what positives look like
  • Assumes future positives are likely similar to those in the training set
  • Learns a mapping from x to y using both classes
  • Example: email spam
Nuance: even with only ~20 positives it might be okay to apply supervised learning. The real difference is how each approach looks at the data, covered next.

Core Difference: How Each One Sees a Brand-New Failure

Anomaly detection: models what normal looks like and flags anything that deviates a lot, including a brand-new failure mode never seen in the data.
Supervised learning: learns what the known positives look like. A new type of failure that resembles none of them can land on the "normal" side and be missed.

Deciding Question: Will Future Positives Look Like Past Ones?

"No, new types keep appearing" → anomaly detection

  • Aircraft engines: many ways to go wrong; tomorrow there may be a brand-new way, and your ~20 positives can't cover them all
  • Financial fraud: new kinds of attempts show up every few months or every year

"Yes, they're similar" → supervised learning

  • Spam: many types, but even over years it keeps selling similar things and pointing to similar sites, so next week's spam resembles past spam
  • Same labels recur, so the training positives are representative

Application Map

ApplicationBetter fitWhy
Fraud detection (new schemes)Anomaly detectionLook for anything different from past transactions. (Supervised is used for previously observed forms of fraud.)
Email spam classificationSupervisedFuture spam resembles the spam you've already seen
Manufacturing: new, unseen defects (e.g. aircraft engines)Anomaly detectionCatch brand-new failures even with no such positive in the training set
Manufacturing: known, seen defects (e.g. phone scratches)SupervisedThe same defect (y = 1) repeats, so enough labeled examples can be collected
Monitoring machines in a data centerAnomaly detectionA hacked machine can behave in a brand-new way unlike any past behavior
Security applications in generalAnomaly detectionHackers keep finding new ways into systems
Weather prediction (sunny/rainy/snow)SupervisedOnly a handful of types, same output labels seen over and over
Disease classification (known disease from symptoms)SupervisedA specific, previously seen disease with labeled cases
Real-life scenario: a phone maker knows its case machine sometimes scratches covers. With plenty of scratched phones labeled y = 1, a supervised classifier works well. If they instead worry about unknown future problems, they'd add an anomaly detector.

💡 Key Takeaways & What's Next

Anomaly detection → find brand-new positives unlike past ones Supervised → decide if x resembles known positives Few positives + varied failures → anomaly detection Many positives + repeating pattern → supervised
Next video: feature choice matters a lot for anomaly detection systems, so the lecture shares practical tips for tuning the features you feed the algorithm.
Pros/cons of combining them (beyond the lecture): running both, or feeding the anomaly score into a supervised model as a feature, can catch known and novel problems. It also doubles the maintenance, and you must handle disagreements between the two systems.
