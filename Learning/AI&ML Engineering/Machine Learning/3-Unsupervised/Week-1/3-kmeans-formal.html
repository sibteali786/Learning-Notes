📐 K-Means, Formalized

Writing out the algorithm precisely — plus two edge cases

The Algorithm in Pseudocode

# Randomly initialize K cluster centroids
μ₁, μ₂, ..., μ_K

Repeat {
    # Step 1: Assign points to cluster centroids
    for i = 1 to m:
        c⁽ⁱ⁾ := index k that minimizes ||x⁽ⁱ⁾ − μ_k||²

    # Step 2: Move cluster centroids
    for k = 1 to K:
        μ_k := average (mean) of points assigned to cluster k
}

μ₁...μ_K are vectors with the same dimension as your features — 2 numbers each if n=2, n numbers if you have n features.

Step 1 — Nearest Centroid (L2 norm)

For each point, find the centroid index k that minimizes the squared distance:

c⁽ⁱ⁾ = argmink ‖x⁽ⁱ⁾ − μk‖²

Squared distance is used in practice (not plain distance) — same minimizing k, but avoids an unnecessary square root.

Step 2 — Recompute as the Mean

Example: if cluster 1 was assigned training examples 1, 5, 6, 10:

μ₁ = ¼ [ x⁽¹⁾ + x⁽⁵⁾ + x⁽⁶⁾ + x⁽¹⁰⁾ ]

Divide by the count of points in that cluster (4 here). Each x is a vector, so μ comes out as a vector too.

⚠️ Edge Case: The Empty Cluster

What if zero points get assigned to a centroid? Step 2 needs to average zero points — 0/0, undefined.

✅ Common fix
Eliminate that cluster entirely → you end up with K−1 clusters.
🔁 Alternative
Randomly re-initialize that centroid and hope it picks up points next round (used if you truly need exactly K clusters).
Why this happens: a bad random init can place a centroid far from all data — every point ends up closer to some other centroid, leaving this one with nothing to average.

K-Means Without Natural Separation — T-Shirt Sizing

K-means doesn't need visually distinct blobs to be useful. Height and weight vary continuously — no natural gaps — yet running K-means with K=3 still produces a useful result.
