Overfitting & Underfitting

Two models can both "work," and both be wrong in opposite directions. A Goldilocks problem: too little fit, too much fit, and the narrow zone in between that actually generalizes.

Regression example — predicting house price from size

Same data, three models of increasing complexity. Watch what happens to the fit as more polynomial terms get added.

1 feature

Underfit

Ignores the flattening trend entirely — a straight line can't bend.

The Goldilocks read: too cold (underfit) and too hot (overfit) are both wrong for the same underlying reason — neither one reflects what the data actually looks like beyond the training examples. "Just right" isn't the model that fits training data best; it's the one likely to fit the next house too.

Two names for two failure modes

underfitting = high bias

The model has a strong, wrong preconception — e.g. "price is linear in size" — and can't fit the training set well even when given the chance. It doesn't have enough flexibility to capture a pattern that's clearly there.

overfitting = high variance

The model fits this training set almost perfectly, but so tightly that a slightly different training set would swing it to a totally different curve. Two engineers, two datasets, wildly different models — that instability is the "variance."

Note on "bias": in ML, "bias" has two distinct meanings — the fairness sense (an algorithm discriminating by gender or ethnicity, which must always be checked for) and this separate statistical sense (a model too rigid to fit the data). This note uses the second meaning throughout.

The same story for classification

Overfitting isn't unique to regression. Here the task is classifying tumors as malignant (×) or benign (○) from tumor size (x₁) and age (x₂) — the decision boundary plays the same role the curve played above.

z = w₁x₁+w₂x₂+b (underfit)  →  adds x₁², x₂², x₁x₂ (just right)  →  adds many higher-order interaction terms (overfit), f = g(z) throughout, g = sigmoid

Why "just right" still misclassifies some points

The middle model in both examples doesn't get everything right — a few crosses land among the circles. That's expected, and it's not a flaw: a boundary that does separate every training point perfectly is exactly the overfitting trap on the right. Tolerating a little training error is often the price of generalizing well.

Worked scenario

Two engineers, two datasets

Two ML engineers at the same hospital each collect their own set of five patient records and fit a fourth-order polynomial model to classify tumors. Because the model has so much flexibility, each one lands on a different wiggly decision boundary that perfectly separates their own five examples — yet the two boundaries disagree sharply on how to classify a sixth, unseen patient. That disagreement, driven purely by which five examples happened to get collected, is what "high variance" means in practice.

Recap

Too few features
Underfits · high bias · doesn't even fit the training set well
Right amount
Fits training data well and generalizes to new examples
Too many features
Overfits · high variance · fits training data almost perfectly but won't generalize

This applies to both regression and classification — the mechanism (too little vs. too much model flexibility relative to the data) is identical, only the shape being fit (a curve vs. a decision boundary) changes.
