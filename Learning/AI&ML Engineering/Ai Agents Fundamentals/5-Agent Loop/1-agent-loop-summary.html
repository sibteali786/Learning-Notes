AGENT FUNDAMENTALS

The Agent Loop

What separates an agent from a single LLM call — and why while(true) is the right answer.
💡 An agent loop = a while loop where the LLM decides when to stop.
You only intervene to cap cost, handle errors, or enforce safety limits.
If the number of steps is known → use a workflow. If unknown → use an agent. Most business problems are workflows. Agents shine at general, open-ended tasks.
LLM vs WORKFLOW vs AGENT
TypeWho controls flow?Steps known?Best for
🤖 LLM call Nobody — one shot Always 1 Simple Q&A, text gen, classification
🔗 Workflow You (deterministic) Yes, fixed Known business processes — email → summarise → route
🌀 Agent LLM (autonomous) No, discovered at runtime Open-ended tasks, multi-step tool use, general assistants
Real scenario: "Update the port in the config file" = workflow (read → parse → modify → write, always the same 4 steps). "Find all files that import the auth module" = agent (unknown depth, discovered recursively).

THE LOOP — HOW IT WORKS
1
Send messages[] to LLM — full conversation history every time
2
LLM responds — either text only or tool call(s)
✅ No tool calls → break. Task done, respond to user.
🔧 Tool calls → execute each tool, append results to messages[]
3
Append LLM response + tool results to messages[] → loop back to step 1
4
Repeat until LLM stops calling tools or a stop condition fires
while (true) {
  const response = await llm.generate(messages);
  messages.push(response);                       // always append

  if (response.finishReason !== 'tool-calls') break; // done

  for (const call of response.toolCalls) {
    const result = await executeTool(call);
    messages.push(toolResult(result));             // feed results back
  }
  // LLM sees new messages → decides next action
}
STOP CONDITIONS — NEVER LET IT RUN FOREVER
✅ Natural — finishReason: "stop"
LLM returns text, no tool calls. Decided it's done. Ideal case — no intervention needed.
🔢 Max iterations
Hard cap e.g. 20 loops. Safety net against infinite tool call chains. Always add this.
📏 Token limit
finishReason: "length". Context window full. Compact or stop — covered in context management lesson.
❌ Error threshold
3 consecutive tool failures → stop. Don't feed repeated errors to LLM — it's a waste of tokens and money.
👤 User intervention
Ctrl+C in terminal. Cancel button in UI. Always give humans an escape hatch regardless of infra.
💰 Cost / token budget
Track token usage per loop. Stop if spend exceeds threshold. Critical for long-running autonomous agents.
STREAMING — streamText vs generateText
⏳
generateText
Buffers everything. You wait. Then the whole response jump-scares you at once. Bad UX for anything >2s.
⚡
streamText
Tokens stream as generated. User sees output immediately. Feels responsive even during long tool chains.
const result = streamText({ model, messages, tools });

for await (const chunk of result.fullStream) {
  if (chunk.type === 'text-delta')  callbacks.onToken(chunk.text);  // stream to UI
  if (chunk.type === 'tool-call')   toolCalls.push(chunk);          // collect for execution
}
⚠️ Don't default to agents. Most business workflows are deterministic — same steps every time. Use an LLM inside a workflow node instead. Agents are for unknown step counts and undefined paths. Over-agenting = unpredictable behavior + higher cost + harder to eval.
WNP scenario: "Set up the new dev project, create the initial tasks, and assign them to the team." → agent needs to: list_users → create_project → create_task × N → assign_user × N. Number of tasks/users unknown at call time. Can't hardcode steps. Agent loop reads each result and decides the next tool call — loop runs until no more tool calls.
Pattern: while(true) · messages[] append · finishReason check · streamText · stop conditions
