AI AGENT DEVELOPMENT

Single Turn Evals

Measure. Compare. Improve. Don't fly blind.
💡 Tests = Pass/Fail (deterministic)  |  Evals = Score/Measure (non-deterministic)
LLMs aren't deterministic even at temp=0 — GPU kernel-level load introduces randomness regardless of seed
WHY EVALS
🎲
Non-determinism
Same input → different output. Traditional tests don't cut it.
📉
Silent Regression
Prompt/model/tool changes can silently degrade behavior.
🚀
Deploy Confidence
90% eval score = ship it. 40% = do not ship.
🔍
Debugging
Tracing + evals = understand exactly WHY it failed.
Real scenario: Scott's co-founder typed the same prompt — worked perfectly for Scott 10x in a row, crashed immediately for co-founder. No evals = no clue why. Turned out to be non-determinism they weren't measuring.
🧪 Single-Turn ≈ Unit Test
One input/output pair. Did the agent pick the right tool? Extract correct args? Refuse when appropriate?
🌐 Full-Run ≈ E2E Test
Complete task execution end to end. How many steps, tool calls, and what's the final outcome?
OFFLINE vs ONLINE EVALS
⚡ Offline (build this first)
✓ Fixed dataset, run locally
✓ Fast dev feedback loop
✓ Great for CI regression blocking
✓ Cheap to run many times
— Curated scenarios only
🌍 Online (advanced / production)
✓ Real user traffic
✓ Catches unexpected edge cases
✓ LLM-as-judge scoring
— Expensive (sample <1% of traffic)
— Thumbs up/down collection loop
DATA SOURCES FOR EVALS
🧪 Synthetic — start here 📊 Production Logs 🪲 Edge Case Mining 🔴 Red Teaming 🤖 LLM-Generated ⚠️ bias risk
Best datasets combine all. Start synthetic → layer in production failures over time.
EVAL CATEGORIES
GOLDEN
Must select exactly the expected tools. Zero ambiguity. Binary pass/fail. Highest confidence signal.
SECONDARY
Likely selects certain tools but flexibility allowed. Scored via F1 (precision + recall) for partial credit.
NEGATIVE
Must NOT select forbidden tools. Tests the agent doesn't over-reach or hallucinate tool use.
SCORERS (EVALUATOR FUNCTIONS)
toolsSelected
binary
toolsAvoided
binary
toolSelectionScore (F1)
0 → 1
F1 = harmonic mean of precision (no extra tools) and recall (no missing tools)
HILL CLIMBING LOOP
Run Evals→ Get Baseline→ Make a Change→ Re-run Evals→ Score ↑? Keep it→ Score ↓? Revert
WNP scenario: Change a task routing tool description → run evals → score jumps 72% → 85% → keep it. No vibes, pure data. Every change is justified.
Tools: Laminar (eval runner) · OpenTelemetry (tracing) · LLM-as-Judge (quality scoring)
