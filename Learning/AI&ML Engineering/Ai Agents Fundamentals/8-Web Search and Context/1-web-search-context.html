WEB SEARCH + CONTEXT MANAGEMENT

Grounding + Token Budgets

Give the agent current knowledge. Then stop the context window from eating you alive.
💡 Web search solves the knowledge cutoff problem. Context management solves the token bloat problem web search causes. They always arrive together.
Every web search result adds ~1,000–3,000 tokens. An agent that searches 5 times per task burns 5–15K tokens per run — before conversation history.

All bars eat from the same window. Tool results (especially web search) are the biggest culprit.
Token costs (rough)
Avg code file: ~500 tokens
Web search result: ~1K–3K tokens
10-exchange chat: ~5K tokens
Tool definitions: ~500–1K tokens
Output 3–4× more expensive than input
Why limits exist
Attention = O(n²) — every token attends to every token. Double context = 4× compute.
At 360K/400K tokens you're already seeing accuracy degradation before hitting the hard limit.
THE "LOST IN THE MIDDLE" PROBLEM
MODEL RECALL BY POSITION
StartMiddleEnd
Models recall beginning and end well — both have fewer competing tokens. The middle is heavily influenced by tokens on both sides, making it harder to attend to. A 1M token context window sounds great but accuracy at 800K tokens is terrible in practice. Bigger window ≠ better performance.

RAG — THE OPEN BOOK TEST ANALOGY
User query→ Vectorize query→ Find nearest vectors in DB→ Inject relevant chunks into context→ LLM answers
Instead of reading the whole textbook, the student reads the question → checks the glossary (vector DB) → turns to only that page → answers. Tokens = you'd never load a whole textbook into RAM when you only need page 47.

Behaviour to watch
OpenAI's description likely says "use freely" — agent can fire 20+ searches on a simple query.
Always say "only use one web search" in prompt when testing. Eval for over-searching.
⚠️ Don't build your own web search tool in production. Use Exa, Tavily, Bing API, or the provider's native tool. Building your own is a fun exercise — then stop. The crawling, deduplication, ranking, and freshness problems are solved problems. Use the solutions.
WNP scenario: Agent searching for "latest IFRS 16 amendments" opens 3 parallel web searches (different query angles). Each returns ~2K tokens. After 4 loops of tool results, context is 12K tokens heavier. Apply compaction: summarize earlier tool results into 200-token bullet points, replace raw results. Context stays lean, conversation continues. Without this, 20 searches = 40K+ tokens of garbage sitting in the window slowing inference and costing money.
