CONTEXT MANAGEMENT

Context Compaction

When the context window fills up, summarize history and keep going — indefinitely.
💡 Compaction = run another LLM to summarize the conversation so far, then swap the detailed history with a 2-message seed. Agent continues with headroom restored.
Token counting is intentionally approximate — ~3.75 chars/token. Exact tokenization is async, model-specific, and expensive. Close enough beats perfect here.
THE 80% THRESHOLD — WHY NOT 100%
Used history (80%)
Headroom (20%)
The remaining 20% must cover: new user message + tool calls + tool results + assistant response + estimation error margin
You can tune this. 90% = fly closer to the sun. 70% = more headroom, compact more often. Default 80% is a practical balance. Change DEFAULT_THRESHOLD and everything adjusts.
COMPACTION FLOW — BEFORE EACH TURN
estimateMessagesTokens(messages)
Sum up tokens across all messages using the ~3.75 chars/token approximation. Fast, free, good enough.
isOverThreshold(total, contextWindow, 0.8)?
total > contextWindow * 0.8. If yes → compact. If no → proceed normally.
Filter system messages out
System prompt is NOT summarized — it's added fresh on every turn. Only user/assistant/tool messages get compacted.
messagesToText() → generateText(summarizationPrompt + text)
Convert the messages array to a plain text blob (no JSON brackets). Feed to a cheaper model with a summarization system prompt. One-shot — no loop needed.
Return 2-message "seed" → replace workingHistory
user: "[CONVERSATION SUMMARY] …summary… continue from here" + assistant: "I've reviewed the summary, ready to continue." Ends on assistant so agent doesn't re-respond immediately.
BEFORE vs AFTER COMPACTION
BEFORE (N messages, ~320K tokens)
system: SYSTEM_PROMPT
user: "Can you help me…"
assistant: [tool call]
tool: [search results 2K tokens]
assistant: "Here's what I found…"
user: "Now do this…"
… 200 more messages …
AFTER (2 messages, ~800 tokens)
system: SYSTEM_PROMPT (added fresh)
user: "[SUMMARY] We discussed X, decided Y, currently working on Z… please continue."
assistant: "I've reviewed the summary and I'm ready to continue. How can I help?"
Ends on assistant → no immediate re-response from LLM when loop resumes.

// modelLimits.ts
export function isOverThreshold(total: number, ctxWindow: number, threshold = 0.8) {
  return total >= ctxWindow * threshold;
}
export function calculateUsagePercentage(total: number, ctxWindow: number) {
  return (total / ctxWindow) * 100;
}

// compaction.ts — compactConversation()
const conversationMessages = messages.filter(m => m.role !== 'system'); // skip system
const text = messagesToText(conversationMessages);                        // plain text, no JSON
const { text: summary } = await generateText({

  { role: 'user',      content: `[CONVERSATION SUMMARY]\n${summary}\n\nPlease continue.` },
  { role: 'assistant', content: "I've reviewed the summary and I'm ready to continue." }
];

✅ What compaction preserves
Overall goal and intent
Key decisions made
Important facts mentioned
Pending tasks/questions
❌ What compaction loses
Exact wording and tone
Detailed tool outputs
Step-by-step reasoning trace
Nuance between related facts
⚠️ Compaction degrades over time. Second compaction merges a previous summary + new messages — you're summarizing a summary. Details erode faster each time. Claude's solution: warn the user ("I'm about to compact") and let them clear context or dump important info to a file first. There's no perfect solution — only trade-offs.
