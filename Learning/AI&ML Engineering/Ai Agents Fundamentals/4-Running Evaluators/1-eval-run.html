PUTTING IT ALL TOGETHER

Writing & Running an Eval Experiment

Data + Executor + Scorers = one Experiment. Group experiments to track progress over time.
💡 Every eval framework — Laminar, Braintrust, Python libs — is the same 3 things with different names:
Dataset (input/expected) + Executor (run the thing) + Scorers (quantify output)
Don't get confused by framework names. The concept is universal. An "Experiment" wraps all three.

WRITING filetools.eval.ts — STEPS
1
Import evaluate + types + data + executor
evaluate from Laminar, EvalData/EvalTarget from types, JSON dataset, singleTurnExecutorWithMocks from executors.
2
Wrap executor — one data item → one run
const executor = async (data: EvalData[]) => data.map(d => singleTurnExecutorWithMocks(d)). Loops your dataset through the dynamic runner.
3
Call evaluate() with name + groupName
name = label in dashboard. groupName = groups related experiments (e.g. "file tools selection") so you can compare V1 vs V2 over time.
4
Add evaluator with secondary bypass
If target.category === 'secondary' → return 1 (don't penalise). Otherwise run toolSelectionScore(output, target). Keeps secondary misses from tanking golden scores.
CODE — filetools.eval.ts 
import { evaluate } from '@lmnr-ai/lmnr';
import { toolSelectionScore } from './evaluators';
import { singleTurnExecutorWithMocks } from './executors';
import dataSets from '../data/file-agent.json' assert { type: 'json' };

const executor = async (data: EvalData[]) =>
  Promise.all(data.map(d => singleTurnExecutorWithMocks(d)));

evaluate({
  name:      'File Tools – Single Turn',
  groupName: 'file tools selection',   // group for dashboard comparison
  dataSet:   dataSets as any,
  executor,
  evaluators: {
    selectionScore: (output, target: EvalTarget) => {
      // don't penalise secondary cases for wrong tool pick
      if (target.category === 'secondary') return 1;
      return toolSelectionScore(output, target);
    }
  }
});
⚠️ Why return 1 for secondary, not filter them out?
Filtering removes secondary cases entirely — you lose the signal that the agent did solve them. Returning 1 rewards a correct pick without punishing a wrong one. You track upside without poisoning your golden score with prompts you never designed for.
groupName — WHY IT MATTERS
📁
Groups experiments
All runs with the same groupName appear together in the dashboard. Compare V1 prompt vs V2 prompt on the same chart.
📈
Tracks progress
Switch model? Change tool description? Same groupName = side-by-side score history. That's hill climbing with data.
🔬
Model comparison
Put GPT-4o, Gemini, Claude runs under the same group. Same data, same scorers, different models — let the chart decide.
