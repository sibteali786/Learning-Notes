EVAL SCORERS

Turning Qualitative → Quantitative

Scorers are assertions that return a 0–1 score. They are the eval equivalent of unit test assertions.
💡 Tool calls = structured JSON → scoreable with plain code (deterministic).
Agent text output = language → needs another LLM or human to score (non-deterministic).
This is why single-turn tool selection evals are easier than multi-turn output evals. JSON is code-testable. Language is not.
THE 3 SCORERS
toolSelectionScore F1 Score → 0.0–1.0
Did the agent pick the right tools? Partial credit via F1 — balances precision (no extra tools) and recall (no missing tools). Not binary.
// pseudo-logic hits = expected.filter(t => selected.includes(t)) score = f1(precision: hits/selected.length, recall: hits/expected.length) // 1.0 = perfect match | 0.5 = partial | 0.0 = totally wrong
WHY F1 AND NOT EXACT MATCH?
Exact match penalises equally whether you missed 1 tool or 5. F1 scales gracefully — a near-miss still gets partial credit, making it a better signal for iterative improvement.
toolsSelected Binary → 0 or 1
Did the agent call all expected tools, in the right order? No partial credit — all or nothing. Used for golden test cases.
// pseudo-logic score = expected.every((t, i) => selected[i] === t) ? 1 : 0 // order matters here
toolsAvoided Binary → 0 or 1
Did the agent stay away from forbidden tools? One wrong pick = immediate 0. Used for negative test cases. Zero tolerance.
// pseudo-logic score = forbidden.some(t => selected.includes(t)) ? 0 : 1 // any forbidden tool selected → instant fail
EXAMPLE NEGATIVE CASE
Prompt: "Tell me a joke about programming." → agent has file/bash tools available but should call none of them. If it calls run_command, score = 0.
WHICH SCORER FOR WHICH CATEGORY
GOLDEN cases
Use toolsSelected (binary)
Must hit exact tools in exact order
Zero ambiguity — full pass or full fail
SECONDARY cases
Use toolSelectionScore (F1)
Partial credit acceptable
Flexibility in tool choice — measure how close
NEGATIVE cases
Use toolsAvoided (binary)
Must call zero forbidden tools
One bad call = immediate 0
MULTI-TURN (future)
Output is text, not JSON
Can't score with code alone
Needs LLM-as-judge or human review
WNP scenario: Prompt = "Create a task and assign it to Ali."
Expected = [list_users, create_task] (look up user ID first, then create).
Agent picks [create_task] only → toolsSelected = 0, toolSelectionScore ≈ 0.67 (got 1 of 2, in wrong order). Signal: agent needs better context about needing a user ID before task creation.
Scorer types: toolSelectionScore (F1) · toolsSelected (binary) · toolsAvoided (binary)
