MULTI-TURN EVALS

multiTurnWithMocks Executor

Run the full agent loop against mocked tools. Collect every step. Feed it all to the judge.
💡 Multi-turn executor = the run function, but without streaming — using Vercel AI SDK's internal loop (stopWhen) so you don't rebuild it, then manually inspecting result.steps to collect what the judge needs.
Tools are mocked with fixed return values. You never hit the real file system. The agent still runs its full reasoning loop — it just gets fake results back.

EXECUTOR FLOW
data in→ buildMockedTools()→ build messages[]→ generateText loop→ inspect result.steps→ return MultiTurnResult
buildMockedTools(data.mockTools)
Creates real tool objects with execute() functions that return the fixed mock values from the eval data. Same descriptions as real tools — agent can't tell the difference.
Build messages[] — two modes
Fresh prompt: [{role:"system", content:SYSTEM_PROMPT}, {role:"user", content:data.prompt}]
Pre-filled: data.messages ?? [...] — use existing history to test mid-conversation behavior.
generateText with stopWhen: stepCountIs(N)
AI SDK runs the full agent loop internally. maxSteps comes from eval data or defaults to 20. No custom loop needed — SDK handles it. Returns result.steps[] for inspection.
Inspect result.steps[] — collect for judge
Each step has toolCalls[] (what the agent asked to call) and toolResults[] (mock responses). Map over all steps to build ordered lists. One step can have parallel tool calls.
Return MultiTurnResult
Everything the judge needs: final text, step-by-step trace, unique tools used, and full call order. See shape below.
CODE — multiTurnWithMocks 
export async function multiTurnWithMocks(data: MultiTurnEvalData): Promise<MultiTurnResult> {
  const tools   = buildMockedTools(data.mockTools);
  const messages = data.messages ?? [
    { role: 'system', content: SYSTEM_PROMPT },
    { role: 'user',   content: data.prompt! }
  ];

  const result = await generateText({
    model:    openai(data.config?.model ?? 'gpt-4o-mini'),
    messages, tools,
    stopWhen: stepCountIs(data.config?.maxSteps ?? 20)
  });

  const allToolCalls: string[] = [];

  const steps = result.steps.map(step => {
    const stepToolCalls = (step.toolCalls ?? []).map(tc => {
      allToolCalls.push(tc.toolName);               // track order globally
      return { toolName: tc.toolName, args: tc.args ?? {} };
    });
    const stepToolResults = (step.toolResults ?? []).map(tr => ({
      toolName: tr.toolName,
      result:   'result' in tr ? tr.result : null
    }));
    return {
      toolCalls:   stepToolCalls.length   > 0 ? stepToolCalls   : undefined,
      toolResults: stepToolResults.length > 0 ? stepToolResults : undefined,
      text:        step.text || undefined
    };
  });

  return {
    text:          result.text,
    steps,
    toolsUsed:     [...new Set(allToolCalls)], // deduplicated
    toolCallOrder: allToolCalls                    // full ordered list (with repeats)
  };
}
MultiTurnResult SHAPE — WHAT THE JUDGE RECEIVES
text
string
Agent's final response to the user. This is what the judge reads and scores.
steps[]
Step[]
Full iteration trace. Each step: toolCalls, toolResults, text. Enables step-level debugging.
toolCallOrder
string[] (with repeats)
Ordered list of every tool called. Used by toolOrderCorrect scorer. E.g. ["list_users", "assign_user", "assign_user"]
toolsUsed
string[] (deduplicated)
Unique tools called. Used by toolsAvoided scorer. Set deduplication handles parallel + repeated calls.
Why generateText not streamText?
No UI to stream to in evals. We only care about the final result + steps. streamText complicates collection with no benefit here.
Why use SDK loop not manual?
We already built the loop manually in run.ts — no need to duplicate. SDK's stopWhen + result.steps give us everything for free.
⚠️ allToolCalls vs toolsUsed: allToolCalls keeps duplicates and order — critical for toolOrderCorrect scorer. toolsUsed is a new Set() — used for toolsAvoided. Don't mix them up. If agent calls list_users twice, order array has it twice; set has it once.
WNP scenario: Prompt = "Assign all senior devs to Q3 project"
Mock: list_users → "[Ali, Sara]" · assign_user → "success"
Agent runs: step 1 → list_users() · step 2 → assign_user(Ali) + assign_user(Sara) parallel · step 3 → text response
Result: toolCallOrder: ["list_users","assign_user","assign_user"] · toolsUsed: ["list_users","assign_user"] · text: "Done — Ali and Sara assigned to Q3" → judge score: 10/10.
