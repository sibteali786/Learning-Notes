🔄 Iterative Prompt Development

Prompting is never right on the first try — it's a loop of refine → test → refine. The process matters more than any "perfect prompt."
Idea → Prompt → Result → Error Analysis → Refine
The Core Loop

Just like ML model development (idea → implement → experiment → analyze error → repeat), prompt engineering follows the same cycle:

Key mindset: there's no "30 perfect prompts" list that works everywhere — what matters is having a repeatable process to get to a good prompt for your specific application.

Worked Example — Chair Fact Sheet → Marketing Copy
Attempt 1

Basic instruction

Your task is to help a marketing team create a description for a retail website based on a technical fact sheet for a chair.

Issue: Result is accurate but far too long.

Attempt 2

Add length constraint

Use at most 50 words.
🧪 Result: 52 words — close enough. LLMs are decent but imprecise with exact word counts.
✓ "at most 3 sentences" → exactly 3 ~ "at most 280 characters" → 281 (close, not exact)

Models tokenize text, so they're better at sentence/word limits than exact character counts.

Attempt 3

Change audience → technical focus

This description is intended for furniture retailers, so should be technical and focus on materials, products, and how it's constructed.
🧪 Scenario: Same fact sheet, different audience (B2B retailer vs. B2C shopper) → prompt reshapes tone/content, not just length.
Attempt 4

Add specific data extraction

Include every 7-character product ID in the technical specification.

Result now includes both product IDs (SWC-100, SWC-110) pulled directly from the fact sheet.

Attempt 5

Add structured formatting

After the description, include a table with product dimensions. Format everything as HTML.
🧪 Result: Valid, renderable HTML output — description + dimension table. This complex prompt was only reached after multiple prior iterations, not written from scratch.
Scaling Up

Early-stage development: iterate against a single example (like this one chair fact sheet).

Mature applications: test the prompt against a larger batch — 10, 50, even 100+ fact sheets — to measure average/worst-case performance before shipping.

🧪 Scenario: An e-commerce catalog generator that must summarize thousands of SKUs consistently needs prompt evaluation across a representative sample, not just one hand-picked example.
💡 Interview/practical tip: Don't chase a "perfect prompt" upfront. Ship a clear-and-specific first draft, run it, diagnose the gap (too long? wrong audience? missing data? wrong format?), and patch the prompt for exactly that gap. Repeat until stable — then, for production use, validate against a larger example set.
