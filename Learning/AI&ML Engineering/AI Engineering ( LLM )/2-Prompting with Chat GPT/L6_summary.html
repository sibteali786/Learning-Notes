🔍 L6 — Check Outputs

DeepLearning.AI · ChatGPT Prompt Engineering for Developers — Lesson 6 summary

🎯 Why Check Outputs Too?

It's not enough to only evaluate inputs (L3) — you should also check the outputs your system generates before showing them to users, for quality, relevance, and safety. Two techniques: run generated responses through the Moderation API, and ask the model itself to self-evaluate its response against a rubric.

Real-world scenario: A customer service bot generates a response that accidentally hallucinates a product feature or price — an output-checking step can catch and block that before it reaches the customer.

🚨 Moderation API on Outputs

Same Moderation API from L3, just applied to the generated response instead of the user's input. A clean product-description response scored very low across all categories and wasn't flagged.

Tip For sensitive audiences (e.g. children's apps), tighten the flagging thresholds on outputs, not just inputs.

🤖 Self-Evaluation Prompt

Feed the model: the customer's question, the retrieved product information, and the agent's generated response — then ask it to output a single Y/N: does the response sufficiently answer the question AND correctly use the product info?

Useful specifically to catch hallucination — the model inventing facts not grounded in the retrieved product data.

🧪 Worked Examples

✅ Good response: Detailed, accurate description of the SmartX ProPhone, FotoSnap DSLR Camera, and TVs, grounded in the real product catalog → model judged: Y
❌ Bad response: "life is like a box of chocolates" (irrelevant, doesn't answer the question or use product info) → model judged: N

Prompt structure:

q_a_pair = f"""
Customer message: ```{customer_message}```
Product information: ```{product_information}```
Agent response: ```{agent_response}```

Does the response use the retrieved information correctly?
Does the response sufficiently answer the question?

Output Y or N
"""

⚖️ Should You Actually Do This in Production?

DoProbably skip (usually)
Moderation API on outputs — cheap, free, good practiceSelf-evaluation via an extra LLM call for every response

Self-evaluation adds an extra model call → more latency and cost (extra tokens). The lesson's honest take: this is rarely used in production, and mostly only worth it if your error-rate tolerance is extremely low (e.g. ~0.0000001%). More capable models like GPT-4-class models make self-evaluation even less necessary. Other ideas mentioned: generate multiple candidate responses and have the model pick the best one, or use chain-of-thought / rubric-style grading prompts for more nuanced evaluation.

def get_completion_from_messages(messages, model="gpt-3.5-turbo", temperature=0, max_tokens=500):
    response = client.chat.completions.create(
        model=model, messages=messages,
        temperature=temperature, max_tokens=max_tokens,
    )
    return response.choices[0].message.content
