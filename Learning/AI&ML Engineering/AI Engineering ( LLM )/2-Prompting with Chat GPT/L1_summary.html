⚙️ How an LLM Learns (Supervised Learning)

An LLM is trained by repeatedly predicting the next token given prior text — a supervised learning task turned into a massive next-word-prediction dataset.

Example: "My favorite food is a bagel with cream cheese and lox." becomes many training pairs:
"My favorite food is a" → bagel  |  "My favorite food is a bagel" → with

Trained on hundreds of billions of words (or more) — this base-training phase can take months on large compute clusters.

🔤 Tokens, Not Words

LLMs predict the next token (common character chunk), not the next character or word. ~1 token ≈ 4 characters ≈ ¾ of a word (English).

learningnewthingsisfun!

Less common words split into multiple tokens:

'prompting' → "prompting"
lollipop → "lollipop"
⚠️ Real-world failure: Asking ChatGPT to reverse the letters of "lollipop" often fails/garbles, because the model sees 3 tokens (l / oll / ipop), not 7 letters.
✅ Fix: Insert dashes/spaces between letters — l-o-l-l-i-p-o-p — forces each character into its own token, so the model can correctly reverse it: p-o-p-i-l-l-o-l.

Context limit example: gpt-3.5-turbo has a limit of roughly 4,000 tokens for input + output combined ("context" = input, "completion" = output). Exceeding it throws an error.

💬 The Chat Format: system / user / assistant

🛠️ system
sets overall tone/behavior
→
🙋 user
specific instruction
→
🤖 assistant
model's reply (can feed back for multi-turn)
Example: system = "You are an assistant who responds in the style of Dr. Seuss." + user = "write me a very short poem about a happy carrot" → rhyming Seuss-style poem output.
Constraint example: system = "All your responses must be one sentence long." → forces a single-sentence carrot story instead of a poem.
Combined: style + length constraints stack together in one system message.

📊 Counting Tokens Per Call

The API response includes usage stats you can inspect:

{'prompt_tokens': 37,
 'completion_tokens': 89,
 'total_tokens': 126}

Useful mainly to check if a user's input risks exceeding the ~4,000-token limit, so you can truncate proactively.

from openai import OpenAI
client = OpenAI()  # reads OPENAI_API_KEY from env automatically

def get_completion(prompt, model="gpt-3.5-turbo"):
    messages = [{"role": "user", "content": prompt}]
    response = client.chat.completions.create(
        model=model, messages=messages, temperature=0,
    )
    return response.choices[0].message.content

def get_completion_from_messages(messages, model="gpt-3.5-turbo", temperature=0, max_tokens=500):
    response = client.chat.completions.create(
        model=model, messages=messages,
        temperature=temperature, max_tokens=max_tokens,
    )
    return response.choices[0].message.content

def get_completion_and_token_count(messages, model="gpt-3.5-turbo", temperature=0, max_tokens=500):
    response = client.chat.completions.create(
        model=model, messages=messages,
        temperature=temperature, max_tokens=max_tokens,
    )
    content = response.choices[0].message.content
    token_dict = {
        'prompt_tokens': response.usage.prompt_tokens,
        'completion_tokens': response.usage.completion_tokens,
        'total_tokens': response.usage.total_tokens,
    }
    return content, token_dict

Also worth noting: gpt-3.5-turbo is legacy-tier now; current OpenAI docs recommend gpt-4o-mini / gpt-4.1-mini for cost-effective chat use, and the 4,000-token context limit is outdated — current models support far larger context windows (128K+ depending on model). Worth re-checking OpenAI's Completions guide and model list before using this in production.
