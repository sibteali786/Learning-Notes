🎯 Why Classify Inputs First?

When a system needs to handle many different types of requests, each with its own set of instructions, it's more reliable to first classify the query type, then route to the appropriate hard-coded instruction set — rather than trying to write one giant prompt that handles everything at once.

Real-world scenario: A customer service assistant gets "close my account" vs "tell me about your TVs" — these need completely different follow-up instructions (account-closure flow with security checks vs. product-info retrieval). Classify first, then branch.

✂️ Delimiters

A delimiter marks where user-supplied text starts/ends, helping the model separate instructions from data (and reducing prompt-injection risk).

This lesson uses #### — chosen because it reliably maps to a single token, making it a clean, unambiguous boundary marker.

📦 Structured Output (JSON)

Asking the model to respond in JSON (e.g. {"primary": ..., "secondary": ...}) means the output can be parsed directly into a Python dict and used programmatically as input to the next step in a pipeline — no manual text parsing needed.

Corrected helper function (drop-in replacement):

from openai import OpenAI
client = OpenAI()  # reads OPENAI_API_KEY from env automatically

def get_completion_from_messages(messages, model="gpt-3.5-turbo", temperature=0, max_tokens=500):
    response = client.chat.completions.create(
        model=model, messages=messages,
        temperature=temperature, max_tokens=max_tokens,
    )
    return response.choices[0].message.content

Also worth checking: for reliably structured JSON output, current OpenAI docs recommend using Structured Outputs (response_format={"type": "json_schema", ...}) instead of relying purely on prompt instructions — this guarantees schema-valid JSON rather than hoping the model follows the "respond in JSON" instruction correctly.
