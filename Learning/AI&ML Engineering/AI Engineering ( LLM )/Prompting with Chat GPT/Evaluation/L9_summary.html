📏 L9 — Evaluation Part II: No Single "Right Answer"

DeepLearning.AI · ChatGPT Prompt Engineering for Developers — Lesson 9 summary

🎯 The Problem: Open-Ended Text Has No Single Right Answer

L8 covered evaluation when there's one objectively correct output (extracted categories/products). But when the LLM generates free-form text — like a customer service reply — there can be many equally valid good answers, so a simple exact-match check doesn't work. This lesson covers two design patterns for evaluating that kind of output using another LLM call as the judge.

Real-world scenario: Two different phrasings of "the SmartX ProPhone costs $899.99 with a 1-year warranty" are both correct — you can't just string-match against one canonical answer.

📋 Pattern 1 — Rubric-Based Evaluation

Ask a second LLM call to judge the first LLM's answer against a checklist ("rubric"), grounded in the retrieved context (the actual product info) — no human-written ideal answer required.

  • Is the response based only on the provided context? (Y/N)
  • Does it include info not in the context? (Y/N)
  • Is there disagreement between response and context? (Y/N)
  • How many questions did the user ask, and were they all answered?

🥇 Pattern 2 — Compare Against an Expert ("Ideal") Answer

When you do have a human-expert-written ideal answer, ask an LLM to compare the generated response against it and classify the relationship — rather than relying on classic NLP text-similarity metrics like BLEU score, which measure surface overlap but not factual correctness.

🧪 Rubric Evaluation — Worked Example

User: "tell me about the smartx pro phone and the fotosnap camera, the dslr one. Also, what TVs or TV related products do you have?"

Generated answer: Full description of the SmartX ProPhone, FotoSnap DSLR Camera, and 5 TV/audio products with prices, ending in a helpful follow-up question.

Rubric evaluation output:

- Is the response based only on the context? Y
- Does it include info not in context? N
- Is there disagreement? N
- Questions asked: 2
- Question 1 answered? Y   Question 2 answered? Y
- Questions addressed: 2

🏆 A–E Grading Scale (from OpenAI's open-source Evals framework)

This rubric prompt is adapted from OpenAI's open-source evals project — a community-contributed library of model-graded evaluation templates.

A — Submission is a subset of the expert answer, fully consistent
B — Submission is a superset of the expert answer, fully consistent (may include extra facts)
C — Submission contains all the same details as the expert answer
D — Disagreement between submission and expert answer
E — Answers differ, but the difference doesn't matter for factuality

"Life is like a box of chocolates" (irrelevant answer) vs. the detailed expert answer → graded D (disagreement) — correctly identified as a bad response.

📌 Note on the notebook's actual output: the video narration says the good, detailed assistant answer was graded A ("subset of the expert answer, fully consistent"). But re-running the same cells in this notebook produced D (disagreement) for that same good answer — likely because the current pricing in the generated answer (e.g. CineView 4K TV at $599.99) doesn't exactly match the pricing baked into the hard-coded "ideal answer" text in the notebook, or because model outputs for grading prompts like this aren't perfectly stable run-to-run even at temperature 0. Worth being aware that this style of LLM-as-judge evaluation is not fully deterministic — treat individual grades as noisy signals, not exact scores, especially for boundary cases.

🧠 Practical Advice from the Lesson

  • Use a stronger model to judge. Even if your production system runs on GPT-3.5 Turbo for cost/speed, using GPT-4 for the (less frequent) evaluation calls gives a more rigorous, trustworthy judgment.
  • Both patterns are "LLM evaluates LLM." The rubric pattern needs no ideal answer (just the retrieved context); the A–E pattern needs a human-written ideal answer but gives finer-grained comparison.
  • These evaluation tools apply both during development (tuning prompts) and in production monitoring (tracking quality over time as real traffic comes in).

from openai import OpenAI
client = OpenAI()

def get_completion_from_messages(messages, model="gpt-3.5-turbo", temperature=0, max_tokens=500):
    response = client.chat.completions.create(
        model=model, messages=messages,
        temperature=temperature, max_tokens=max_tokens,
    )
    return response.choices[0].message.content
