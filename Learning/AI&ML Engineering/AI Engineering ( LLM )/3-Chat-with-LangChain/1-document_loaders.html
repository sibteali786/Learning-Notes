LANGCHAIN RAG PIPELINE — STEP 1 DOCUMENT LOADERS

Document Loading in LangChain

How to pull data from 80+ sources into a standardized "Document" object before it can be chunked, embedded, and retrieved.

Problem Statement

To build a "chat with your data" application, raw data first needs to be loaded into a workable, standardized format. Data lives in wildly different places (websites, YouTube, databases, Notion) and in different formats (PDF, HTML, JSON). Document Loaders are LangChain's abstraction that handles the specifics of accessing + converting any of these sources into one consistent interface.

How It Works

Any Source (PDF, YouTube, URL, Notion...)
→
Loader.load()
→
List[Document]

Every loader, regardless of source, ultimately returns a Document object with two parts:

FieldDescription
page_contentThe actual text content of that chunk/page
metadataExtra info — e.g. source (file/URL) and page number

80+ Loaders — Rough Categorization

Unstructured

Public sources

YouTube, Twitter, Hacker News, text files

Unstructured

Proprietary sources

Figma, Notion, and other company/personal tools

Structured

Tabular data w/ text cells

Airbyte, Stripe, Airtable — for QA/semantic search over table data

Four Loaders Covered in Detail

1. PDF — PyPDFLoader

Loads a PDF and returns one Document per page.

from langchain.document_loaders import PyPDFLoader

loader = PyPDFLoader("docs/cs229_lectures/MachineLearning-Lecture01.pdf")
pages = loader.load()

# pages is a list — e.g. 22 pages = 22 Document objects
page = pages[0]
print(page.page_content[:500])   # first 500 chars
print(page.metadata)             # {'source': '...pdf', 'page': 0}
Real-world scenario: Loading a 22-page lecture PDF gives you 22 Document objects — each one's metadata tags which page it came from, so later when your chatbot answers a question, it can cite "page 4" as the source.

2. YouTube — Audio → Whisper transcript

Downloads the audio from a YouTube video, then transcribes it into text using OpenAI's Whisper speech-to-text model.

from langchain.document_loaders.generic import GenericLoader
from langchain.document_loaders.parsers import OpenAIWhisperParser
from langchain.document_loaders.blob_loaders.youtube_audio import YoutubeAudioLoader

url = "https://www.youtube.com/watch?v=..."
save_dir = "docs/youtube/"

loader = GenericLoader(
    YoutubeAudioLoader([url], save_dir),
    OpenAIWhisperParser()
)
docs = loader.load()
print(docs[0].page_content[:500])
Real-world scenario: Want to "chat with" a favorite lecture or podcast episode on YouTube? This loader pipeline turns the raw audio into searchable transcript text — no manual transcription needed.

3. URLs / Web pages — WebBaseLoader

Loads content directly from any URL on the internet.

from langchain.document_loaders import WebBaseLoader

loader = WebBaseLoader("https://github.com/some-repo/README.md")
docs = loader.load()
print(docs[0].page_content)
Gotcha: Raw web content often comes with a lot of whitespace and boilerplate mixed with the real text — this is a good example of why post-processing / cleaning is usually required before using the content downstream.

4. Notion — NotionDirectoryLoader

Notion is a common store of personal/company knowledge. You first export your Notion database (to markdown), then load that export directory.

from langchain.document_loaders import NotionDirectoryLoader

loader = NotionDirectoryLoader("docs/Notion_DB")
docs = loader.load()
print(docs[0].page_content[:200])  # markdown-formatted text
Real-world scenario: The lesson uses "Blendle's Employee Handbook" exported from Notion as a live example — teams often build internal chatbots over their own Notion wiki this way.

Key Distinctions

Structured vs. Unstructured sources

Unstructured = raw text-like content (PDFs, web pages, videos).
Structured = tabular data (Airtable, Stripe) where only some cells contain text worth semantic search.

Loading ≠ Chunking

Loaders only standardize the format. Documents are often still too large — the next step (splitting) breaks them into smaller chunks so retrieval pulls only the most relevant snippet, not the whole document.

Practical Tips

✅ Every loader exposes the same interface: loader.load() → List[Document]. Learn this pattern once, and any of the 80+ loaders becomes usable.

✅ Always inspect .metadata — it's what lets your RAG app cite sources later (filename, page number, URL).

✅ Raw loaded content is rarely "clean" (whitespace, boilerplate) — expect a post-processing step.

✅ Why this matters for RAG: retrieval quality depends on retrieving small, relevant chunks — not entire documents — which is why loading is immediately followed by splitting in the pipeline.
