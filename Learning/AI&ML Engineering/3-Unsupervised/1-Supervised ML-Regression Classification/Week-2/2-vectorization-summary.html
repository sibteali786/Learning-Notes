⚡ Vectorization

Vectorized code is shorter to write and runs much faster — it lets NumPy tap into parallel hardware (CPU or GPU) instead of computing one step at a time.

1️⃣ Setup: Parameters & Features

Math indexing starts at 1 (w₁, w₂, w₃), but Python/NumPy indexing starts at 0 (w[0], w[1], w[2]).

import numpy as np
w = np.array([1.0, 2.5, -3.3])   # w[0], w[1], w[2]
b = 4
x = np.array([10, 20, 30])       # x[0], x[1], x[2]
🔹 n = 3 here (number of features). w and x are NumPy arrays, not plain lists — that's what enables vectorized math.

2️⃣ Three Ways to Compute the Prediction

Method 1 — Manual

Write out every term explicitly. Fine for n=3, unworkable for n=100,000.

f = w₁x₁ + w₂x₂ + w₃x₃ + b
f = w[0]*x[0] + \
    w[1]*x[1] + \
    w[2]*x[2] + b

😞 Inefficient to write AND to compute.

Method 2 — For Loop

Scales to any n, but still computes one multiply-add at a time (sequential).

f = Σ(j=1 to n) wⱼxⱼ + b
f = 0
for j in range(0, n):
    f = f + w[j] * x[j]
f = f + b

😞 Better, but not vectorized → still slow for large n.

Method 3 — Vectorized ✅

Uses NumPy's dot product, which runs in parallel under the hood.

f = w⃗ · x⃗ + b
f = np.dot(w, x) + b

😄 One line. Much faster, especially as n grows large.

3️⃣ Why Vectorization Wins — Two Benefits

BenefitExplanation
Shorter codeOne line (np.dot(w,x)+b) instead of loops or long expressions — easier to write and read
Faster executionnp.dot uses parallel hardware (CPU vector instructions or GPU) instead of computing terms one after another like the for loop does

4️⃣ Real-World Angle: Why This Matters at Scale

Example scenario: Imagine n = 100,000 features (e.g., a large feature set in a big dataset).

  • Manual expression → impossible to type 100,000 terms
  • For loop → runs sequentially, 100,000 steps, one at a time
  • np.dot(w, x) → computed in parallel, dramatically faster

This speedup matters even more when running on a GPU (Graphics Processing Unit), hardware originally built for graphics but well suited to the same parallel math used in ML.
