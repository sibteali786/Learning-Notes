🎯 Numerically Stable Softmax & Logistic Loss

🐛 The Bug: Floating-Point Round-off

Computers store numbers with finite precision. The order of operations to compute the same value can change how much rounding error creeps in.

Option 1 — Direct

x1 = 2.0 / 10000
# 0.000200000000000000

Option 2 — Indirect (same value)

x2 = (1+1/10000) - (1-1/10000)
# 0.000199999999999978

📌 Same mathematical answer, different computation path → different round-off error. This exact issue shows up when computing the softmax/sigmoid loss the "obvious" two-step way.

🔧 Fix for Logistic Regression

❌ Original (2 steps)

a = g(z) = 1/(1+e−z)
loss = −y·log(a) − (1−y)·log(1−a)
Dense(units=1, activation='sigmoid')
model.compile(loss=BinaryCrossentropy())

✅ Recommended (1 fused step)

loss = −y·log(1/(1+e−z)) − (1−y)·log(1−1/(1+e−z))
Dense(units=1, activation='linear')
model.compile(loss=BinaryCrossentropy(
    from_logits=True))

💡 "logit" = the raw z value, before any activation is applied.

🔧 Fix for Softmax Regression (same idea, N classes)

❌ Original

(a₁,...,a₁₀) = g(z₁,...,z₁₀)
loss = −log(aj)  where j = true label
Dense(units=10, activation='softmax')
model.compile(loss=
  SparseCategoricalCrossentropy())

✅ Recommended

loss = −log( ezj / (ez₁+⋯+ez₁₀) )
Dense(units=10, activation='linear')
model.compile(loss=SparseCategorical
  Crossentropy(from_logits=True))

❓ Q&A — "How does linear + from_logits move the 'a' computation into the loss step?"

Question: How does applying a linear activation to the last layer, then using from_logits=True, "send" the calculation of a — which normally happens at the last layer — to instead be calculated inside the loss function step?

Normally (two separate steps):

Layer applies sigmoid
→
a is computed & stored
→
Loss reads stored a

Here, a is fully computed and rounded off before the loss function ever touches it. That rounding error is now locked in — the loss can't undo it.

With activation='linear' + from_logits=True:

Layer outputs raw z (no activation applied)
→
Loss fn receives z directly
→
Loss fn computes sigmoid(z) AND the log-loss together, as one expression

activation='linear' means the last layer literally skips applying sigmoid/softmax — it just hands over z (the logit). from_logits=True then tells the loss function: "what you're getting isn't a probability, it's a raw z — compute the whole formula -y·log(sigmoid(z)) - (1-y)·log(1-sigmoid(z)) yourself, in one go."

Why that helps: because it's now one combined symbolic expression instead of two separate rounded steps, TensorFlow's math backend can algebraically simplify it internally before evaluating — substituting sigmoid(z)=1/(1+e⁻ᶻ) straight into the log terms and cancelling/rearranging so it never needs to store a dangerously large or small intermediate number.

🔑 Bottom line: a is never actually computed and stored as its own number anymore. It only exists symbolically, folded inside the bigger loss formula — which is evaluated as a whole, giving TensorFlow room to pick a numerically safer path to the same final answer (exactly like the 2/10000 vs. indirect-subtraction example above).

🧠 Why Fusing Helps (Mechanism)

Layer outputs raw z (logit)
→
Loss fn receives z, not a
→
TF builds ONE combined formula
→
TF rearranges algebraically
→
Avoids tiny/huge intermediate e^z values

🔑 Key insight: "a" is never separately computed and stored. It only exists symbolically inside the full loss expression — so TensorFlow can pick a numerically safer path to the same final number, the same way 2/10000 beat the indirect subtraction above.

⚠️ One Extra Step at Prediction Time

Since the last layer now outputs raw logits (z), not probabilities (a), you must manually apply the activation after predicting:

Model typePrediction code
Binary (logistic)logit = model(X)
f_x = tf.nn.sigmoid(logit)
Multiclass (softmax)logits = model(X)
f_x = tf.nn.softmax(logits)

📌 model(X) now returns z₁...z₁₀ — not a₁...a₁₀ — so this manual softmax/sigmoid call is required to get back actual probabilities.

🌍 Real-World Analogy

Think of it like doing a multi-step arithmetic word problem:

  • Old way: Round your answer after every single step, then feed that rounded number into the next step — errors compound.
  • New way: Write out the entire equation symbolically first, simplify algebraically (cancel terms, combine fractions), and only round once at the very end — much less error accumulates.

TensorFlow's from_logits=True is exactly this: "don't round off after computing the probability — give me the raw score and let me simplify the whole formula before computing anything."
