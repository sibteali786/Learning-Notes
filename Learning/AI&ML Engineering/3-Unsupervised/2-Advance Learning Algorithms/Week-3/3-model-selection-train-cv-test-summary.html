Lesson 3 — Model Selection: Train / Cross-Validation / Test

Why one test set isn't enough to both pick a model AND report how good it is.

1 Recap: Training Error Lies to You

Once w,b are fit to the training set, J_train is likely lower than the true generalization error — the model has literally seen and optimized against those exact points. J_test is a much better estimate of real-world performance, because the model never touched that data during fitting.

2 Using J_test to Pick a Polynomial Degree — Looks Reasonable...

Suppose you're not sure what degree polynomial fits best. Try d = 1 through d = 10, fit each on the training set, and compute J_test for each:

d=1f = w₁x + bJ_test(w⁽¹⁾,b⁽¹⁾)
d=2f = w₁x + w₂x² + bJ_test(w⁽²⁾,b⁽²⁾)
d=3f = w₁x + w₂x² + w₃x³ + bJ_test(w⁽³⁾,b⁽³⁾)
⋮⋮⋮
d=5f = w₁x + ... + w₅x⁵ + bJ_test lowest ✓
⋮⋮⋮
d=10f = w₁x + ... + w₁₀x¹⁰ + bJ_test(w⁽¹⁰⁾,b⁽¹⁰⁾)

Pick d=5 (lowest J_test), then report J_test(w⁵,b⁵) as "how well this model generalizes."

⚠ This procedure is flawed

You just used the test set to choose d — an extra parameter, selected by whichever value made J_test smallest. That's the same mistake as fitting w,b to training data and then reporting J_train: J_test(w⁵,b⁵) is now an optimistic (too-low) estimate of true generalization error, because the test set influenced a decision instead of staying purely an unbiased final check.

3 The Fix: Add a Third Split — Cross-Validation Set

Split data into three subsets instead of two. A common split is 60% train / 20% cross-validation (CV) / 20% test:

60% Train
20% CV
20% Test

"Cross-validation" is also called the validation set, development set, or dev set — all the same thing, just different names practitioners use.

4 The Correct Model Selection Procedure

1
Fit w,b for each candidate model (d=1 through d=10) using the training set.
2
Evaluate each fitted model on the cross-validation set, computing J_cv(w⁽¹⁾,b⁽¹⁾) through J_cv(w⁽¹⁰⁾,b⁽¹⁰⁾).
3
Pick the model with the lowest J_cv — e.g. d=4 if J_cv(w⁽⁴⁾,b⁽⁴⁾) is smallest.
4
Only now touch the test set: report J_test(w⁴,b⁴) as the generalization estimate.
d=1f = w₁x + bJ_cv(w⁽¹⁾,b⁽¹⁾)
d=2f = w₁x + w₂x² + bJ_cv(w⁽²⁾,b⁽²⁾)
d=3f = w₁x + w₂x² + w₃x³ + bJ_cv(w⁽³⁾,b⁽³⁾)
d=4f = w₁x + ... + w₄x⁴ + bJ_cv lowest ✓ → pick this
⋮⋮⋮
d=10f = w₁x + ... + w₁₀x¹⁰ + bJ_cv(w⁽¹⁰⁾,b⁽¹⁰⁾)
Why this works

w,b were fit using the training set. The degree d was chosen using the CV set. The test set was never touched during any decision — so J_test(w⁴,b⁴) is a fair, unbiased estimate of true generalization error.

5 Same Procedure Works for Neural Network Architecture Selection

Model selection isn't limited to polynomial degree — it generalizes to choosing between entire architectures (e.g. handwritten digit classification):

1. Small NN (25 → 15 → 1 units)J_cv(w⁽¹⁾,b⁽¹⁾)
2. Medium NN (20 → 12 → 12 → 20 units) ✓ lowest J_cvJ_cv(w⁽²⁾,b⁽²⁾)
3. Large NN (32 → 16 → 8 → 4 → 12 units)J_cv(w⁽³⁾,b⁽³⁾)

Train all three on the training set → evaluate each on CV set (for classification, J_cv is typically the fraction of CV examples misclassified) → pick the architecture with lowest J_cv → report J_test on that chosen network as the final generalization estimate.

6 The Golden Rule

Best Practice

Make every decision about your model — fitting parameters, choosing polynomial degree, choosing architecture, choosing hyperparameters — using only the training and cross-validation sets. Never look at the test set until you've locked in your final model. Only then evaluate on test, exactly once, to report generalization performance.

7 Clarifying Q&A

Q: Why not just use J_test(w⁵,b⁵) for model selection — why go to the trouble of a cross-validation set?

Because using the test set to make a decision (which degree d to pick) makes the test set complicit in fitting — no different in principle from fitting w,b to training data. J_test would then be measuring "how well did this model do on the data I used to choose it," not "how well does it do on truly unseen data." Result: J_test(w⁵,b⁵) ends up optimistically low, understating the real generalization error. The cross-validation set exists specifically to absorb this decision-making role, so the test set can remain completely untouched and give one final, honest number at the end.

Q: What's the ideal train/CV/test split fraction for a classification problem?

No different rule for classification vs regression — the split is about data volume, not task type. 60/20/20 (train/CV/test) is the classic default, sometimes seen as 70/15/15. With very large datasets, the CV and test percentages often shrink (e.g. 98/1/1) because even 1% of a huge dataset is still enough examples to validate/test on reliably.

Q: How do we know we chose the "right" J_test metric for classification vs. regression?

There isn't one universally "correct" metric — it's a design choice, but two things must hold: (1) the metric must match the problem type — squared error for regression; logistic loss or (more common and interpretable) fraction misclassified for classification — and (2) the same metric must be used consistently across J_train, J_cv, and J_test, otherwise your model-selection comparisons and final generalization estimate aren't measuring the same thing.
