🏗️ RAG: Architecture Overview

DeepLearning.AI · Retrieval Augmented Generation · Module 1 · "RAG architecture overview" (Zain Hasan)

The Three Components

You've already seen the most important components in a RAG system. This lecture shows how they work together.

LLM

The language model itself. Generates the response.

Knowledge base

A database of relevant information. Practically speaking, just a database of useful documents.

Retriever

Searches the knowledge base and returns the documents it determines are most relevant to the prompt.

1. Normal LLM Use vs a RAG System

Normal use: you type a prompt and send it to the LLM. The LLM processes the prompt and generates a response.

RAG: the user experience is identical (submit a prompt, get back a response), but inside the system there are a few more steps.

Slide: the shaded area is the added RAG system sitting between the prompt and the LLM; the extra trip through it is the "added latency".

2. What Happens Inside a RAG System

StepWhat happens
1. PromptThe user submits a prompt. The RAG system first routes it to the retriever.
2. RetrieveThe retriever has access to the knowledge base (a database of useful documents). It queries the database and returns the documents it determines are most relevant to the prompt.
3. AugmentThe system creates an augmented prompt, incorporating information from the relevant documents into the original prompt.
4. GenerateFrom here the system operates like any other LLM: the augmented prompt is sent to the LLM and it generates a response.
Example augmented prompt (from the lecture): "Answer the following question: why are hotels in Vancouver so expensive this coming weekend? Here are five relevant articles that may help you respond:" followed by text inserted from the articles.

3. What the LLM Does With It

Two knowledge sources

The LLM responds based on both the knowledge it learned from its training data and the additional context provided by the retrieved documents.

Same experience, slight cost

User experience is the same as always, perhaps with a little bit of added latency. You type a prompt, you get back a response.

Thanks to the side route through the retriever, there's a higher likelihood the response is accurate, up-to-date, and context aware. The main difference between using an LLM directly and a RAG system is the addition of the retriever.

4. Advantages of RAG

This fairly straightforward addition (the retriever) allows for a number of advantages.

① Injects missing knowledge

Slide: adds info not in the training data (e.g., policies, updates). Lecture: first and most important; makes information available to the LLM that might otherwise not be. Company policies, a piece of personal information, or this morning's headlines: RAG is often the only way to make some kinds of information available to an LLM.

② Reduces hallucinations

Slide: grounds answers with relevant context. Lecture: hallucinations or misleading responses are often caused by LLMs generating responses about topics excluded from their training data or just mentioned rarely. Adding relevant information directly in the prompt grounds the model's responses and makes them less likely to create generic or misleading text.

③ Keeps models up to date

Slide: reflects new info by updating the knowledge base. Lecture: retraining a language model is usually a costly and time-consuming feat, so LLMs struggle with very new information. In RAG you simply update the knowledge base like entries in any other database. As soon as those changes are indexed, the LLM can respond based on the new information.

④ Enables source citation

Slide: includes sources for verifiable answers. Lecture: a RAG system can add citation information to the augmented prompt, and the LLM can include it in its response. This grounds the response and lets human readers dig deeper and validate the generated text.

⑤ Focuses the model on generation

Slide: retriever finds facts, LLM writes responses. Lecture: the retriever filters down a vast world of information, finds what's most important and relevant, and presents it succinctly. The LLM still needs to write a good response, but it isn't relied upon for fact-finding or filtering. Each component works on the area of its greatest strength.

5. Code Demo (Abstracted)

A very simple demo with most details abstracted away. Two helper functions:

retrieve(query)

A wrapper around a retriever. Accepts a text query and returns relevant documents from the knowledge base.

generate(prompt)

A wrapper around a large language model. Accepts a text prompt and returns the LLM's response.

Step A: save the prompt, then submit it directly to the LLM.

prompt = "Why are hotel prices in Vancouver super expensive this weekend?"
generate(prompt)
Slide shows the end of this answer: "...conditions, I can only provide general guidance about hotel pricing trends." (the plain LLM can't answer specifically)

Step B: see what additional information the retriever has. ✓ 0.5s

retrieved_documents = retrieve(prompt)
print(retrieved_documents)
Taylor Swift is performing a two-night concert residency at BC Place this weekend, drawing thousands of fans to Vancouver. The Taylor Swift concerts at BC Place have created unprecedented demand for Vancouver accommodations this weekend. Swifties from across North America are flocking to Vancouver for Taylor Swift's BC Place shows, causing hotel shortages.

Step C: build an augmented prompt with both the original question and the retrieved information. ✓ 0.0s

augmented_prompt = f"""Respond to the following prompt: {prompt}

using the following retrieved information to help you answer {retrieved_documents}"""

Step D: submit the augmented prompt to the LLM. ✓ 1.0s

generate(augmented_prompt)
"The high hotel prices in Vancouver this weekend can be attributed to Taylor Swift's BC Place concerts as shown in the retrieved data. The two-night residency has transformed Vancouver into a destination for music fans worldwide, with Swifties traveling from across the continent. This massive influx of visitors has created a supply shortage, leading to surge pricing across all hotels."
Author's conclusion: "That's really all there is to RAG. Adding additional context to your prompt to help an LLM respond more accurately." This was a very high-level overview; the next video looks at each component in more detail.

Interview / Practical Tips

  • Be able to walk through the flow in order: prompt → retriever (↔ knowledge base) → relevant documents → augmented prompt → LLM → response.
  • The single architectural difference vs a normal LLM call is the retriever. Know the one cost the author names: added latency.
  • Know all five advantages: missing knowledge, fewer hallucinations, up to date, source citation, model focused on generation.
  • "Up to date without retraining": update the knowledge base like any database; changes take effect once indexed.
  • Be able to explain the demo: retrieve() → build augmented prompt → generate().
