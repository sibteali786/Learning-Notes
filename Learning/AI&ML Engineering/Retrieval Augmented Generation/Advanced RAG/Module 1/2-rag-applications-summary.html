🧭 RAG: Applications

DeepLearning.AI · Retrieval Augmented Generation · Module 1 · "Applications of RAG" (Zain Hasan)

Recap & The Big Picture

Core idea: pair an off-the-shelf LLM with a knowledge base of information it might not have had access to during training. Many LLM-powered systems already work this way. The lecture walks through five.

1. Code Generation

Problem: LLMs have been trained on lots of code (conceivably every public Git repo), but generating correct code for a specific project requires specialized information that isn't in public training data.

LLM needs your project's context

Classes, functions, definitions, and the overall coding style.

Codebase = knowledge base

RAG retrieves project-specific content (relevant classes, definitions, files) for the LLM.

Better code generation & Q&A

Answers tailored to your actual repository.

2. Company Chatbots

Every company has its own products, policies, and communication guidelines. Treat enterprise documents as the knowledge base.

Tailored to your company

Every business has its own products, policies, and communication style.

Uses internal documents

Manuals, support guides, FAQs.

Grounds answers in real context

Reduces generic or incorrect/misleading answers.

DeploymentWhat it knows
Customer service chatbotCompany product info, current inventory, common troubleshooting steps
Internal chatbotAccurately answers company-policy questions or directs you to useful documentation
Slide example: an H&M chatbot ("I can give you quick answers to frequently asked questions"). The knowledge base helps ground responses in company-specific products/policies and minimizes generic or misleading answers.

3. Specialized Knowledge (Healthcare & Legal)

High-impact domains

Legal and medical use cases.

Specialized documents

Case files, recently published journals, private data.

Accurate, secure use

Supports precision and privacy needs.

Why RAG matters most here: precision is imperative, and the amount of niche and potentially private information is vast. The lecture says a RAG-based approach might be the only way to deploy an LLM product that is accurate enough and can use private information.

Slide example (legal): the query "Identify which of these third-party contracts do not contain our standard assignment language" run over a project of 827 files (e.g., supply and license agreement PDFs).

4. AI-Assisted Web Search

Search engines as retrievers

Historically: given a query, return relevant websites.

AI summarizes results

Key info in a quick, skimmable format.

Internet as knowledge base

Summaries powered by real-time retrieval.

Slide example: a Google AI summary for "what is the most common element on the periodic table" (hydrogen), shown above the regular website results. AI web summaries are basically a RAG system whose knowledge base is the entire internet.

5. Personalized RAG

Large-scale RAG is powerful; so are highly personalized ones. Assistants now live in text messages, email, word processors, calendars and help you send messages, organize your schedule, draft documents, and finish projects big and small.

Assistants everywhere

Messaging apps, email clients, etc.

They need context

More context leads to better results.

Your data = knowledge base

Small-scale (texts, contacts, emails, a folder of docs) but dense with important context.

Interview / Practical Tips

  • Be ready to name 3+ applications and what the knowledge base is in each (repo, company docs, case files/journals, the internet, personal data).
  • "Grounding" = anchoring responses in your specific documents to cut generic or misleading output.
  • High-stakes domains (legal, medical): precision + privacy are the justification for RAG.
  • Search engines were already retrievers; AI summaries add the generation step.
  • Knowledge bases can be tiny (your inbox) or huge (the web). The architecture is the same.
