🔎 RAG: Introduction

DeepLearning.AI · Retrieval Augmented Generation · Module 1 · Intro video (Zain Hasan) · "Introduction to RAG"

The Problem

LLMs are remarkable: they answer questions, summarize and rewrite text, give feedback on documents, generate code and more. Tasks that seemed out of reach a few years ago. But an LLM only knows what was in its training data.

Unseen info → weaker answers When the prompt needs information the model never saw, quality drops.

💡 RAG = an approach that improves LLM performance by giving it access to information it doesn't know from training.

1. Two Steps for Answering Any Question

Humans answer questions in two phases. RAG copies that exact structure.

QuestionRetrieval (collect)Generation (reason)
Why are hotels expensive on the weekend?None neededRespond from your own knowledge: more people travel on weekends → more competition for rooms
Why are hotels in Vancouver super expensive this coming weekend?A little Search online → Taylor Swift is in town for a two-night residencyCombine found fact + general knowledge → answer
Why doesn't Vancouver have more hotel capacity close to downtown?A lot Extensive research: Vancouver's development history, urban planning, etc.Synthesize the research into an answer
Key idea: sometimes you need zero info, sometimes a little, sometimes a lot. Retrieval = collecting useful info. Generation = reasoning over it and responding.

2. Traditional LLM Usage

Think of an LLM as a person with broad general knowledge from reading huge chunks of the internet (but not someone who spends time on Wikipedia — it's a mathematical model trained on massive internet datasets).

During training the model learns whatever is in the data. When you prompt it, you're hoping relevant info was in training — ideally many times.

✓ Great answer when…

The relevant knowledge was in the training data (e.g., "why are hotels expensive on weekends").

✗ Not-so-great answer when…

The prompt is about a very recent event or specialized info the model hasn't seen.

Training data sources (slide): Web pages · Books · Forums · Code. Example: for "Why doesn't Vancouver have more hotel capacity close to downtown?", training data might contain a book on Urban Development in Vancouver (zoning laws and city planning since the early 1900s limited downtown hotel growth) and a forum comment ("probably because land costs are super high near downtown"). The LLM only has what happened to be there.

3. What LLMs Don't Know

🔒 Private databases

LLMs can't access confidential info. Companies keep private databases.

🕳️ Hard-to-access info

Some information isn't widely available online, so it's inaccessible to LLMs.

⏱️ Real-time data

LLMs are trained on past data and don't update automatically. News is published every minute.

Just as it's unreasonable to expect you to be an expert on every topic, it's unreasonable to expect an LLM to be. Both give much better responses with better information.

4. The Core Idea: "Just put it in the prompt!"

How do you make sure the LLM knows the useful information? Modify the prompt before sending it. Add information that helps the LLM respond, alongside the user's original question.

Now the LLM has the information it needs to respond accurately (e.g., the Taylor Swift residency).

5. The Retriever

The info has to come from somewhere. The component of a RAG system that handles this is the retriever.

  • Manages a knowledge base of trusted, relevant, and possibly private information
  • When a prompt arrives, finds the most relevant information and shares it with the LLM
  • Improves generation: the model uses the retrieved info when it responds

6. Full RAG Flow (Putting It Together)

Name decoded: Retrieval Augmented Generation — you're improving ("augmenting") the way an LLM generates text by first retrieving relevant info from a knowledge base. Admittedly a mouthful.

7. Plain LLM vs RAG

Plain LLMRAG system
Knowledge sourceOnly training dataTraining data + knowledge base via retriever
Recent eventsUnaware (trained on past data)Info retrieved from the knowledge base
Private / confidential dataCan't accessRetriever manages private info
What goes to the modelUser's promptUser's prompt + retrieved info (augmented prompt)

11. Interview / Practical Tips

  • Explain RAG in one line: retrieve relevant info first, then have the LLM generate using it.
  • Name the three gaps RAG fills: private data, hard-to-access data, real-time data.
  • Distinguish the two components: retriever (finds info from the knowledge base) vs LLM (generates the answer).
  • Key mechanism: the prompt is modified before it reaches the LLM. The model itself isn't changed.
  • Retrieval need varies: none, a little, or a lot, depending on the question.

💡 Key Takeaway

LLMs are only as good as the information they have access to. RAG = Retrieval (collect info via the retriever from a knowledge base) + Augmented Generation (add it to the prompt so the LLM reasons over it).
