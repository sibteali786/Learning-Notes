Keyword search: counting words, then counting them smarter

A decades-old technique that’s still a key part of modern RAG retrievers. The idea: documents that contain many of the prompt’s words are more likely to be relevant. The lesson builds the scoring up in four steps, ending at TF-IDF.

Step 0: turn text into a bag of words

Both the prompt and every document are treated as a bag of words: word order is ignored and only which words appear, and how often, matters.

“Making pizza without a pizza oven”
pizza2
making1
without1
a1
oven1

These counts are stored in a vector with one spot per word in the system’s vocabulary, easily tens of thousands of spots. Each number counts how often that word appears in the text.

Sparse vectors and the inverted index

Most spots in the vector hold zeros, so these are called sparse vectors. A sparse vector is generated for every document to prepare the knowledge base.

Sparse vector for the prompt (tiny vocabulary shown)

Few non-zero entries: that’s what “sparse” means.

Term-document matrix = inverted index

Arrange all document vectors in a grid: each column is a document, each row is a word. It’s “inverted” because you usually start from a document and ask which words it has; here you start from a word and find every document containing it.

The index is built once, before any search. At query time only the prompt’s sparse vector is generated, which is quick.

Example index (5 documents)

Filled cell: the document contains the word.

Scoring: four steps, each fixing the last problem

Each prompt word is a keyword. For each keyword, find its row in the index and go across it, awarding points to documents.

1

Simple scoring: one point per keyword present

For each keyword, award one point to every document that contains at least one copy. The prompt has five keywords, so the highest possible score is five. Rank by total.

Problem: it ignores how many times a keyword appears, which likely signals greater relevance.

2

Term frequency (TF): a point every time it appears

Award each document the number of points in its column, not just one per keyword. Example query: pizza oven.

Document 1Homemade pizza in oven is better than frozen pizza
pizza ×2, oven ×1Simple: 2TF: 3
Document 2Wood-fired oven is a better oven than a stone oven for cooking pizza
pizza ×1, oven ×3Simple: 2TF: 4

Problem: longer documents contain keywords many times simply because they’re longer.

3

Normalized TF: divide by document length

Score = (keyword occurrences) / (total words in document)

Levels the playing field. It rewards documents where keywords are a bigger share of the text and de-emphasizes long documents that hit keywords only because they’re long.

Problem: every keyword counts equally, whether it’s a filler word like “the” or a telling word like “pizza”.

4

TF-IDF: weight words by how rare they are

Score = TF(word, doc) × log(total docs / docs containing word)

Weighting by inverse document frequency (IDF) makes rare words count more. Details in the next section.

Computing IDF, step by step

Say the knowledge base has 100 documents. “pizza” appears in 5 of them; “the” appears in all 100.

🍕 pizza (rare)

1. Document frequencydocs containing word ÷ total docs5/100 = 0.05
2. Flip it to reward rare words1 ÷ DF20
3. Apply log (base 10)tames the exaggeration1.30

the (common)

1. Document frequencydocs containing word ÷ total docs100/100 = 1.0
2. Flip it1 ÷ DF1
3. Apply log (base 10)too common, no weight0

Why log? Without it, rare words are overly rewarded (20 vs 1). With it, rare words still weigh more but far less exaggerated. The slide writes this as log(1/20); the value 1.30 is log10(20).

From index to TF-IDF matrix

Multiply each row of the inverted index by that word’s IDF, giving the TF-IDF matrix. Then score exactly as before: for each prompt keyword, go across its row and award each document the value in that cell. Values below are the slide’s illustrative numbers.

Low-scoring document

Top-scoring documents use keywords often and, especially, use keywords that are rare across the whole knowledge base. TF-IDF is the standard baseline for keyword retrieval. Modern systems use a slightly refined version called BM25 (next lesson).

The same thing in a few lines of Python

From-scratch sketch matching the lesson’s formulas (normalized TF × log10 IDF). It skips punctuation handling and is meant for learning, not production.

import math
from collections import Counter

corpus = ["making pizza without a pizza oven", "..."]
docs = [d.lower().split() for d in corpus]           # bag of words
N = len(docs)

df  = Counter(w for d in docs for w in set(d))       # docs containing each word
idf = {w: math.log10(N / n) for w, n in df.items()}  # inverse document frequency

def tfidf_score(prompt, doc):
    counts = Counter(doc)
    return sum(
        (counts[w] / len(doc)) * idf.get(w, 0)       # normalized TF x IDF
        for w in prompt.lower().split()
    )

ranked = sorted(docs, key=lambda d: tfidf_score("pizza oven", d), reverse=True)

Library note: scikit-learn’s TfidfVectorizer uses a smoothed natural-log IDF and L2 normalization by default, so its numbers won’t match the lesson’s exactly. The ranking idea is the same. Check the current scikit-learn docs for its exact formula before comparing values.

Alternatives and trade-offs

Simple presence counting

Pros
  • Trivial to build and explain
Cons
  • Ignores repetition, length and word rarity

Normalized TF

Pros
  • Fair to short and long documents
Cons
  • Filler words still count as much as rare ones

TF-IDF (this lesson)

Pros
  • Rewards rare, meaningful words
  • Standard baseline; index built once; fast queries
Cons
  • Matches exact words only (no synonyms, no meaning)
  • Repeated words keep raising the score without limit

Remove stop words up front

Not covered in the lesson. IDF already shrinks the weight of very common words.

Pros
  • Smaller index
Cons
  • Can break phrases or queries where small words matter

BM25 (next lesson)

Pros
  • Refines TF-IDF and is the common production choice
Cons
  • Adds tunable parameters to understand

Key takeaways

  • Keyword search retrieves documents that share words with the prompt; more shared words means more likely relevant.
  • Text becomes a bag of words stored as a sparse vector; all document vectors form a term-document matrix (inverted index) built once before searching.
  • Scoring evolves: simple presence → term frequency → length-normalized TF → TF-IDF, each fixing the previous flaw.
  • IDF = log(total docs / docs containing the word): rare words (pizza, 1.30) weigh more than common ones (the, 0).
  • TF-IDF is the standard keyword baseline; production systems use the refined BM25.
