Evaluating Retrieval

Precision, recall, top-k, MAP and MRR: how to tell whether your retriever is actually finding relevant documents.

Why: you can measure a retriever on latency, throughput and resource usage, but what ultimately matters is search quality: is it finding relevant documents?

1 · The three ingredients

① The prompt
A retriever may do well on one prompt and poorly on another, so you test many.
② The ranked list
The documents the retriever returned for that prompt, in order.
③ Ground truth
The list of all truly relevant docs in the knowledge base. To grade the retriever you must know the right answers.

2 · Precision vs recall

Precision = relevant retrieved ÷ total retrieved
Penalizes returning irrelevant docs. “How trustworthy are the results?”
Recall = relevant retrieved ÷ total relevant in the knowledge base
Penalizes leaving out relevant docs. “How comprehensive is the retriever?”
Your question: “only 10 relevant docs exist, so how can it retrieve 12?”
Retrieved and relevant are different sets. The retriever doesn’t know which docs are relevant; it just returns its top results, and some of them are wrong. Retrieved = 12 docs: 8 relevant (hits) + 4 irrelevant (noise). The knowledge base has 10 relevant docs in total, so 2 relevant docs were missed. The 10 is the size of the relevant pool, not a cap on how many docs can be returned. Retrieved can be anything from 0 up to the whole knowledge base.
Precision = 8/12 (how many of the 12 returned were good). Recall = 8/10 (how many of the 10 good ones were found).

Real-life scenario

A support bot has 10 true answers about “refund policy”. If it returns 15 articles and 9 are right, agents have to wade through 6 distractors (precision 60%), but they’re rarely missing the key article (recall 90%). Legal-style search favors recall (don’t miss anything); a bot that stuffs the top 3 docs into an LLM prompt favors precision (noise hurts).

3 · Top-k: metrics depend on how many docs you look at

Metrics change with the number of docs returned, so they’re quoted @K: only the K highest-ranked docs count. Top-1/Top-5 is stricter; top-5 to top-15 is the commonly used range.

4 · Average precision & MAP@K

MAP gives a holistic view and rewards ranking relevant docs high. Start with average precision (AP) for one prompt:

RankItemPrecision@rankCounted?
1relevant1/1 = 1.0✔
2–1/2 = 0.5skip
3–1/3 ≈ 0.3skip
4relevant2/4 = 0.5✔
5relevant3/5 = 0.6✔
6–3/6 = 0.5skip
  1. Sum the precisions on relevant rows only: 1 + 0.5 + 0.6 = 2.1
  2. Divide by the number of relevant docs retrieved in the top K (3): 2.1 / 3 = 0.7 → AP@6
  3. MAP = average the AP across many prompts → the AP of a “typical” prompt.

Why it rewards good ranking: an irrelevant doc high in the list lowers the precision at the rank of every relevant doc below it, dragging the average down. High MAP ⇒ the retriever puts the relevant docs it finds near the top.

Note (my addition): the lecture divides by relevant docs retrieved in the top K. Many libraries instead divide by min(K, total relevant) or total relevant, so values can differ between tools.

5 · Reciprocal rank & MRR

Reciprocal Rank = 1 / (rank of first relevant doc)

Rank 1 → 1.0 · rank 2 → 0.5 · rank 4 → 0.25. The later the first relevant doc appears, the worse the score. MRR averages over many prompts and shows how soon, on average, you hit something relevant. It stresses having at least one relevant doc as high as possible.

MRR calculator (slide: ranks 1, 3, 6, 2)

The slide rounds 1/3 → 0.33 and 1/6 → 0.17, giving a sum of 2.0; exact arithmetic gives 1 + 0.3333 + 0.1667 + 0.5 = 2.0 → MRR = 0.5.

6 · Which metric when?

MetricAnswersUse it for
Recall / Recall@KDid we find the relevant docs?Most foundational and most cited; the retriever’s core goal
Precision & MAPAre irrelevant docs sneaking in? How well are results ranked?Build on recall: noise and ranking quality
MRRHow soon is the first good result?Specialized: performance at the very top of the ranking
Practical loop: change a setting (e.g. the semantic-vs-keyword weight in hybrid search), re-run a set of sample prompts, and watch recall/precision to see if it helped. Works in development and production monitoring.
Downside: every metric needs ground-truth relevant docs for a collection of sample prompts, a time-consuming, manual job (e.g. “hand marked” in the lecture).

7 · Python sketch (mine, not from the lecture)

def precision_at_k(ranked, relevant, k):
    return sum(d in relevant for d in ranked[:k]) / k

def recall_at_k(ranked, relevant, k):
    return sum(d in relevant for d in ranked[:k]) / len(relevant)

def average_precision(ranked, relevant, k):
    hits, total = 0, 0.0
    for i, d in enumerate(ranked[:k], start=1):
        if d in relevant:
            hits += 1
            total += hits / i          # precision at this rank
    return total / hits if hits else 0.0   # lecture's denominator

def reciprocal_rank(ranked, relevant):
    for i, d in enumerate(ranked, start=1):
        if d in relevant:
            return 1 / i
    return 0.0

# MAP / MRR = mean of AP / RR over all test prompts

Takeaways

  • Need prompt + ranked list + ground-truth relevant docs.
  • Precision = hits ÷ retrieved; recall = hits ÷ all relevant. Retrieved can exceed total relevant because some retrieved docs are irrelevant.
  • Quote metrics @K (top-5 to top-15 is typical).
  • AP/MAP reward putting relevant docs high; RR/MRR focus on the first relevant doc.
  • Recall first, then precision/MAP, MRR for the top of the list. All need labelled data.
