Hybrid Search

Metadata filtering + keyword search + semantic search, combined with Reciprocal Rank Fusion (RRF) and a beta weight.

One-line idea: run keyword and semantic search in parallel, filter both lists with metadata, then merge the two rankings into one using RRF, tuned by k and beta.

1 · Quick review: three techniques, three strengths

Metadata filtering

Rigid criteria stored in document metadata narrow the results. Fast, easy to implement, easy to interpret.

Gives you: a strict yes/no gate neither other technique can provide.
Weakness: not a good search technique on its own.

Keyword search

Scores and ranks documents by sharing the prompt’s keywords. Fast and easy; can find relevant documents very well.

Gives you: exact matches, great for technical terms and product names.
Weakness: exact words only; misses same-meaning-different-words.

Semantic search

Prompt and documents are embedded as vectors; the closest vector to the prompt wins.

Gives you: flexible, meaning-based matching nothing else can do.
Weakness: slower and more computationally intensive.

Both searches return about 50 documents; many appear in both lists, but in a different order. The filter leaves e.g. 35 (keyword) and 30 (semantic). The filter runs on each list before the merge.

3 · Reciprocal Rank Fusion (RRF)

RRF is the commonly used algorithm for combining the two ranked lists. It rewards documents for ranking highly on either list, and lets you control keyword-vs-semantic weight.

score(d) = Σ 1 / (k + ranki(d))

sum over every ranked list i (here just two: keyword rank and semantic rank)

  • With k = 0: 1st place = 1 pt, 2nd = 0.5, 3rd ≈ 0.33 …
  • Points from each list are added; totals produce the final ranking.
  • Example (slide): keyword rank 2nd + semantic rank 10th → 1/2 + 1/10 = 0.5 + 0.1 = 0.6.

Mini calculator

What k does: controlling the top ranks’ impact

k = 0
1st scores 1 pt, 10th scores 0.1 pt → 10× difference. A top-ranked doc on even one list shoots to the top of the overall ranking.
k = 50
1st scores 1/51 (slide shows 1/50 as shorthand), 10th scores 1/60 → about 1.2× difference. Still pays to be first, but a single high rank doesn’t dominate.
Key limitation: RRF only looks at ranks, not scores. If the top document scored far better than the second, that gap is thrown away.

4 · Beta: weighting semantic vs keyword

A retriever’s hybrid search usually adds a second hyperparameter, beta, to weight the two rankings.

  • β = 0.8 → 80% semantic, 20% keyword. β = 0.7 → 70/30.
  • 70/30 (semantic/keyword) is a typical starting point; tune it for your system.
  • Exact word matching matters (SKUs, error codes, legal terms)? Weight keyword more, i.e. lower beta.
  • Meaning matters more, keywords less crucial? Weight semantic more, i.e. higher beta.
The lecture doesn’t give the exact formula for combining beta with RRF. The common implementation, and what the demo below uses (my inference), is: score = β·1/(k+ranksem) + (1−β)·1/(k+rankkw).

7 · Python sketch (my own, not from the lesson)

def rrf(kw_ranked, sem_ranked, k=0, beta=None):
    """kw_ranked / sem_ranked: lists of doc ids, best first."""
    scores = {}
    for rank, d in enumerate(kw_ranked, start=1):
        w = 1.0 if beta is None else (1 - beta)
        scores[d] = scores.get(d, 0) + w / (k + rank)
    for rank, d in enumerate(sem_ranked, start=1):
        w = 1.0 if beta is None else beta
        scores[d] = scores.get(d, 0) + w / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)

def hybrid(prompt, top_k=5, k=0, beta=0.7):
    kw  = [d for d in bm25_search(prompt, 50)  if passes_filter(d)]
    sem = [d for d in vector_search(prompt, 50) if passes_filter(d)]
    return rrf(kw, sem, k=k, beta=beta)[:top_k]

Note the filter is applied to each list first, so ranks are positions in the filtered lists. A doc missing from one list simply gets 0 from it.

8 · Alternatives & trade-offs

Single technique onlySimplest system.Keyword misses synonyms; semantic can miss exact IDs/terms.

Takeaways

  • Hybrid = keyword + semantic in parallel → metadata filter each list → fuse → top_k.
  • RRF score = Σ 1/(k + rank); only ranks matter, not scores.
  • Small k lets top ranks dominate; larger k (e.g. 50) flattens it (10× → ~1.2×).
  • β weights semantic vs keyword; 70/30 is a typical start; lower β when exact words matter.
  • Everything is tunable, but tuning needs measurement → retrieval metrics next.
