Semantic search: matching meaning, not words

Keyword search counts words. Semantic search places text at points in space so that similar meanings land close together, then ranks documents by how close they are to the prompt.

The problem it solves

Semantic search matches documents to prompts based on shared meaning and captures nuances keyword search misses.

Real-life scenario: a support bot gets “my laptop won’t turn on”. The help article is titled “Device fails to power up”. No shared keywords, but a semantic search can still find it.

Same skeleton as keyword search

At a high level it works just like keyword search: every document and the prompt each get a vector, the vectors are compared to produce scores, and the closest matches win. The only difference is how the vectors are assigned.

Embedding models: words become locations

An embedding model maps text to a location in space, represented by a vector. In two dimensions you can draw these as points on an x-y plane.

Example from the lesson

“pizza” → vector [3, 1]“bear” → vector [5, 2]

These particular numbers are only illustrative.

The “magic” part: semantically similar words map to nearby locations. food and cuisine land close together; trombone and cat land far apart. Similar meanings lead to similar positions.

Measuring “closeness” between vectors

To quantify similarity of two texts, measure the distance between their vectors. There are a few ways.

Euclidean distance

Straight-line distance between two vectors: the shortest possible path. Essentially the Pythagorean theorem scaled to more dimensions.

Smaller = closer. Caveat: in very high-dimensional space every point tends to be pretty far from every other point.

Cosine similarity

Compares the direction of two vectors, even if they’re not close in space. [10, 10] and [100, 100] aren’t near each other but face the same way.

-1opposite
0perpendicular
1same direction
Most commonly used measure. Higher = closer.

Dot product

Length of the projection of one vector onto another. Similar length and direction gives a larger value.

negativeopposite
090 degrees
positivesame direction
Range: negative to positive infinity. Higher = closer. Seen occasionally.

Not a math person? Fine. You’ll likely never implement these yourself, but know that for cosine similarity and dot product higher values mean closer vectors, hence more similar concepts. Cosine ranges from -1 to 1; dot product has no fixed bounds.

How semantic search runs

Embed documentsThe embedding model projects every document into vector space. Similar meaning sits closer together.
Embed the promptThe prompt gets a vector of its own.
Measure distanceCompare the prompt vector to each document vector.
Rank and returnSort by distance and return the closest documents.

Closest documents have the most similar meaning, provided the embedding model works properly. How the model learns to place similar concepts together is the next lesson.

The three measures in code

Plain NumPy, for understanding. Producing the vectors needs an embedding model (placeholder embed below).

import numpy as np

def euclidean(a, b):
    return np.linalg.norm(a - b)                       # smaller = closer

def dot(a, b):
    return np.dot(a, b)                                # higher = closer

def cosine(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))   # -1 to 1

# docs_vecs = [embed(d) for d in documents]            # embed() = your embedding model
# q = embed(prompt)
# ranked = sorted(zip(documents, docs_vecs),
#                 key=lambda p: cosine(q, p[1]), reverse=True)

print(cosine(np.array([10, 10]), np.array([100, 100])))   # 1.0 (same direction)
print(euclidean(np.array([10, 10]), np.array([100, 100])))  # ~127.3 (far apart)

Extra tip (not in the lesson): if your embedding vectors are normalized to unit length, cosine similarity and dot product give the same ranking. For the actual embedding call, use your provider’s current embeddings documentation; client libraries and model names change quickly.

Alternatives and trade-offs

Cosine similarity (common default)

Pros
  • Focuses on direction, so meaning rather than size
  • Bounded -1 to 1, easy to read
Cons
  • Ignores vector length (rarely a problem)

Dot product

Pros
  • Simple and fast to compute
Cons
  • Unbounded, and sensitive to vector length

Euclidean distance

Pros
  • Intuitive: straight-line distance
Cons
  • Everything tends to look far apart in very high dimensions

Semantic search only

Pros
  • Handles synonyms and paraphrases
Cons
  • Slower, more computationally expensive
  • Exact product names or codes can be missed, so pair with keyword search (hybrid)

Word vs sentence vs document embeddings

Pros
  • Pick the unit that matches what you’re searching
Cons
  • One vector for a long document can blur its details, so chunk size matters

Key takeaways

  • Semantic search matches by meaning: it handles synonyms (happy/glad) and avoids same-word confusions (Python the language vs the snake).
  • Same skeleton as keyword search; the difference is that vectors come from an embedding model instead of word counts.
  • Similar meanings map to nearby locations. Axes have no simple meaning; real vectors have 100 to 1,000+ dimensions.
  • Embedding models exist for words, sentences and documents, each outputting one vector.
  • Measure closeness with cosine similarity (most common, -1 to 1), dot product (unbounded) or Euclidean distance. For cosine and dot, higher means closer.
  • Pipeline: embed documents, embed prompt, measure distances, rank, return closest.
