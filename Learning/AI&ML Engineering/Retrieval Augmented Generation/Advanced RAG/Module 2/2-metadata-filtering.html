RAG, Module 2 Information retrieval foundations Lesson: metadata filtering

Metadata filtering: the strict gatekeeper

The simplest and most familiar technique in a retriever. It uses rigid criteria on a document’s metadata to narrow down results. It doesn’t find relevant documents; it decides which documents are allowed through.

What it is

Metadata is information about a document rather than its text: title, author, creation date, access privileges, and so forth. A metadata filter keeps only the documents that satisfy rigid conditions on those fields.

Newspaper example

You work at a newspaper and want a retriever for articles from the paper’s whole history. The knowledge base holds thousands of articles. The full text lives in the knowledge base, but this index can only be searched through each article’s metadata.

How querying looks: like a SQL query

Filter on one field, or combine several. Only documents that meet every condition come back; everything else is filtered out.

Single condition

Every article published on a given day (or by a particular author):

SELECT * FROM articles
WHERE publication_date = '2023-10-01';

Multiple conditions

Opinion pieces by your favorite journalist between June and July 2024:

section = “Opinion”
author = “Michael Chen”
date = June to July 2024

All three must be true for an article to be returned.

Analogy: if you’ve ever filtered a table in a spreadsheet, you’ve already done metadata filtering. You apply a strict set of criteria to pick which members of a larger collection you want to use.

How it’s used inside a RAG system

In a typical RAG system you don’t use metadata filtering to perform retrieval. You use it to narrow down results returned by other retrieval techniques (keyword and semantic search). And the filters usually aren’t decided by what the user said in the prompt, but by other attributes of the user making the request.

Subscription filtering

Some articles are free on the open internet; others are for paid subscribers only. Each article stores a free/paid flag.

×User not signed in as a paid subscriber: exclude subscription = paid

Geographic filtering

The paper prints in many regions. Each article stores the region where it was published. The system detects where the reader is.

✓Include only region = North America for a reader in North America

Real-world mapping: in a company assistant the same pattern enforces access privileges: an Engineering user never gets HR-only documents, even if they’d match the question perfectly.

Advantages and limitations

Advantages

  1. Conceptually simple. Easy to understand how the system works and to debug problems.
  2. Fast, mature, well-optimized. A reliable approach with years of engineering behind it.
  3. The only way to enforce rigid criteria. If you must strictly define which documents can or can’t be retrieved, metadata filtering is the only approach that gives you that behavior. Most important of the three.

Limitations

  1. Not really a search technique. It’s a tool for refining results from the other two techniques in this module.
  2. Overly rigid, ignores content. It never looks at what a document says.
  3. No ranking. Once documents pass the filter there’s no way to order them.
  4. Useless alone. A retriever relying only on metadata filtering would be essentially useless.

Bottom line: RAG systems you build will very likely include metadata filters, but they need pairing with other techniques that can tell whether a document’s contents are relevant to the prompt.

Alternative approaches and trade-offs

Filters from user attributes (this lesson)

Pros
  • Predictable and easy to debug
  • Enforces access rules reliably
Cons
  • Can’t react to what the prompt asks for

Filters extracted from the prompt

For example, an LLM turns “opinion pieces from last summer” into section and date conditions. Not covered in this lesson.

Pros
  • Lets users narrow results in natural language
Cons
  • Mistakes silently drop good documents
  • Not safe for access control

Filter before vs after search

Pros of filtering search results afterward
  • Simple to add to any retriever
Cons
  • Lists shrink (e.g. 50 to 35); filtering first can avoid that if your database supports it

Key takeaways

  • Metadata filtering applies rigid criteria to fields like title, author, date, section, and access privileges. Only documents meeting every condition survive.
  • It looks like a SQL query or a spreadsheet filter.
  • In RAG it narrows results from other techniques; the filters come from user attributes (subscription, region), not the prompt.
  • Strengths: simple, fast, mature, and the only way to enforce strict rules.
  • Limits: not true search, ignores content, no ranking, useless on its own.
  • Up next: keyword search, which adds the ability to judge whether a document’s contents match the prompt.
