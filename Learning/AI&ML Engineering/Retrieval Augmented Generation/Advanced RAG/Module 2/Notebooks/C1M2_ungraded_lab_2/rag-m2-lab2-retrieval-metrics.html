0 · The lab at a glance

Goal: measure how good a semantic retriever is, using Precision@K and Recall@K, on a labeled dataset.

20 Newsgroups
11,314 posts, 20 categories→ Pre-computed embeddings
embeddings.joblib (11,314 vectors)→ Embed the query
BAAI/bge-base-en-v1.5→ Cosine similarity vs all docs→ Top-K→ Precision@K / Recall@K

How “relevant” is defined here: a retrieved post counts as relevant if its newsgroup category equals the category you expect for the query (e.g. query “advancements in space exploration technology” → sci.space). That’s the lab’s ground truth.

Data: the posts were embedded ahead of time to save time; the model is only used to embed the queries.

2 · Your questions about cosine_similarity

def cosine_similarity(v1, array_of_vectors):
    if hasattr(v1, "detach"):                      # torch tensor?
        v1 = v1.detach().cpu().numpy()
    v1 = np.asarray(v1, dtype=np.float32).ravel()

    if hasattr(array_of_vectors, "detach"):
        array_of_vectors = array_of_vectors.detach().cpu().numpy()
    A = np.asarray(array_of_vectors, dtype=np.float32)

    if A.ndim == 1:                                # single vector case
        A = A.ravel()
        denom = np.linalg.norm(v1) * np.linalg.norm(A)
        return float(0.0 if denom == 0 else np.dot(v1, A) / denom)

    # 2D case: one similarity per row of A
    A = np.atleast_2d(A)
    v1_norm = np.linalg.norm(v1)
    A_norms = np.linalg.norm(A, axis=1)
    denom = v1_norm * A_norms
    with np.errstate(divide='ignore', invalid='ignore'):
        sims = (A @ v1) / np.where(denom == 0, 1.0, denom)
    sims[denom == 0] = 0.0
    return sims.tolist()

The function is written defensively: it accepts either PyTorch tensors or NumPy arrays, a single vector or a whole matrix, and never crashes on zero vectors.

2a · What are asarray, detach, cpu, and why remove/detach a tensor?

PyTorch tensor
PyTorch’s array type. It can (1) live on a GPU, and (2) remember how it was computed (an autograd “graph”) so gradients can be calculated in training.

NumPy arrays are plain CPU arrays with neither feature, so NumPy can’t read a tensor that’s on a GPU or that tracks gradients (it raises an error).
The conversion chain
x.detach() → cuts the tensor off from the autograd graph (no gradient tracking; shares the same data)
.cpu() → copies it from GPU memory to normal CPU memory (no-op if already on CPU)
.numpy() → views it as a NumPy array

hasattr(v1, "detach") is a duck-typing check: “does this object have a .detach method?” Only torch tensors do, so NumPy inputs skip the conversion.
np.asarray(x, dtype=np.float32): “make sure this is a NumPy array of 32-bit floats.” If x is already an ndarray of that dtype it returns it without copying (unlike np.array, which copies by default). If x is a list, it builds an array. float32 halves memory vs float64 and matches what the embedding model outputs.
In this lab specifically: model.encode(..., convert_to_tensor=False) already returns NumPy and the joblib embeddings are most likely NumPy too, so these branches are mostly a safety net (my inference). The comment in compute_metrics explains the motive: “avoid GPU→NumPy conversion errors”.

2b · What is ravel()?

It flattens an array into 1-D (a plain list of numbers). Returns a view of the original when possible, otherwise a copy. Why it’s used: a vector can arrive as (768,) or (1, 768) or (768, 1), and the math below needs a clean 1-D shape.

2c · What is denom? Are these length vectors?

Yes. np.linalg.norm(v) is the vector’s length (L2 norm): √(v₁² + v₂² + …). Cosine similarity divides the dot product by the product of the two lengths, so it measures the angle between vectors, not their size:

cosine(v, a) = (v · a) / ( ‖v‖ × ‖a‖ ) ← denominator = denom
  • v1_norm = one number: the length of the query vector.
  • A_norms = np.linalg.norm(A, axis=1) = one length per row of A (per document) → vector of N numbers. axis=1 means “compute across the columns of each row”.
  • denom = v1_norm * A_norms = elementwise product → N denominators, one per document.

Play with it (edit the numbers)

v1 (query):
Rows of A (documents). Row 4 is all zeros on purpose to show the zero-vector guard.
  • np.atleast_2d(A): guarantees a matrix shape (N, D). A 1-D vector of 3 numbers becomes shape (1, 3).
  • A @ v1: matrix-vector product = dot product of every row with v1 → N numbers at once (no Python loop).
  • np.where(denom == 0, 1.0, denom): wherever the denominator is 0, substitute 1.0 so the division can’t blow up (0/0 = NaN, x/0 = inf).
  • np.errstate(...): silences NumPy’s divide/invalid warnings. Because of the np.where trick it’s likely redundant (my reading), just belt-and-braces.
  • sims[denom == 0] = 0.0: for zero vectors (undefined angle) the score is forced to 0 instead of the fake value produced by dividing by 1.0.
  • .tolist(): converts the NumPy array into a plain Python list of floats, which top_k_greatest_indices then sorts.

3 · top_k_greatest_indices and the sorted(...lambda...) line

indexed_list = list(enumerate(lst))
sorted_by_value = sorted(indexed_list, key=lambda x: x[1], reverse=True)
top_k_indices = [index for index, value in sorted_by_value[:k]]
1. enumerate
Pairs every score with its position (doc id): [0.2, 0.9] → [(0, 0.2), (1, 0.9)]. Needed because sorting would otherwise lose which doc each score belonged to.
2. sorted(..., key=lambda x: x[1], reverse=True)
x is one pair (index, score). lambda x: x[1] is a tiny unnamed function returning the score (item at position 1). key= tells sorted “compare by this”. reverse=True = highest first.
3. slice + list comprehension
[:k] keeps the first k pairs; the comprehension unpacks each pair and keeps only the index. Result: doc ids of the k best matches.

4 · retrieve_documents with an example

def retrieve_documents(query, embeddings, model, top_k=5):
    query_clean = preprocess_text(query)
    query_embedding = model.encode(query_clean, convert_to_tensor=False).astype(np.float32)

    cosine_scores = []
    for x in embeddings:                         # one doc vector at a time
        if hasattr(x, "detach"): x = x.detach().cpu().numpy()
        x = np.asarray(x, dtype=np.float32)
        score = cosine_similarity(query_embedding, x)   # 1-D branch -> float
        cosine_scores.append(float(score))

    top_results = top_k_greatest_indices(cosine_scores, k=top_k)

    print(f"Query: {query}")
    for idx in top_results:
        print(f"Document: {df.iloc[idx]['text'][:200]}...")
        print(f"Category: {newsgroups_train.target_names[df.iloc[idx]['category']]}...")

5 · Precision@K and Recall@K functions

precision_at_k(relevant_count, k)
Guard: negative inputs → ValueError; k == 0 → returns 0.0 (avoids divide-by-zero). Otherwise relevant_count / k.
recall_at_k(relevant_count, total_relevant)
Same guards. Returns relevant_count / total_relevant, where the denominator is the number of relevant docs in the whole corpus (not just the top K).
Same numerator (relevant docs in the top K), different denominators: K for precision, all relevant docs for recall.

Results from the lab (K = 5, 20, 50)

How to read the results

Precision falls as K grows
At K=5, 8 of 10 queries hit 1.00. By K=50 the harder ones sag: electronics 0.66, politics 0.52, Windows 0.60. More docs ⇒ more chances for off-topic ones.
Recall looks tiny, and that’s expected
The “relevant set” is a whole category (the lab says 500–600 docs). Even a perfect top-5 gives about 5/600 ≈ 0.01, and K=50 caps near 0.08. Recall can’t get high until K is in the hundreds.
Why some queries are weaker
“historical influence of politics on society” → talk.politics.misc overlaps heavily with sibling politics groups, so semantically-correct docs get labelled “wrong” (my interpretation; the lab calls it ambiguous).
Caveat on the labels
“Relevant = same category” is a proxy. A sci.space post may not actually answer the query, and a post from another group might. Real evaluation sets label relevance per query.

Takeaways

  • Tensor → NumPy needs detach().cpu().numpy(); np.asarray normalizes type/dtype; ravel() flattens to 1-D.
  • denom = product of vector lengths; one per document in the 2-D case; zero vectors are guarded to score 0.
  • A @ v1 scores every document at once; sorting scores with their indices yields the top-K doc ids.
  • compute_metrics: embed query → score all docs → top-K → map to categories → count matches → P = hits/K, R = hits/category size.
  • Precision drops and recall rises with K; with category-sized relevant sets, recall stays low.
