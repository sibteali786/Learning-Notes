Horizontal Partitioning vs Sharding

Same idea — split a big table into smaller pieces — but where those pieces live is what makes them different.

The Core Difference

Horizontal Partitioning

  • Splits a big table into pieces that stay in the same database
  • Each piece becomes a different table (or schema) — e.g. customers_west, customers_east
  • The client now needs to know which table/schema to query
  • Still one server to manage and connect to

Sharding

  • Splits a big table across multiple database servers/instances
  • Table name and schema stay exactly the same everywhere
  • The client needs to know which server to connect to
  • Multiple independent servers, each with its own resources

Visually

Both techniques exist to spread out a big table's data — the axis they split on is the only difference: table/schema for horizontal partitioning, server for sharding.
