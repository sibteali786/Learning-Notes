Sharding Setup — Docker + Postgres + pgAdmin

Spinning up 3 identical Postgres shards, wiring pgAdmin to manage them, and every real error hit along the way.
The Plan Schema & Dockerfile Build & Run Debugging Log Networking Fix

The Plan

Spin up 3 identical Postgres instances for the URL-shortener example — one for each shard — then build a NodeJS/Express REST API on top that decides which shard to hit.

Matches the slide: "Spin up 3 postgres instances with identical schema — 5432, 5433, 5434 — write to the sharded databases, read from the sharded databases."

Schema & Dockerfile

Every shard needs the same table created automatically on first boot, so the init SQL is copied into Postgres's special init folder.

init.sql

create table url_table (
  id serial not null primary key,
  URL text,
  URL_ID character(5)
)

Dockerfile

FROM postgres
COPY init.sql /docker-entrypoint-initdb.d

Anything placed in /docker-entrypoint-initdb.d runs automatically the first time the container initializes its database — the filename doesn't have to be init.sql.

Build & Run

Build one custom image, then spin up 3 containers from it — one per shard port:

// build the custom image (init.sql baked in)
docker build -t pgshard .

// spin up the 3 shards — modern Postgres images require a password
docker run --name shard1 -p 5432:5432 -e POSTGRES_PASSWORD=postgres -d pgshard
docker run --name shard2 -p 5433:5432 -e POSTGRES_PASSWORD=postgres -d pgshard
docker run --name shard3 -p 5434:5432 -e POSTGRES_PASSWORD=postgres -d pgshard

// spin up pgAdmin to browse all 3 shards
docker run -e PGADMIN_DEFAULT_EMAIL="sibteali786@gmail.com" \
           -e PGADMIN_DEFAULT_PASSWORD="password" \
           -p 5555:80 --name pgadmin -d dpage/pgadmin4
Updated from the original video

The original commands (docker run --name shard1 -p 5432:5432 pgshard, with a random pgAdmin email) no longer work as-is on current Postgres/pgAdmin images: a real POSTGRES_PASSWORD is required at container start, and pgAdmin now validates the email format — it must be a real-looking address, not a placeholder string.

Once all 4 containers are up, add 3 servers in pgAdmin (host = machine IP or container name, ports 5432/5433/5434, user/db default to postgres) — each should show the same url_table schema, empty.

Debugging Log — What Actually Broke

01docker build failed
MistakeFile was named DockerFile (capital F) instead of Dockerfile — Docker's default build only looks for the exact lowercase name.
Fixmv DockerFile Dockerfile, then docker build -t pgshard . succeeded.
02"address already in use" on port 5433
MistakeAssumed the port was free — a local (non-Docker) Postgres was already listening on 127.0.0.1:5433.
Diagnosisss -ltnp | grep 5433 → sudo lsof -i :5433 -sTCP:LISTEN -P -n → found local postgres PID 1839.
FixThat local service only bound to 127.0.0.1, so 0.0.0.0:5433 was still free for Docker — confirmed and reused the port, no real change needed.
03"Conflict, name already in use"
MistakeReused a container name (pgshard2) that already existed in Created/Exited state instead of removing it first.
Fixdocker rm pgshard2 before re-running.
04Containers exiting immediately — "superuser password is not specified"
Root causeThe base postgres image requires POSTGRES_PASSWORD (or POSTGRES_HOST_AUTH_METHOD=trust) on every fresh container start. This check runs at container-start time, not build time — hit repeatedly across shard1, shard2, and shard3.
Fixdocker rm <name>, then docker run --name <name> -p <hostport>:5432 -e POSTGRES_PASSWORD=postgres -d pgshard.
05init.sql failing during container init
MistakeTrailing comma in CREATE TABLE (URL_ID character(5),) — invalid SQL syntax.
FixRemoved the trailing comma, then rebuilt the image (docker build -t pgshard .) since init.sql is copied in at build time, and recreated the container.
06pgAdmin: curly quotes in -e values
Mistake"hussein" used smart/curly quotes (from copy-paste or terminal autocorrect) instead of straight ", breaking both shell quoting and email validation.
FixRetyped with straight double quotes: -e PGADMIN_DEFAULT_EMAIL="sibteali786@gmail.com".
07pgAdmin couldn't connect to localhost:5432
MistakeAssumed localhost inside the pgAdmin container refers to the host machine — it doesn't. Each container has its own network namespace, so localhost there is pgAdmin itself.
Also failedhost.docker.internal — that hostname is a Docker Desktop convenience, not available on plain Docker Engine on Linux.
Real fixPut pgAdmin and all 3 Postgres containers on a shared user-defined network, then connect using container names (see below).

The Networking Fix

docker network create pgnet
docker network connect pgnet pgadmin
docker network connect pgnet pgshard1
docker network connect pgnet pgshard2
docker network connect pgnet pgshard3

Then in pgAdmin, set host = pgshard1 (etc.) and port = 5432 — the container's internal port, not the host-mapped one.

Key concept

Host-mapped ports (5432 / 5433 / 5434) are for reaching containers from the host machine. Container-to-container traffic on a shared Docker network uses container names + the container's internal port (always 5432 for Postgres) — a separate, non-conflicting namespace from the host ports.
