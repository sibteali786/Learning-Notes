⚙️ Automating Partitions with Node.js

Community Q&A: dynamically generating 100 partitions instead of typing them by hand

The question

From the intro-to-database-engineering course: if you have a huge customers table and want to partition by ID, manually typing out dozens (or hundreds) of CREATE TABLE + ATTACH PARTITION statements gets tedious fast. This is a scripted solution — written in Node.js/JavaScript for readability, though the same logic works in any language, including PL/pgSQL.

The plan

  • Target scale: 1 billion customers (simplified from Postgres integer's real max of ~4 billion, i.e. 2³²)
  • Each partition holds 10 million rows
  • Result: 1,000,000,000 ÷ 10,000,000 = 100 partitions
1B customers
÷ 10M each →
100 partitions

Setup Spin up Postgres (port exposed this time)

docker run --name pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres

Unlike the earlier demo, the port is exposed here (-p 5432:5432) since the Node.js script connects from outside the container.

Script 1: create_partitions.mjs

1
Connect to Postgres, create a fresh customers database (drop-and-recreate is commented out by default — a safety measure so you don't accidentally wipe a real database).
⚠️ The drop database line is intentionally commented out in the shared script. Only uncomment it if you're sure you want to wipe an existing database — running this against a real database with existing customer data is destructive.
2
Connect to the new customers database and create the partitioned table — same pattern as the manual demo, just parameterized.
const sql = `create table customers (id serial, name text)
             partition by range (id)`;
await dbClientCustomers.query(sql);
3
Loop 100 times, computing each partition's ID range and generating the same two SQL statements used manually before — CREATE TABLE ... (LIKE ... INCLUDING INDEXES) and ATTACH PARTITION.
for (let i = 0; i < 100; i++) {
    const idFrom = i * 10000000;
    const idTo = (i + 1) * 10000000;
    const partitionName = `customers_${idFrom}_${idTo}`;

    const psql1 = `create table ${partitionName}
                     (like customers including indexes)`;

    const psql2 = `alter table customers
        attach partition ${partitionName}
        for values from (${idFrom}) to (${idTo})`;

    await dbClientCustomers.query(psql1);
    await dbClientCustomers.query(psql2);
}
🐛 Gotcha learned the hard way: the upper bound (idTo) in a Postgres range partition is exclusive. A range FOR VALUES FROM (0) TO (10000000) actually covers IDs 0 through 9,999,999 — not up to 10,000,000. Off-by-one errors here will bite you.
4
Close both connections when done.
// run it:
npm install   // installs the 'pg' library
node create_partitions.mjs

Script 2: populate_customers.mjs

Run after partitions exist. Inserts 10 million random-named customers per loop iteration, 100 times — 1 billion rows total (the demo only waits through a couple of iterations rather than the full run).

for (let i = 0; i < 100; i++) {
    const psql = `insert into customers(name) (
                    select random() from generate_series(1,10000000)
                    )`;
    await dbClientCustomers.query(psql);
}

Notice the insert only ever targets the single logical customers table — you never insert into a specific partition directly. Postgres automatically routes each row to the correct partition based on its generated id.

Verifying the result

docker exec -it pg psql -U postgres -d customers
select max(id) from customers;
-- shows highest inserted ID so far

\d customers            -- shows table + "Number of partitions: 100"
\d+ customers            -- lists all 100 partitions in detail

select count(*) from customers_0_10000000;
-- query any individual partition like a normal table
💡 Takeaway: once partitions are attached, they behave like completely ordinary tables — you can query them directly by name, or just query the parent customers table and let Postgres route/prune automatically.

Summary
