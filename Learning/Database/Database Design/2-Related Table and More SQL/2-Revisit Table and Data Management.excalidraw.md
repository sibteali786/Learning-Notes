What does the CONSTRAINT…FOREIGN KEY…REFERENCES… clause do? ^wGIUVrgq

In short, the clause creates a foreign key constraint, which serves as a link between two related tables. The constraint is twofold:
- The constraint ensures that the foreign key column in the child table references only valid primary key values in the parent table.
- The constraint ensures that the updating or deletion of rows in the parent table doesn’t violate the consistency between two related tables. ^SQ3CdsVM

- These two are reffered as Referential Integrity.
- The CONSTRAINT…FOREIGN KEY…REFERENCES… clause enforces referential integrity between two related tables. ^4Xk2fotf

Part 1 ^SWXGo1KX

The FOREIGN KEY…REFERENCES… statement creates the foreign key constraint that enforces referential integrity ^HgW0Qaai

Part 2 ^voeRBfMr

The CONSTRAINT… clause allows you to name this constraint ^GOpFFNbv

When you create a foreign key constraint, you don’t necessarily need to name it, but naming it will make it easy to access whenever you need to modify such a constraint in the future. We named the foreign key constraint fk_product_review in the review table, for example. If we ever need to drop this constraint, we can access the constraint via this name: ^Y3fLg9CP

-- comment: SQLite doesn't support ALTER TABLE 
-- comment: DROP CONSTRAINT
ALTER TABLE review 
  DROP CONSTRAINT fk_product_review; ^e2JeMrf9

Foreign Key Constraint
What it does

- Enforces referential integrity between a parent table and a child table
- The child's foreign key column can only hold values that exist as primary keys in the parent

- Can't drop a parent table while a child table references it — else Error: cannot drop table
- To drop both: drop child first, then parent (this also removes the constraint)

Key term: Orphan data — child rows whose parent row no longer exists; the FK constraint exists to prevent this ^fdRfUAZB
