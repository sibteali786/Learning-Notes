CREATE TABLE review (
  review_id INT PRIMARY KEY,

  review_text TEXT NOT NULL,

Questions
What is the general syntax for creating two tables that have a relationship?

- The shared column product_id is primary key in the product table and foreign
key in the review table.
- Here product is Parent table becuase it uses the shared column as PRIMARY 
KEY.
- review is called the Child table as holds foreign key. ^6MgXJdyh

- The parent table syntax is similar to creating a single table 
- the child table however has some syntax smae with few difference ^A9mOtwOS

CREATE TABLE child_table_name (
  column1 datatype1 [NOT NULL],
  column2 datatype2 [NOT NULL],
  ...,
  foreign_key_column datatype,
  CONSTRAINT fk_parent_child 
    FOREIGN KEY (foreign_key_column) REFERENCES  
    parent_table_name(parent_table_primary_key)
); ^Ufdk4YDw

Alternatively, you can create the two tables independently and add the foreign key constraint to the child table afterward: ^gqP4QUQ2

-- comment: assuming the parent and child tables 
-- comment: have been created
ALTER TABLE child_table_name
  ADD CONSTRAINT fk_parent_child
    FOREIGN KEY (foreign_key_column) REFERENCES 
    parent_table_name(parent_table_primary_key); ^7wr9XwMU

What does the CONSTRAINT…FOREIGN KEY…REFERENCES… clause do? ^wGIUVrgq

In short, the clause creates a foreign key constraint, which serves as a link between two related tables. The constraint is twofold:
- The constraint ensures that the foreign key column in the child table references only valid primary key values in the parent table.
- The constraint ensures that the updating or deletion of rows in the parent table doesn’t violate the consistency between two related tables. ^SQ3CdsVM

- These two are reffered as Referential Integrity.
- The CONSTRAINT…FOREIGN KEY…REFERENCES… clause enforces referential integrity between two related tables. ^4Xk2fotf

Part 1 ^SWXGo1KX

The FOREIGN KEY…REFERENCES… statement creates the foreign key constraint that enforces referential integrity ^HgW0Qaai

Part 2 ^voeRBfMr

The CONSTRAINT… clause allows you to name this constraint ^GOpFFNbv

When you create a foreign key constraint, you don’t necessarily need to name it, but naming it will make it easy to access whenever you need to modify such a constraint in the future. We named the foreign key constraint fk_product_review in the review table, for example. If we ever need to drop this constraint, we can access the constraint via this name: ^Y3fLg9CP

-- comment: SQLite doesn't support ALTER TABLE 
-- comment: DROP CONSTRAINT
ALTER TABLE review 
  DROP CONSTRAINT fk_product_review; ^e2JeMrf9

One line advice
ALWAYS NAME YOUR CONSTRAINTS AS A BEST PRACTICE ^mCXe8WTY

RDBMS also does it automatically if we do not explicitly name it
and we can retrieve it too but it varies from one RDBMS to other ^BvlSadLI
