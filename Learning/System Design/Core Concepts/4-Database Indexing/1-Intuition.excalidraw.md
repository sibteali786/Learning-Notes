How Database Indexes Work ^sfRpr7dx

- Data is stored as heap - no particular order, like a notebook write notes as they come in  ^KcrkzYBC

Physical Storage and Access Patterns ^spJIbqjN

Unless interviewing for a database internals role, the details here are not going to be asked in an interview. That said, they are an important foundation to understand the problem of why we need indexes. ^golsHL4F

- Need to store data as well as quickly access vast amount of data 
- While we can only process data when its in memory i.e every query loads data into RAM from disk.
- without index we load each page into memory ( RAM ) and scan through it and it has to be done for millions of pages, we are reading Disk just to find a single record. ^0UdTXHHU

- Indexes help us minimize the number of pages we need to read from storage / Disk by telling us exactly which pages contain our target data
- It's the difference between checking every page in a book versus using the table of contents to jump straight to the relevant pages. ^UJyu9QPd

While SSDs are the norm today, it's important to note that random access is still significantly slower than sequential access, even on SSDs. This is a common misconception - while the performance gap is smaller than with HDDs, it's still very real. And for systems still using HDDs, especially for large datasets, this performance difference becomes even more pronounced, making proper indexing absolutely critical. ^tYRvPq7g

Cost ^96Rj1LRQ

- Indexes come at a cost 
- When ever a new record is inserted or updated the database must update not just the main table but every index on it.
- With multiple indexes a single write operation can trigger several disk writes. ^5ovmywSt

When Indexes could hurt more than help ^1Hy3frUU

- A table with frequent writes but infrequent reads like logging table.
- Small tables of few hundred rows ( here cost of maintaining index exceeds cost of simple sequential scan ) ^XFEt7XcH

In reality, the impact of indexes on memory is often overblown. Modern databases have smart buffer pool management that reduces the performance hit of having multiple indexes. However, it's still a good idea to closely monitor index usage and avoid creating unnecessary indexes that don't provide significant benefits. ^lnfXLTUf
