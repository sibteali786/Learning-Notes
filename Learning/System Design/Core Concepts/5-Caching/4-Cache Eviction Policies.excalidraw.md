## Text Elements
Cache Eviction Policies ^qmeRAO8X

- Eviction Policies decide what to keep and what to remove when new data comes in.
- Why ? because caches have limited memory and become full faster relatively. ^ZV9VCtPP

LRU Cache ( Least Recently Used ) ^oezYkxBs

- As name suggests : remove items that are not used recently.
- track access order using linked list or ring buffer so least recently used can be removed in constant time.


Default for most systems : because it adapts well to most workloads where recently used data is likely to be used again. ^77MMn40H

- evict items : which are least used.
- tracks counter and removes ones with lowest frequency.

- Works well when certain keys are consistently popular over time

Example 
if trending videos or top playlists stay popular across hours or days, LFU usually does a better job keeping those hot items in cache. ^pgLTaZiA

LFU (Least Frequently Used) ^T30snTyZ

- evicts oldest item in the cache based only on insertion time.
- Can be implemented with simple queue but ignores usage patterns

- May evict items that are still hot, rarely used in real systems beyond simple caching layers ^W9zgNpzk

FIFO (First In First Out) ^xwfDn9tW

TTL (Time To Live) ^XKn7JLUm

- TTL is not an eviction policy by itself.
- Sets an expiration time for each key and removes entries that are too old

- Often combined with LRU or LFU to balance freshness and memory usage

TTL is a must have when data must eventually refresh, like API responses or session tokens. ^IJnFaQ6S
