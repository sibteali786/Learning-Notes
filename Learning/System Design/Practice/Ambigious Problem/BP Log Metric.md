Availability vs Consistency: Your reasoning ("app goes down while logging = bad") is actually about durability/uptime, not the CAP tradeoff. CAP applies when you have distributed nodes and a network partition — e.g., you write a BP reading on mobile, it syncs to a backend, and web tries to read it 2 seconds later from a different replica. Do they need to see the exact same value instantly (consistency) or is "eventually shows up" fine (availability)? For personal health logging — not collaborative — being AP (eventually consistent) is a reasonable call, but the justification should be "no simultaneous conflicting writes, single source of truth per user, eventual sync is fine for read-your-own-data" rather than "avoid downtime."

SSE for mobile — worth reconsidering. SSE holds an HTTP connection open, which mobile OSes aggressively kill in the background to save battery. For "notify user something's abnormal" on mobile, native push (APNs/FCM) is the real-world standard — it works even when the app isn't open. SSE would make sense for the web app tab being open. What would you do differently knowing that?
