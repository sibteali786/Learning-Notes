1. Send only metadata to App server and use property 
like status to denote file being uploaded.
- then request for pre-signed url from Blob Storage
- it has file size limits, permissions and TTL.
 ^sPYQNukV

50 Gb @100mbs = 1hr 12 min ^1LcpSZDQ

2. Chunk Files on client to 5mb chunk
- Convert file in chunks
- send all chunks info with metadata to app server with status 'not started'
- then we start uploading chunk either parallel or seqential
- Track the uploaded chunks and not uploaded ones to resume later


3. What if for some failure upload stops
- we try to compare chunks on client side with chunks on databases
- but its error prone since we do not know which chunk ( client ) to compare with which one
on database

we Fingerprint each chunk ( hash bytes of each chunk ) 
- this fingerprint becomes our id in database so we can compare chunks effectively

4. How to update the chunk status ? 
- send patch or PUT request to database ( app server )
- One more round trip but can cause issues like client lies, gives false info that file 
got uploaded but its not 

    To keep consistency and trust
    Trust but verify
    - S3 tells us chunk got uploaded
    - we send request to app server  and ask Blob Storage if file got uploaded
    - then only update the chunk status
    
    
    CDC in S3 is Event Notifications ( Changes Data capture )
    - Adds complexity as S3 notifies File Service this chunk is uploaded now update it
    - we update the chunk status in database
    - This is called S3 Multipart upload and is supported By S3

we can either chose Trust but Verify or we can use S3 Multipart upload. ^fTDH2HU2
