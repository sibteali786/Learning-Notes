gRPC: Efficient Service Communication ^9kWTDr8P

Why we need it ^863Q7sKI

- Its more performant than HTTP based JSON requsts since its uses binary encoding instead of JSON.
- It uses Protocol Buffers instead of JSON ^LrJfGXHP

Protocol Buffers are a compact binary data format with a strict schema that you define upfront, which makes messages smaller on the wire and faster to parse than JSON. The biggest difference is schema and encoding. JSON is human readable and flexible but verbose, while Protobuf is typed, versionable, and binary. REST is not a format at all but an API style that usually uses HTTP and often JSON. ^IZmAeKj6

Where to Use It ^yDUyXWWO

- Best for microservice architectures where services need to communicate fast and effectively.
- Where Data format is not imprtant but reaching data fast is important
- Best for Internal service communication especially when performance is 
critical.
- Moslty used to for internal service communication, REST is for Public 
APIs while gRPC for internal service to service communication ^kPWquwN1

In many interviews, using REST both for internal and external APIs is fine and you can build from there depending on the needs of the problem and probes from your interviewer. ^54oBoJFp

POINT TO REMEMBER ^zqqAo4Or

we recommend using REST for public-facing APIs and leaving gRPC for internal service-to-service communication  ^bf5JkKZW
