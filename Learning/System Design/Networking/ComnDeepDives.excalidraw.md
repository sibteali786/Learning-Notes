Regionalization and Latency ^ow6Guie5

- Means servers are distributed in a region and how much time it takes for a server to respond back.
- If a user is in Los Angeles, the more near the server is the less latency the request-response would have.
- In some cases it cannot be avoided if user has no data center near it, but it can be solved as well ^LbyRIT7d

Content Delivery Networks ( CDN ) ^ZNETaxOl

1. If our data does not changes alot and is not updated frequently that it can be " cached " in what we call as Edge Location

Why Used ?
- Fast response if data is present in Edge location
- Reduce load on servers ^QMSPNPoi

Regional Partitioning  ^7bTINURN

- Make region partitions based on usage or data relevance. ^cEtuNC9F

Example
Uber as an example. With the Uber app we're ordering rides from drivers in a specific city. If we're in Miami, we'll never want to book a ride with a driver currently in New York. This is an important insight! ^zu77TO84

- How to deal with failure like newtwork failure, server not responding, taking too much time to respond, power cut etc ^r1a4fWUF

Timeouts and Retries with backoff ^Ye7skyOd

- If we expect a request to take certain amount of time, we can timeout if request takes longer than that
- If server is not responding twice in a row, we can retry but with a backoff 

Remember its usefull for transient failure ( ones that are temporary like network glitch, loaded server etc ) ^8Zxmfi3u

Backoff ^oRDGSPEE

- Retrying is good unless its not trying for a permanent problem or increasing load on server even after consecutive failure in a short period of time, in that case we should bacoff
- We wait a little before retrying and then wait little more longer and so on if it continues.
- This backoff should be at some level random ? why becuase if 100 clients synchronize and retry at same time it can be a disaster as well.
 ^Lzkwpvud

This randomness is called Jitter ^sFpYq8hz

Retry Techniques ^Ld8VPSB0

Idempotancy ^8E0bgBVW

- APIs that produce same result no matter how many times they are called.
Like HTTP Get request

For complex cases like Writing data, we can have idempotency keys to make sure same request is idempotent that is server has some identification stored so it know it processed this request already. ^3SAYQDwp

Circuit Breakers ^piuoOcFg

- This is a technique used to solve problems like Cascading Failures like a down database instance which needs to restart but continous user requests cause it to never start at all. ^w0c5L8vH

How it works ^E6cDFhfL

- The circuit breaker monitors for failures when calling external services
- When failures exceed a threshold, the circuit "trips" to an open state
- While open, requests immediately fail without attempting the actual call
- After a timeout period, the circuit transitions to a "half-open" state
- A test request determines whether to close the circuit or keep it open ^2XrezyAb

Benefits ^pReHJlMk

Where to Use ^mDwHErJO

Some example sites to apply circuit breakers:

- External API calls to third-party services
- Database connections and queries
- Service-to-service communication in microservices
- Resource-intensive operations that might time out
- Any network call that could fail or become slow ^2eHqvTEn
