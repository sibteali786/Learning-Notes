UDP ^maj8Usut

- Connectionless: No handshake or connection setup
- No guarantee of delivery: Packets may be lost without notification
- No ordering: Packets may arrive in a different order than sent
- Lower latency: Less overhead means faster transmission
 ^OYepc3KX

UDP is perfect for applications where speed is more important than reliability, such as live video streaming, online gaming, VoIP, and DNS lookups. In these cases the application or client is equipped to handle the occasional packet loss or out of order packet.  ^IKKbA6pO

Transport Layer Protocols ^T7E63iLc

TCP ^SDyH73Ay


Connection-oriented: Establishes a dedicated connection before data transfer
Reliable delivery: Guarantees that data arrives in order and without errors
Flow control: Prevents overwhelming receivers with too much data
Congestion control: Adapts to network congestion to prevent collapse
 ^aw3dRKki

Tcp is perfect fo cases where 
data integrity is important 
or wherever UDP is not a 
good fit ^BoAr1SdA

When to Chose which Protocol ^LX007dTW

Tcp is mostly the default protocol in most 
system design interviews even if you do not 
mention it. 
But there can be cases where if we try to accomodate
UDP instead of TCP it would be better.

1. Low latency is critical ( real time apps, gaming)
2. Some data loss is acceptable ( Media streaming -> no 
one cares what last sentence was uttered in a video call ) 
3. High volume telemetry or logs where occassional loss is 
acceptable ^5AfuDhEN

Flow Control ^IlXTTfmg

- Host A needs to send multiple segments ( packets ) to Host B, which Host B can acknowledge all in 1 ACK.
- The question is how much A can send ? 
 ^sVx4vMhb

This is called Flow Control ^QTUdYxhX

The window Host A has to maintain so Host B is not overloaded
with packets.

- If Host A sends more packets then B's buffer can handle remainig packets are dropped.
- Thus RWND ( Receiver Window ) is sent along with the ACK from Host B on each ACK in request-response.
- The Sender Host A maintains a Sliding window to know how much segments ( packets ) it can send to Host B each time. ^ddiJpLxm

for reference see [[Networking#Flow Control]]  ^7ApKC26f

The transport layer is where we establish end-to-end communication between applications. They give us some guarantees instead of handing us a jumbled mess of packets. ^VmFxCoU8
