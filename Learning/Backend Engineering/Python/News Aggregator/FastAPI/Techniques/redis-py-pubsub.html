Creating & Subscribing

r = redis.Redis(...)
p = r.pubsub()

p.subscribe('chan1', 'chan2')
p.psubscribe('my-*')

Subscribing just tells Redis "send me stuff for this." Nothing is read from the socket yet — that's get_message()'s job (see §3).

The Message Dict

Every message read is a dict with 4 keys:

keymeaning
typesubscribe / unsubscribe / psubscribe / punsubscribe / message / pmessage
channelthe channel involved
patternNone unless type is pmessage
datasubscription count for [un]subscribe · actual payload for [p]message
{'type': 'message', 'channel': b'orders', 'pattern': None, 'data': b'order#123'}

3 Ways to Read Messages

get_message()

Non-blocking poll. Data ready → returns dict. Nothing ready → returns None immediately.

Best for: your own event loop

listen()

Blocking generator — for msg in p.listen():. Waits until something arrives.

Best for: simple scripts, nothing else to do

run_in_thread()

Runs get_message() on a loop in a background thread automatically.

Best for: fire-and-forget — requires handlers on every subscription

Core idea: get_message() is the actual "pump." Subscribing sets up what to listen for; calling get_message() (directly, via listen(), or via the background thread) is the act of pulling bytes off the socket right now. No call = messages sit unread in the OS buffer.
# get_message() in your own loop
while True:
    message = p.get_message()
    if message:
        # handle it
        pass
    time.sleep(0.001)

Message Handlers

Instead of manually branching on the dict, attach a callback per channel/pattern. When a handled message arrives, get_message() calls the handler internally and returns None — the message was already dealt with.

3 ways to attach a handler (mixable in one call)

FormWhen to useExample
Keyword argPlain, identifier-safe channel namesp.subscribe(**{'my-channel': handler})
redis.Subscription(name, handler)Names kwargs can't express — binary, special charsp.subscribe(redis.Subscription(b'\x80\x81', handler))
MixedCombine plain names + Subscription objects freelyp.subscribe('logs', redis.Subscription(b'\x82\x83', h))

Why Subscription exists: Python kwargs must be valid identifiers — no dashes, no raw bytes. redis.Subscription is just a small wrapper pairing (channel, handler) for names that can't be a kwarg.

def order_handler(message):
    print("New order:", message['data'])

def binary_handler(message):
    print("Binary:", message['data'])

p.subscribe(**{'orders': order_handler})
p.subscribe(redis.Subscription(b'\x80\x81', binary_handler))

r.publish('orders', 'order#123')
p.get_message()  # → calls order_handler(), prints, returns None

run_in_thread() — Rules & Safety Net

subscribe + handler
→
run_in_thread()
→
background loop calls get_message() on interval
Hard rule: every subscribed channel/pattern MUST have a handler attached before calling run_in_thread() — or it raises an error and refuses to start.

Why: the background thread has no way to hand a message dict back to your main thread. If a channel had no handler, that message would just be silently dropped on a thread nobody's watching. redis-py blocks this scenario outright rather than let messages vanish.

p.subscribe(**{'my-channel': my_handler})
thread = p.run_in_thread(sleep_time=0.001)
# ... background loop now runs get_message() every 0.001s ...
thread.stop()

Exception handler — catching crashes on the thread

If a handler raises inside the background thread, there's no try/except on your main thread to catch it — the thread would just die silently. exception_handler is your safety net.

def exception_handler(ex, pubsub, thread):
    print(f"Handler crashed: {ex}")
    thread.stop()

thread = p.run_in_thread(exception_handler=exception_handler)

Receives 3 args: the exception itself, the pubsub object (to inspect/resubscribe), and the thread (to stop it or restart cleanly).

Other Practical Notes

Quiet mode

r.pubsub(ignore_subscribe_messages=True) — suppresses subscribe/unsubscribe confirmations so get_message() only surfaces real data.

Reconnect behavior

PubSub auto re-subscribes to all prior channels/patterns on reconnect — but messages published during the disconnect are lost (consistent with at-most-once delivery).

Cleanup

Call p.close() when done to release the connection.

PUBSUB introspection

r.pubsub_channels(), r.pubsub_numsub(...), r.pubsub_numpat() — same server commands, wrapped as methods.
