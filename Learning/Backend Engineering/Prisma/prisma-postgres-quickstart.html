Prisma ORM v7 · PostgreSQL Quickstart

From empty folder to typed queries

New TypeScript project → Prisma ORM connected to Postgres → generated, type-safe client. v7's headline change: you now wire the DB driver yourself via an adapter, instead of Prisma connecting for you.

The pipeline

Steps 1–3 — project scaffolding

1. Create project + init TS

mkdir hello-prisma && cd hello-prisma
npm init
npm install typescript tsx @types/node --save-dev
npx tsc --init
(swap npm for bun/pnpm/yarn — same commands, different runner)

2. Install Prisma + Postgres deps

npm install prisma@prev @types/pg --save-dev
npm install @prisma/client@7 @prisma/adapter-pg pg dotenv

3. Enable ESM

// tsconfig.json
{ "module": "ESNext", "moduleResolution": "bundler" }

// package.json
{ "type": "module" }

Dependency cheat sheet

PackageRole
prismaCLI — init, migrate, generate
@prisma/clientThe query library your app imports
@prisma/adapter-pgDriver adapter — bridges Prisma Client to pg (new in v7's architecture)
pgActual node-postgres driver doing the wire protocol
@types/pgTS types for pg
dotenvLoads .env so process.env.DATABASE_URL works

Step 4 — prisma init generates 3 files

schema.prisma

schema

Datasource + generator config. This is where you'll add models next.

.env

secrets

Holds DATABASE_URL="postgresql://user:pass@localhost:5432/mydb?schema=public" — fill in your real credentials here.

prisma7.config.ts

config

Reads DATABASE_URL via dotenv/config. Named prisma7.config.ts specifically so it won't clash with Prisma 8's prisma.config.ts.

npx prisma init --datasource-provider postgresql --output ../generated/prisma

Step 5 — define your models

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  content   String?
  published Boolean @default(false)
  author    User    @relation(fields: [authorId], references: [id])
  authorId  Int
}

One-to-many: a User has many Posts; each Post points back via authorId.

Steps 6–7 — migrate, generate, connect

6. Create tables + generate client

npx prisma migrate dev --name init   # creates the actual DB tables
npx prisma generate                   # regenerates the typed client

7. Instantiate client with the adapter

// lib/prisma.ts
import "dotenv/config";
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "../generated/prisma/client";

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });
const prisma = new PrismaClient({ adapter });
This is the v7 shift — in older Prisma versions, PrismaClient connected to the DB itself. v7 pushes that to a driver adapter you instantiate explicitly — more control over pooling/config, one extra step to wire up.

Step 8 — query it

const user = await prisma.user.create({
  data: {
    name: "Alice", email: "alice@prisma.io",
    posts: { create: { title: "Hello World", published: true } },
  },
  include: { posts: true },
});

const allUsers = await prisma.user.findMany({ include: { posts: true } });

Run with npx tsx script.ts. Explore the data visually after with npx prisma studio.

Practical tip — since you're already comfortable with Docker volumes/Compose, the natural pairing here is a postgres service in compose.yaml with a named volume for persistence, and DATABASE_URL in .env pointing at localhost:<mapped-port> — no need for Prisma's own hosted Postgres offering if you're already self-hosting.
