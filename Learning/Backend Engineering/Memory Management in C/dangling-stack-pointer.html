Dangling Pointers to the Stack

Why new_coord() always prints 50, 60
The Bug
BROKEN 
coord_t *new_coord(int x, int y) {
  coord_t c;          // lives on new_coord's stack frame
  c.x = x; c.y = y;
  return &c;          // returns address of LOCAL variable
}

The moment new_coord returns, its stack frame is popped. The address &c now points to freed memory — undefined behavior.

Same address, reused three times

1
main's frame
new_coord(10,20) → c.x=10, c.y=20 @ addr A
↓ returns, frame popped, addr A freed
2
main's frame
new_coord(30,40) → c.x=30, c.y=40 @ addr A (reused)
↓ returns, frame popped, addr A freed
3
main's frame
new_coord(50,60) → c.x=50, c.y=60 @ addr A (reused)
↓ returns, frame popped — last value left at A: 50, 60

Why all three pointers show the same thing

c1 ──┐ c2 ──┼──► address A ──► { x: 50, y: 60 } (last write wins) c3 ──┘

Calls are sequential, not concurrent — each frame pops before the next pushes, so the allocator keeps handing out the same free slot. c1, c2, c3 all end up pointing at that one shared, stale address.

Recursive / nested calls

If a call happens before the previous one returns (recursion, nesting), frames stack on top of each other at different addresses — no collision, because nothing has been popped yet.

This bug specifically

Two things combine: (1) returning a pointer to memory that dies when the function returns, and (2) the next call reusing that exact freed address — making the bug look consistent instead of random garbage.

The Fix
CORRECT 
coord_t new_coord(int x, int y) {   // return by VALUE
  coord_t c;
  c.x = x; c.y = y;
  return c;                         // compiler COPIES c into caller's frame
}

The struct is copied out before the frame is popped, so each caller gets its own independent coord_t — not a pointer to a reused address.

Other ways to solve it

  • Return by value (used above) — simplest, safest for small structs. Minor copy cost.
  • Heap allocation (malloc) — pointer stays valid after return, but you now own manual free(); risk of leaks/double-frees.
  • Caller-allocated (coord_t *out param) — no copy, no heap; caller owns the memory. Common in perf-sensitive C, shifts responsibility to caller.
