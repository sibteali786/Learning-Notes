Trace

CH11 · Mark & Sweep GC · L8

Problem Statement

Mark only touches objects directly referenced by stack frames / globals. It has no idea about objects nested inside those — like an integer sitting inside a list. Without tracing, those nested-but-live objects get swept (freed) by accident, corrupting memory that's still in use.

On the flip side, an object that references itself (or forms a cycle) but isn't reachable from any root must still be treated as dead — reference existence alone isn't proof of life. Reachability from a root is what matters.

Real-World Example

def get_list():
    a = 5
    return [a]

print(get_list())

Here, a (an integer, value 5) is boxed inside a list. mark marks the returned list because it's directly referenced by a frame/global — but it never looks inside the list, so a stays unmarked. Sweep would then free a while the list still points to it. That's a use-after-free waiting to happen.

Self-reference trap: a list that appends itself (a.append(a)) but is never returned or stored anywhere still has a reference count > 0 conceptually — pointing at itself. A naive "has any reference" check would keep it alive forever. Only a root-reachability walk (mark → trace) correctly identifies it as garbage.

How It Works — Root → Trace Graph

mark marks only root-adjacent objects (blue). trace walks outward from those marked objects through containers (orange → green), using a worklist (gray_objects) so nested objects at any depth get marked too. The self-referencing array (red) is never reached from any root, so it stays unmarked and gets swept.

Key Distinctions

mark()

  • Walks VM frames' references stacks
  • Marks only directly reachable objects
  • Doesn't look inside containers
  • This is the "roots" pass

trace()

  • Starts from objects already marked
  • Uses a gray_objects worklist stack
  • Recursively (iteratively) blackens containers
  • Handles cycles safely — already-marked objects are skipped
Why a worklist instead of recursion? Using an explicit stack (gray_objects) instead of recursive function calls avoids stack-overflow risk on deeply nested or cyclic structures, and naturally terminates — once an object is marked, trace_mark_object refuses to re-push it, so cycles can't cause infinite loops.

Implementation — 3 Functions

trace_mark_object(gray_objects, obj)

Guard clause: NULL or already-marked → return immediately (this is what breaks cycles). Otherwise set is_marked = true and push onto gray_objects for later processing.

trace_blacken_object(gray_objects, obj)

Given an object popped off the worklist, look at its kind. INTEGER/FLOAT/STRING → no-op (leaf values, no outgoing references). VECTOR3 → call trace_mark_object on x, y, z. ARRAY → loop over elements[0..size) and call trace_mark_object on each.

trace(vm)

Allocate gray_objects (capacity 8; bail if allocation fails). Seed it with every already-marked object in vm->objects. Then drain the worklist: pop → blacken (which may push more objects back on) → repeat until empty. Free gray_objects at the end — it's just scratch space, not ownership of the objects.

Code

void trace_mark_object(stack_t *gray_objects, snek_object_t *obj) {
  if (obj == NULL || obj->is_marked == true) {
    return;
  }
  obj->is_marked = true;
  stack_push(gray_objects, obj);
}

void trace_blacken_object(stack_t *gray_objects, snek_object_t *obj) {
  if (obj->kind == INTEGER || obj->kind == FLOAT || obj->kind == STRING) {
    return; // leaf types — nothing to chase
  }
  if (obj->kind == VECTOR3) {
    snek_vector_t v = obj->data.v_vector3;
    trace_mark_object(gray_objects, v.x);
    trace_mark_object(gray_objects, v.y);
    trace_mark_object(gray_objects, v.z);
  }
  if (obj->kind == ARRAY) {
    for (size_t i = 0; i < obj->data.v_array.size; i++) {
      trace_mark_object(gray_objects, obj->data.v_array.elements[i]);
    }
  }
}

void trace(vm_t *vm) {
  stack_t *gray_objects = stack_new(8);
  if (gray_objects == NULL) { return; }

  for (size_t i = 0; i < vm->objects->count; i++) {
    snek_object_t *obj = (snek_object_t *)vm->objects->data[i];
    if (obj->is_marked) {
      stack_push(gray_objects, obj);
    }
  }

  while (gray_objects->count > 0) {
    snek_object_t *obj = (snek_object_t *)stack_pop(gray_objects);
    trace_blacken_object(gray_objects, obj);
  }

  stack_free(gray_objects);
}

Gotchas / Interview Tips

Order matters: mark → trace → sweep

Trace assumes mark already ran and seeded root objects with is_marked = true. It only re-checks vm->objects for already-marked ones — it does not itself know about frames.

Cycle safety comes from the guard clause

The single line if (obj->is_marked) return; in trace_mark_object is what makes self-referencing / cyclic structures terminate instead of looping forever. If asked in an interview "how do you handle cycles in a tracing GC," this is the answer.

gray_objects is scratch, not storage

It's freed at the end of trace() — it never owns the snek_object_ts, it just tracks "still need to blacken this." Real ownership/lifetime of objects lives in vm->objects, cleaned up later by sweep.
