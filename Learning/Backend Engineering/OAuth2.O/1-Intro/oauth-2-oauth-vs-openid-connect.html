OAuth vs OpenID Connect

They're often used together but are different things — with very different security considerations (details in a later section). This lesson: the high-level difference.

The Core Distinctionmemorize this
OAuth

Accessing APIs

Designed for applications to get access to APIs. The app only needs the ability to call the API — it does not need to know who the user is.

Issues: Access Token

OpenID Connect (OIDC)

Identifying the user

An extension of OAuth that adds user identity information on top, so the OAuth server can tell the app who the user is.

Issues: ID Token (plus the access token)

Terminology note: you'll hear "authorization vs authentication". The instructor dislikes these terms — they're nearly the same word and confusing, especially for non-native English speakers. Just think: accessing APIs (OAuth) vs identifying users (OIDC).
The Hotel AnalogyOAuth in the real world

You check in at a hotel: show ID + credit card at the front desk → they hand you a key card. You swipe it at your room door and it opens. The door doesn't know who you are — the front desk did that part. The door only checks whether the card is encoded as allowed.

Key insight: the key card needn't encode who you are — only which doors it opens and when it expires. Likewise an access token can grant access without telling the API or the app anything about the user's identity.
Software Example: Upload to Google DriveOAuth alone is enough

An app only needs to show an upload UI. It gets an access token from Google, then calls the Drive API to upload the file to the user's Drive. It never needs to know who the user is.

// OAuth only: no identity needed
POST https://www.googleapis.com/upload/drive/v3/files
Authorization: Bearer <access_token>   ← all the app needs
Where OAuth Alone Falls Shortneed the user's identity?

If the app wants to show the user's name in the UI or a profile photo in the corner, OAuth can't help: nothing in OAuth communicates user information. It's all added externally — mainly by OpenID Connect.

How OpenID Connect Adds Identitysame framework + one new token

OIDC builds on OAuth as a foundation. The same framework — how data moves and who the players are in the transaction — is unchanged. It simply adds user information into the flow, letting the OAuth server communicate data about the user back to the app.

Real-world scenarios:
• Photo-backup app uploading to Google Drive → OAuth only (access token).
• Same app showing "Welcome, Ali" with your avatar in the corner → needs OIDC (ID token).
• "Sign in with Apple / Google" buttons → identity is the whole point, so OIDC.
Key Takeaways & Tipsinterview-ready

Remember

  • OAuth = accessing APIs. OIDC = identifying users.
  • OIDC is an extension, not a replacement — same framework.
  • OAuth by itself conveys no user info.
  • Different tokens: access token vs ID token.

Interview one-liner

"OAuth gives apps an access token to call APIs without knowing who the user is. OpenID Connect extends OAuth with an ID token that tells the app who the user is."
