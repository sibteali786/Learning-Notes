// 01 — Symbols
Symbol() PRIMITIVE
Always unique. Even same description ≠ same symbol.
const a = Symbol('id'); const b = Symbol('id'); a === b // false — always
Hidden from JSON.stringify, for...in, Object.keys
Collision-free keys when multiple libs touch same object
Cannot be cloned — the reference IS the identity
Well-Known Symbols BUILT-IN HOOKS
Hook into JS engine behaviour on your custom classes.
// Make class iterable [Symbol.iterator]() { ... } // Control type coercion [Symbol.toPrimitive](hint) { ... } // Override instanceof [Symbol.hasInstance](obj) { ... }
Real use: Range class with Symbol.iterator works in for...of, spread, destructuring automatically.
Property Ordering Rules ALWAYS
JS engine follows a strict order — symbols always last.
1. Integer indices ↑
→
2. String keys (insertion order)
→
3. Symbols (insertion order)
Reflect.ownKeys(obj) // ['1','2','z','a', Symbol(s1), Symbol(s2)] // ──integers── ──strings── ──symbols──
Use Reflect.ownKeys() to get ALL — integers + strings + symbols together.
// 02 — Object Property APIs
getOwnPropertySymbols() VISIBILITY
The only way to see symbol-keyed properties.
Object.keys(obj) // ❌ misses symbols for...in // ❌ misses symbols JSON.stringify(obj) // ❌ misses symbols Object.getOwnPropertySymbols(obj) // ✅ [Symbol(id), Symbol(secret)]
getOwnPropertyDescriptors() METADATA
Returns full descriptor — not just value, but the hidden flags.
{ value, writable, enumerable, configurable } // OR accessor descriptor: { get() {}, set(v) {}, enumerable, configurable }
Why it matters: Spread { ...obj } silently drops getters/setters and non-enumerable props. Descriptors preserve everything.
// True clone preserving getters Object.defineProperties( {}, Object.getOwnPropertyDescriptors(source) );
// 03 — Weak Collections
WeakMap & WeakSet — The GC-Safe Alternative MEMORY
Don't prevent garbage collection. Keys must be objects.

// ❌ Map — memory leak const cache = new Map(); cache.set(domNode, data); // domNode removed — Map still holds ref // ✅ WeakMap — GC safe const cache = new WeakMap(); cache.set(domNode, data); // domNode removed → entry vanishes
Rule: Key is an object you don't own? → Weak variant. Need iteration or primitives? → Map/Set.

// 05 — Symbol Cloning
Can you deep clone a Symbol? NO — BY DESIGN
Cloning creates a NEW symbol → original refs break.
MethodSymbols?
structuredClone()✗ dropped
JSON.parse/stringify✗ dropped
{ ...spread }✗ dropped
Object.defineProperties + getOwnPropertyDescriptors✓ same ref
const ID = Symbol('id'); const obj = { [ID]: 42 }; // ❌ clone creates new Symbol internally // original ID ref can't reach it // ✅ Copy SAME symbol reference Object.defineProperties( {}, Object.getOwnPropertyDescriptors(obj) ); // cloned[ID] === 42 ✓
Mental model: Symbols aren't data to clone — they're keys/identities to share. Same reason you don't clone a WeakMap key.
