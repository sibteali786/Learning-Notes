Q3 — Return Type & Accumulation
Two common patterns when traversing + collecting:
Pattern A — Pass an array down
function traverse(el, results)
  results.push(el) if match
  traverse(child, results) for each child
Pattern B — Return and merge up
function traverse(el)
  childResults = traverse(child) for each child
  return [el, ...childResults] if match else [...childResults]

Which pattern you pick affects whether your function is pure or relies on shared mutable state. Pattern A mutates a shared array; Pattern B builds new arrays at each level.

Quick question before tasks: Which pattern do you think is more interview-friendly and why? No wrong answer — just reason through it. ^5wsV6NXr

On Pattern A vs B
You're right that Pattern A is more memory efficient — one shared array vs creating new arrays at every stack frame. ✅
But also note for interviews: Pattern A requires you to either

have an outer wrapper function that initializes the array, or
use a default parameter results = []

This is a common interview follow-up — "how do you expose a clean public API while keeping internal state?"

On Order
Good pragmatic thinking. But worth knowing:

DFS on a DOM tree naturally gives document order (top-to-bottom) because you visit a node before going deeper — this is called pre-order DFS.

So even though order isn't specified, DFS is the "correct" choice here by convention since getElementsByClassName also returns in document order. ^IX79WaoM

/**
 * @param {Element} element
 * @param {string} property
 * @param {string} value
 * @return {Array<Element>}
 */
export default function getElementsByStyle(element, property, value) {
  let result = [];
  // no base condition needed loop handles it
  function traverse(el) {
    const childEl = el.children;
    for (const child of childEl) {
      traverse(child);
    }
    const computed = window.getComputedStyle(el);
    if (computed && computed.getPropertyValue(property) === value) {
      result.push(el);
    }
  }
  for (const child of element.children) {
    traverse(child);
  }
  return result;
}
