🎓 IntersectionObserver — Infinite Scroll

Built the scroll-event version first, felt the pain, then swapped it out. Here's what stuck.
~80+
scroll event fires / gesture
~8-10
observer fires / gesture
OLD WAY

scroll event + manual math

  • Fires on every pixel scrolled
  • Reads scrollTop/scrollHeight/clientHeight → forces synchronous layout recalculation
  • Runs on main thread → competes with rendering
  • Needs manual "near bottom" math + loading guard
NEW WAY

IntersectionObserver + sentinel

  • Fires only when sentinel crosses viewport threshold
  • Browser-engine optimized, off main thread's critical path
  • No layout thrashing on every event
  • rootMargin lets you preload before user sees the edge

🔄 How it works, end to end

1
Empty sentinel div placed at bottom of list — purely a tripwire, no content
2
new IntersectionObserver(callback, options) created, told to watch sentinel
3
Sentinel scrolls near viewport → browser calls your callback with entry.isIntersecting = true
4
Callback triggers loadMore() → fetch → append items → sentinel physically moves further down
5
Repeat — browser keeps watching the same sentinel element automatically
root

Container to observe within. null = browser viewport. Use the scroll container itself if it's not the whole page.

rootMargin

Grows/shrinks the trigger zone. '200px' fires 200px before sentinel is visible — avoids blank-screen flash.

threshold

% of sentinel visible before firing. 0.1 = 10% visible triggers the callback.
