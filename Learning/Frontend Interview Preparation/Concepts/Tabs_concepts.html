3Accessibility — Roles, States, Properties

CategoryApplied here
Role (what it is)role="tablist", role="tab", role="tabpanel"
State (changes dynamically)aria-selected={isActiveValue}
Property (relationship link)aria-controls (tab → panel), aria-labelledby (panel → tab)
Bug caught: aria-controls/aria-labelledby are id references — pointing at a string that isn't a real element's id is a dangling reference, invisible to sighted users, broken for screen readers. Golden rule: "No ARIA is better than bad ARIA" — a role/property is a promise; an unfulfilled one actively misleads assistive tech.

4Keyboard Accessibility — Roving Tabindex

The mechanism: only the active tab gets tabIndex={0} (in native Tab order); all others get tabIndex={-1} (focusable only via .focus(), skipped by Tab key). This alone satisfies Tab-in/Tab-out behavior for free.
KeyBehavior implemented
TabNative — lands on active tab going in, exits tablist going out (no code needed, side effect of roving tabindex)
← / →Modulo arithmetic for wraparound: (i + 1) % len and (i - 1 + len) % len
Home / EndJump to index 0 / items.length - 1
onFocus, delegated at the container: activation happens on focus, not click — required because arrow-key .focus() calls never fire a click event. Delegating one onFocus to the tablist (bubbles in React) replaced per-button handlers; ref-array comparison matched event.target back to the correct item without fragile id-string parsing.
Ref array, not document.querySelector: needed for imperative .focus() calls — the one legitimate escape hatch from pure declarative state, since "move focus" can't be expressed as data the way "which tab is active" can.

5Mistakes Made & Fixes

Tabs I: Direct DOM manipulation (document.querySelector + classList) inside a React component. Problem: state lived in the DOM, invisible to React — risk of desync on any unrelated re-render.
Fix: moved active-tab tracking into useState.
Tabs II: Set aria-controls/aria-labelledby to values with no matching id anywhere → dangling ARIA references.
Fix: generated matching ids via helper functions, unique per-instance via useId.
Tabs III — bug 1: Used event.target.key (React-internal, not a real DOM property) to identify which tab was focused.
Fix: matched event.target against the ref array by identity instead.
Tabs III — bug 2: event.preventDefault() called unconditionally (first on every keydown, then on every button keydown) — silently broke native Tab-key navigation, since it suppressed default behavior for keys never meant to be intercepted.
Fix: scoped preventDefault() to only fire inside the specific ArrowLeft/ArrowRight/Home/End branches.

6Underlying Principle (carries to Menu, Accordion, Carousel, Combobox)

Declarative for state, refs only for imperative escape hatches. "Which tab is active" is state → useState. "Move keyboard focus to this DOM node" is inherently imperative → the one legitimate reason to reach for a ref. This exact shape (roving tabindex + ref array + focus-driven activation) reappears near-identically in Menu, single-open Accordion, Carousel, and Combobox — all APG patterns with "a list of interactive elements, arrow keys move focus, one is active at a time."
