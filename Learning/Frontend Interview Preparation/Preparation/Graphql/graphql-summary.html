05 · Resolver Chain (Key Concept)
// Data in memory
tasks = [
  { id: "1", assignee: "1" }
]

// Schema says assignee: User
// But data has assignee: "1" (ID)

// Field resolver bridges the gap ↓
Task: {
  assignee: (parent) =>
    users.find(u =>
      u.id === parent.assignee
    )
}
getTasks fires → returns [{assignee:"1"}]
↓ for each Task
Task.assignee resolver fires
↓ parent = the task object
returns full User { id, name, email }
⚡ Works for mock data AND freshly created mutation results — resolver chain doesn't care where the task came from
06 · Context + Auth Pattern
🔐 Build Context
// runs on every request
context: async ({ req }) => {
  const token =
    req.headers.authorization || ""
  return {
    isAuthenticated:
      token === "secret-token",
    // db: prismaClient,
    // user: decodeJWT(token)
  }
}
🛡️ Protect Resolver
getTasks: (_, __, ctx) => {
  if (!ctx.isAuthenticated)
    throw new GraphQLError(
      "Unauthorized", {
        extensions: {
          code: "UNAUTHENTICATED"
        }
      }
    )
  return tasks
}

10 · Interview Quick-Fire
Q: What is a resolver?
A function that fulfills a schema field — like a route handler in Express. Every field in your schema can have one.
Q: Why use input instead of type for arguments?
type fields can have resolvers, arguments of their own, and circular references. input is intentionally flat — plain validated data, no resolution, no circular refs allowed.
Q: What is context used for?
A shared object built per-request and passed to every resolver. Used for auth (decoded JWT / current user), DB connections (Prisma client), and logging.
Q: Query vs Mutation — beyond read/write?
Queries execute in parallel (safe, no state change). Mutations execute sequentially to prevent race conditions — e.g. createTask + updateTaskStatus running in parallel could corrupt data.
Q: What is a field-level resolver and when do you need one?
A resolver on a specific field of a type (e.g. Task.assignee). Needed when the raw data shape doesn't match the schema — e.g. data has assignee: "1" but schema expects a full User object.
