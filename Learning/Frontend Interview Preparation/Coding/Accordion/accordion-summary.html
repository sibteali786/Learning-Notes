Core Concepts Learned

🗂️ State shape Set

Independent multi-open sections need to track which ids are open — a Set<value> beats an array (O(1) has/add/delete vs O(n)) and a single boolean (can't represent N independent states).

♻️ Immutable updates

React detects change via reference comparison. set.add(x) mutates in place — same reference, no re-render. Always copy first: new Set(prev) then mutate the copy.

🖱️ Click vs 🎹 Keydown targeting

Click can land on any descendant (e.g. the icon span) and bubbles up — closures over event target are unsafe. Keydown always targets the currently focused element directly — no ambiguity.

🔗 this / closures

Passing an id via closure (onClick={() => handleClick(id)}) is more reliable than reading e.target.id, since nested elements can be the real click target.

Keyboard Navigation (Accordion III)

1 · Find current position

sections.findIndex(s => s.value === currentValue) — identity read from a data-* attribute on the focused button, not a closure (closure breaks once the listener moves to a single delegated parent).

2 · Compute next index with wraparound

Down: (i + 1) % length. Up: (i - 1 + length) % length — the + length avoids JS's % returning negative results, which plain (i - 1) % length would produce at index 0.

3 · Move focus imperatively

refs.current[nextIndex]?.focus() — arrow keys move focus, not React state, so this must be an imperative DOM call via refs, not a state update.

4 · preventDefault()

Arrow/Home/End have native browser scroll behavior — call event.preventDefault() per handled case so the page/container doesn't scroll instead of moving focus.

Your Solution vs. Official Solution

Your approach

  • kept useRef array of button DOM nodes for focus targeting
  • kept single nextIndex computed once, one .focus() call site (deduped vs. 4× repetition)
  • initially one onKeyDown per item (N listeners) + closure-passed value
  • upgraded to single delegated listener + data-accordion-value for identity — matched official's event delegation

Official (GreatFrontEnd)

  • uses document.getElementById(...).focus() — raw DOM query, bypasses React's ref system
  • uses document.activeElement to find current focus — global lookup, not component-scoped
  • uses single delegated onKeyDown on outer container
  • uses data-accordion-value to identify the section without closures

Verdict: your final version combines the best of both — event delegation (from official) + ref-based focus management instead of raw document.* queries (your improvement). Refs are React's sanctioned escape hatch for imperative DOM access; getElementById is a global lookup that's more fragile with multiple instances, SSR, or test environments.
