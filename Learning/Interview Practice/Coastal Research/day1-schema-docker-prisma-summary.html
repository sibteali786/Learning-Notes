1 · From a business story to entities

Coastal Research: a PI law firm's paralegal submits a research request for a case against a defendant; an admin assigns a researcher, who records the insurance policies found and their limits. Firms must never see each other's data.

Noun-extraction technique

  • Nouns → candidate tables (some shrink to columns)
  • Facts about a noun → columns
  • Verbs between nouns → relationships; "several", "more than one" hint cardinality
  • "never / must / only" → rules: DB constraint or app logic?

What changed between passes

  • Research + Request merged → one entity
  • Case "name" dropped → case_no, accident_date, jurisdiction_state, incident_type
  • Defendant promoted from embedded fields → own table (multiple defendants per case)
  • Roles are a column, not a table per role

3 · Design decisions (interview answers)

💰 Money → Decimal(12,2)

Decimal is stored base-10, exactly as typed. Float is binary, so 0.1 can't be represented and sums drift. Alternative: integer cents. Prisma returns a Decimal object, which serialises to a string in JSON.

🧮 Don't store derived data

isApplicable removed. Store effective_from/to and compute "active on accident date". A stored copy goes stale when a date is corrected. Only denormalise for a measured perf reason.

🏢 Tenant scoping = User.firm_id?

API knows only who is logged in. To return only their firm's cases, the user must point to a firm. Nullable because admins/researchers are internal staff. Filter every firm-user query by it (same idea as AsyncLocalStorage tenant isolation at work).

👤 Defendant is 1:N per Case, not M:N

If two firms sue the same person, a shared row would link data across tenants. Two rows with the same name is the safer trade.

📄 PolicyFinding = snapshot per request

Not a master policy registry, so no M:N join table. It records "what this researcher found on this date". Limits can change between two checks, so some duplication is accepted.

🔺 Research.case_id is denormalised

It saves a hop, but case_id can disagree with defendant.case_id. Guards: the service derives it from the defendant and never trusts the client. DB level: composite FK (defendant_id, case_id) → Defendant(id, case_id).

0️⃣ Min cardinality on the parent side

A Firm can exist with zero users and zero cases, because the parent has to exist first. An FK cannot enforce "at least one child". That needs app logic (create both in one transaction) or triggers.

👥 3 relations between the same two tables

created_by is required. assigned_to and assigned_by are nullable because a new request isn't assigned yet. Prisma needs a relation name on both sides to pair them.

5 · Indexes: every one justified by a query

Research(assigned_to_id, status)

Researcher's queue: "my IN_PROGRESS requests". The equality column goes first; status narrows within it.

Research(status, created_at)

Admin queue: "SUBMITTED requests, oldest first". Filter, then sort, from the same index.

Every FK column

Postgres doesn't auto-index foreign keys. Without them, joins and cascade deletes scan the whole child table.

Say it: "@@unique([firm_id, case_no]) already creates an index whose leftmost column is firm_id, so I didn't add a separate one on Case.firm_id."

6 · Docker Compose for Postgres

Ports

  • ports: "HOST:CONTAINER" makes it reachable from the host
  • expose is only visible to other containers on the network

Pin the image tag

postgres:17, not latest. A future pull could bring a new major version whose data format or data path differs (18 moved it).

Named volume → data survives

  • Mounted at /var/lib/postgresql/data (v17)
  • Must also be declared under top-level volumes:
  • down keeps it; down -v deletes it

⚠️ Init env vars run once

POSTGRES_USER / PASSWORD / DB only apply when the data directory is empty. Changing the password later does nothing while the volume exists.

Healthcheck

Postgres has no HTTP endpoint, so use the pg_isready CLI inside the container. It's used by depends_on: condition: service_healthy (app container, CI).

restart vs up -d

Container config is fixed at creation. restart reuses the old config; up -d detects the change and recreates it. The named volume keeps the data.

YAML gotcha I hit

- pgdata: /var/lib/...
space after : → YAML parses it as a mapping, so "missing a mount target"
- pgdata:/var/lib/...
one string, source:target

7 · Env vars, ${} vs $$, and real secrets

.env next to compose
→
Compose fills ${VAR} on the host
→
value baked into resolved config
$$VAR in healthcheck
→
literal $VAR passed through
→
container shell expands it at runtime

What $$ really buys

One source of truth and no values in the resolved config. It is not security: pg_isready never needs the password, and user/db names aren't secrets.

Env vars ≠ secret storage

Visible via docker inspect; leak through child processes, crash dumps, and logging that prints the environment.

Real options

  • Local: POSTGRES_PASSWORD_FILE + Compose secrets (mounted file)
  • AWS: Secrets Manager / SSM, fetched with the EC2 instance role
  • RDS can manage and rotate the master password in Secrets Manager

Repo hygiene

  • .env in .gitignore
  • commit .env.example with placeholders

8 · Node, TypeScript & Prisma 7 tooling

dependency vs devDependency

Rule: does the running server import it?

  • deps: express, @prisma/client, @prisma/adapter-pg, pg, zod, bcrypt, jsonwebtoken
  • dev: prisma CLI, typescript, tsx, @types/node, dotenv (only the Prisma config uses it)

Migrations in production

The prisma CLI is dev-only, so npm ci --omit=dev on EC2 doesn't have it. Run migrate deploy as a CI/CD step against RDS before the new code goes live, or keep prisma in deps (bigger image).

migrate dev vs migrate deploy

  • dev: creates migrations, may reset the DB. Local only.
  • deploy: applies existing files only. CI and prod.

Prisma 7 differences

  • prisma.config.ts holds the datasource URL
  • client generated to generated/prisma (gitignored), not node_modules → prisma generate in every build
  • driver adapter (@prisma/adapter-pg) required
  • no automatic .env loading

TypeScript on Node

  • module/moduleResolution: nodenext follows Node's real ESM rules → relative imports need .js
  • dev: tsx watch (fast, no type check)
  • prod: tsc once in CI → node dist/…
  • pin runtime: .nvmrc, engines, matching @types/node

Env loading

  • Node 20.6+: --env-file=.env built in (dev script)
  • prod: variables come from platform / Secrets Manager, no file

🐛 npx prisma@latest crashed

The latest dist-tag pointed at 8.0.0-rc.15, and npm's resolver crashed (edgesOut). Lesson: use the locally installed CLI (npx prisma) and check npm view <pkg> dist-tags.

🔒 npm allow-scripts

New npm blocks install scripts (bcrypt, prisma, esbuild) until approved. Install scripts are the main supply-chain attack vector, so review before npm approve-scripts.
