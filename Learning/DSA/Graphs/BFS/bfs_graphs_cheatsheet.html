Breadth-First Search

Level-by-level graph traversal — the tool for "fewest steps" and "shortest path" problems on unweighted graphs.

Problem Statement

Given a graph (adjacency list) or grid, find the minimum number of steps / edges to reach a target from a start node — e.g. fewest connections between two people in a social network, or the shortest route through a maze. Any time a problem asks for the minimum moves or shortest distance in an unweighted graph, this is a BFS signal.

How It Works — DFS vs BFS

DFS
BFS
Picks one direction and follows it as far as possible before backtracking.
Fans out evenly — visits every neighbor at the current distance before going further.
Uses a stack (or recursion).
Uses a queue — first in, first out, so earlier-discovered nodes get processed first.
Can overshoot: wanders down a long path before trying a shorter alternative.
Guaranteed to find the target along the shortest possible route, because it clears distance 1 before distance 2, distance 2 before distance 3, etc.

The Ripple Effect

On a grid, checking the 4 directions (up/down/left/right) from the start cell spreads outward like a ripple on water. Cells one step away light up first, then two steps, then three. Each ring = one BFS level, and separating those rings is the key to almost every BFS problem.

The Level-Size Trick (in code)

Before pulling from the queue each round, capture levelSize = queue.length. That number is exactly how many nodes belong to the current ring. Loop that many times — any new neighbors pushed during the loop belong to the next ring and wait their turn.

Pseudocode

function bfsLevels(graph, start):
    queue <- [start]
    visited <- {start}
    levels <- []

    // outer loop: one iteration per distance layer
    while queue is not empty:
        levelSize <- queue.length   // locks in this ring's node count
        currentLevel <- []

        for i in 0..levelSize:
            node <- queue.popFront()
            currentLevel.append(node)

            for neighbor in graph[node]:
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.pushBack(neighbor)

        levels.append(currentLevel)

    return levels

Key Distinctions

Data structure
Queue (FIFO) — not a stack. FIFO order is what keeps nodes processed layer by layer.
Visited tracking
Mark visited the moment a node is pushed onto the queue (mark-on-push), not when it's popped — otherwise the same node can be queued multiple times by different neighbors before it's processed.
Grid vs graph
Same algorithm — a grid is just a graph where each cell's "neighbors" are the 4 (or 8) adjacent cells instead of an adjacency list.
Shortest path guarantee
Only holds for unweighted graphs. For weighted shortest paths you need Dijkstra's algorithm instead.

Complexity

O(V + E)
Time — every node visited once, every edge examined once
O(V)
Space — queue + visited set; worst case an entire level sits in the queue at once

Alternative Approaches

DFS
Simpler to write recursively, less memory pressure in some cases, but does not guarantee shortest path — only use when you need reachability/connectivity, not minimum distance.
Dijkstra
Generalizes BFS to weighted graphs using a min-heap instead of a plain queue. Reduces to BFS when all weights are equal.
Bidirectional BFS
Run BFS from both start and target simultaneously, meet in the middle. Cuts search space roughly in half for large graphs — worth mentioning in interviews as an optimization.
A*
BFS/Dijkstra + a heuristic to bias the search toward the target faster. Overkill for most interview problems but good to know exists.

Real-World Examples

🔗
Social networks
"Degrees of separation" between two people — LinkedIn's "2nd/3rd connection" labels are BFS distance.
🗺️
Maze / map routing
Shortest route through an unweighted grid, e.g. GPS routing when every road segment counts as one step.
🌐
Web crawlers
Crawling pages level by level from a seed URL, exploring nearby pages before distant ones.

Interview / Practical Tips

  • Trigger words to watch for: "fewest," "minimum steps," "shortest path" + "unweighted" — that combination screams BFS.
  • State out loud why DFS wouldn't work first (no shortest-path guarantee) — interviewers want to hear that reasoning, not just the correct code.
  • Always clarify: is the graph weighted? Directed? Can it have cycles? Grid or adjacency list?
  • Narrate the level-size trick explicitly — it's the one line interviewers check for in "minimum steps" grid problems.
  • Mark visited on push, not on pop — this is the most common BFS bug and worth saying out loud as you write it.
