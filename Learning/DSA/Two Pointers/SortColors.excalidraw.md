## — Intuition

Imagine the array divided into **4 regions** at any point:

```
[  0s  |  1s  |  unknown  |  2s  ]
 ^       ^      ^           ^
low     low    mid         high
```

- Everything **before low** → sorted 0s
- Between **low and mid** → sorted 1s  
- Between **mid and high** → unknown (not yet processed)
- Everything **after high** → sorted 2s

**`mid` is your explorer** — it shrinks the unknown region from the left, `high` shrinks it from the right. We stop when unknown region is empty i.e. `mid > high`.

---

## Why O(N) — No Element Processed Twice?

Each pointer only moves in **one direction** and never goes back:
- `low` only increases
- `mid` only increases  
- `high` only decreases

When you swap `mid` with `high` and don't increment `mid` — yes you re-examine that position, **but `high` already decreased**. The unknown region still shrank by 1.

So every swap/move shrinks the unknown region by exactly 1. Unknown region starts at N, so **maximum N iterations total**.

---

## Dry Run on `[2,0,2,1,1,0]`

```
low=0, mid=0, high=5   → nums[mid]=2 → swap(mid,high) → [0,0,2,1,1,2], high=4
low=0, mid=0, high=4   → nums[mid]=0 → swap(mid,low)  → [0,0,2,1,1,2], low=1, mid=1
low=1, mid=1, high=4   → nums[mid]=0 → swap(mid,low)  → [0,0,2,1,1,2], low=2, mid=2
low=2, mid=2, high=4   → nums[mid]=2 → swap(mid,high) → [0,0,1,1,2,2], high=3
low=2, mid=2, high=3   → nums[mid]=1 → mid=3
low=2, mid=3, high=3   → nums[mid]=1 → mid=4
mid > high → DONE ✅
```

Notice — `mid` never went back, `high` never went forward. Unknown region shrank every single step.
