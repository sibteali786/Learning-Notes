Chapter 7.1

No <form> in React Native

Concept
Web — form-based

Inputs grouped in <form>. Submit fires onSubmit with an event object. e.target.value to read input.

React Native — individual

No form element. Each input managed separately with useState. Submit = onSubmitEditing callback on the input itself.

★ Real-world analogy: Web forms are like a checkout cart with a single "Pay" button. RN inputs are like individual cashiers — each one independently tracked and submitted. More control, more wiring.

TextInput — The Core Setup

Step 1
⚠️ TextInput has zero default styling. Drop it in unstyled and it's completely invisible — no border, no background, no height. Always add at minimum borderWidth + borderColor to see it.
<TextInput value={value} onChangeText={setValue} // gives you the string directly (not an event) placeholder="E.g Coffee" returnKeyType="done" // changes bottom-right keyboard button label onSubmitEditing={handleSubmit} // fires when user taps done/return style={styles.textInput} />

Styles for the textInput:

textInput: { borderColor: theme.colorLightGrey, borderWidth: 2, padding: 12, fontSize: 18, borderRadius: 50, // pill shape marginHorizontal: 12, marginBottom: 12, }, // Also: remove justifyContent:"center" from container, add paddingTop: 12
💡 onChange vs onChangeText: onChange gives a synthetic event (like web). onChangeText gives you the string directly — use this 99% of the time. Same shorthand pattern: onChangeText={setValue} not onChangeText={(v) => setValue(v)}.

Keyboard Control Props

Reference
PropPurposeExample values
keyboardType Controls which keyboard layout opens "default" · "numeric" · "email-address" · "phone-pad"
returnKeyType Changes label on the bottom-right keyboard button "done" · "go" · "search" · "next" · "send"
autoCapitalize Controls automatic capitalization "none" · "sentences" · "words" · "characters"
autoComplete Enables native autofill suggestions "email" · "password" · "name" · "off"
autoCorrect Toggle spell-check corrections true · false
onSubmitEditing Fires when done/return key is pressed — replaces form onSubmit () => handleSubmit()
★ Keyboard is input-controlled: Unlike web where keyboard is an OS concern, in RN the TextInput's props directly control which keyboard opens. Set keyboardType="numeric" even for a text field used for phone numbers — the OS shows the numeric pad immediately on focus.

Step 2 & 3

TypeScript type + initial data:

type ShoppingListItemType = { id: string; name: string; }; const initialList: ShoppingListItemType[] = [ { id: "1", name: "Coffee" }, { id: "2", name: "Tea" }, { id: "3", name: "Milk" }, ];

State + handleSubmit:

const [shoppingList, setShoppingList] = useState(initialList); const [value, setValue] = useState<string>(); const handleSubmit = () => { if (value) { const newList = [ { id: new Date().toISOString(), // unique per ms name: value, }, ...shoppingList, // new item prepended ]; setShoppingList(newList); setValue(undefined); // clear input } };

JSX — map over state:

<View style={styles.container}> <TextInput value={value} onChangeText={setValue} placeholder="E.g Coffee" returnKeyType="done" onSubmitEditing={handleSubmit} style={styles.textInput} /> {shoppingList.map((item) => ( <ShoppingListItem key={item.id} name={item.name} /> ))} </View>
