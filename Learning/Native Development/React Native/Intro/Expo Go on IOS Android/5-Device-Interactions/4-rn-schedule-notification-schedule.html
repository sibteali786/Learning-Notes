Full updated counter/index.tsx — permission check + schedule:

import * as Notifications from "expo-notifications"; import { Alert } from "react-native"; const scheduleNotification = async () => { const result = await registerForPushNotificationsAsync(); if (result === "granted") { await Notifications.scheduleNotificationAsync({ content: { title: "I'm a notification from your app! 📨", }, trigger: { type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL, seconds: 5, }, }); } else if (Device.isDevice) { // Only show alert on real device — not simulator (where it always fails) Alert.alert( "Unable to schedule notification", "Enable the notifications permission for Expo Go in settings", ); } };

Trigger Types

Reference
Trigger typeUse caseKey fields
TIME_INTERVAL Fire after N seconds from now seconds: 5
DATE Fire at a specific Date object date: new Date(...)
DAILY Fire every day at a specific time hour: 9, minute: 0
WEEKLY Fire once per week weekday: 2, hour: 9
YEARLY Fire once per year month: 0, day: 1
⚠️ SDK 53 breaking change: Trigger now requires an explicit type field (SchedulableTriggerInputTypes.TIME_INTERVAL). Omitting it causes the notification to fire instantly. Always include type.

Foreground vs Background — Critical Gotcha

Gotcha
App in foreground

Notification fires but does not appear in the notification tray. Swallowed silently. You must add a foreground notification handler to intercept it.

App backgrounded ✓

Notification appears in the OS notification tray after the trigger delay. Tapping it opens the app. This is the expected behavior.

Bonus — Secrets in React Native Apps

From Q&A

Discussion from the transcript about GoogleServices.json / Firebase files and what counts as a "secret":

Not actually secret

GoogleServices.json, .plist, Firebase IDs — these are bundled into the app binary. Anyone can extract them from a downloaded .apk / .ipa. Scope-locked to your app bundle, but readable. Don't treat as secrets.

Actual secret — keep server-side

API keys (OpenAI, Stripe, etc.) with billing implications. Must live on a server (Lambda / Cloud Function). App calls your API. You can rotate keys without releasing a new app version.

★ The rule: Anything shipped in your app bundle is extractable by a determined person. If you can't rotate it without releasing a new app version → it's a problem. Put real secrets behind a server API you control.
💡 If you need GoogleServices.json in EAS CI without committing to git → use EAS Secrets. Docs: eas secret:create — Expo has first-class support for injecting files at build time.
