Chapter 6.2

How a Stack Works

Concept

Each new screen renders on top of the previous. Going back pops the top screen off. The first screen is always at the bottom.

BOTTOMindex.tsx → /
PUSHEDcounter.tsx → /counter
TOP (active)idea.tsx → /idea

← goBack() removes top card, reveals card below

3 ways to go back

1. Swipe from left edge (iOS gesture)
2. Header back button (auto-added by Stack)
3. Android system back button / gesture

🎨 Platform-specific by design: iOS uses slide-from-right + left-aligned back button. Android uses bottom-up animation + left-aligned title. This is intentional — apps should feel native to their platform.
★ Real-world analogy: A stack of browser tabs you can't reorder — each navigate() opens a new tab on top, each goBack() closes the current tab and returns to the previous one.

New Screen Files

Setup

app/counter.tsx

export default function CounterScreen() { return ( <View style={styles.container}> <Text style={styles.text}>Counter</Text> </View> ); }

app/idea.tsx

export default function IdeaScreen() { return ( <View style={styles.container}> <Text style={styles.text}>Idea</Text> </View> ); }
💡 Screens are export default (routing files). Note the shared pattern: flex: 1 + justifyContent: "center" + alignItems: "center" for a centered placeholder — keep it as your screen template.

3 Ways to Navigate

Core API
#MethodWhen to useCode
1 <Link> Declarative links in JSX — like an <a> tag. Simple tappable text/element. href="/counter"
2 useRouter Programmatic — inside event handlers, callbacks, after async operations. router.navigate("/idea")
3 Header buttons Free — Stack auto-injects back button in header. No code needed. auto-injected by Stack

Method 1 — Link component in index.tsx:

import { Link } from "expo-router"; <Link href="/counter" style={{ textAlign: "center", marginBottom: 18, fontSize: 24 }} > Go to /counter </Link>

Method 2 — useRouter hook in counter.tsx:

import { useRouter } from "expo-router"; const router = useRouter(); <TouchableOpacity onPress={() => router.navigate("/idea")}> <Text>Go to /idea</Text> </TouchableOpacity>

router.push vs .navigate vs .replace

Critical Distinction
router.push()

Always adds a new screen on top of the stack — even if that screen is already in the stack. Guarantees forward navigation.

router.navigate()

Smart — if the target screen already exists in the stack, goes back to it instead of adding a duplicate. Can go backwards.

router.replace()

Replaces the current screen with the new one. No back button to the replaced screen. Good for auth flows (login → home).

★ The gotcha with navigate(): Stack is index → idea → counter. Calling router.navigate("/idea") from counter goes back to the existing idea screen — it doesn't push a new one. Use push() if you always want to go forward.
💡 Rule of thumb: Tappable links in JSX → <Link>. Triggered after an event (form submit, async result, condition) → useRouter. Auth redirect → replace().
