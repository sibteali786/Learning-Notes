Chapter 6.3 — Modal Navigation

What is a Modal Screen

Concept

A modal renders on top of existing content. On iOS it slides up from the bottom and can be dismissed by dragging down. On Android it looks like a regular stack screen (platform default).

✓ Modal defined at top-level (works)
_layout.tsx (root)
index

idea (modal) ✓

Modal is adjacent to siblings — renders over all of them.

✗ Modal inside tab (broken)
_layout.tsx (root)
Tabs navigator
screen (modal) ✗

Can't render over its own parent navigator — modal is trapped inside the tab.

★ Real-world analogy: A modal defined inside a tab is like trying to open a popup that covers the browser window from inside an iframe — it's constrained by its parent. Define modals at the highest layout level they need to cover.

Adding presentation: modal

Code

One prop change in _layout.tsx — no new files needed:

<Stack> <Stack.Screen name="index" options={{ title: "Shopping list" }} /> <Stack.Screen name="counter" options={{ title: "Counter", presentation: "modal" }} /> <Stack.Screen name="idea" options={{ title: "My idea", presentation: "modal" }} /> </Stack>

💡 Custom alert trick from transcript: Use presentation: "transparentModal" + a small centered View with your custom UI inside. Replaces the need for Alert.alert() when you need full styling control.
💡 File-system routing reminder: You don't need to define screens in _layout.tsx for them to exist — files in app/ auto-become screens. You only define them in the layout when you need to add options like presentation or a custom title.
Chapter 6.4 — Bottom Tabs

Stack → Tabs: One Word Change

Setup

The entire conversion is swapping Stack → Tabs and Stack.Screen → Tabs.Screen:

- import { Stack } from "expo-router"; + import { Tabs } from "expo-router"; - <Stack> + <Tabs> - <Stack.Screen name="index" ... /> + <Tabs.Screen name="index" ... /> - </Stack> + </Tabs>
💡 Link and useRouter still work with tabs — you can navigate programmatically or via Link even when tabs are present. Just less necessary since the bar handles it.

Tab Bar Icons + Global Tint Color

Step 2
import Feather from "@expo/vector-icons/Feather"; import AntDesign from "@expo/vector-icons/AntDesign"; import FontAwesome5 from "@expo/vector-icons/FontAwesome5"; import { theme } from "../theme"; // Global active tint — set once, applies to ALL tabs <Tabs screenOptions={{ tabBarActiveTintColor: theme.colorCerulean }}> <Tabs.Screen name="index" options={{ title: "Shopping list", tabBarIcon: ({ color, size }) => ( <Feather name="list" size={size} color={color} /> ), }} /> <Tabs.Screen name="counter" options={{ title: "Counter", tabBarIcon: ({ color, size }) => ( <AntDesign name="clockcircle" size={size} color={color} /> ), }} /> <Tabs.Screen name="idea" options={{ title: "My idea", tabBarIcon: ({ color, size }) => ( <FontAwesome5 name="lightbulb" size={size} color={color} /> ), }} /> </Tabs>
tabBarIcon prop

A function returning any React element. Receives color, size, focused. Must pass color + size through to the icon for tinting to work.

tabBarActiveTintColor

Set on screenOptions of the <Tabs> container — applies globally to all tabs. Change one value to retheme all icons + labels.

tabBarInactiveTintColor

Optional companion prop — controls the grayed-out color for inactive tabs. Defaults to system grey if omitted.

⚠️ Don't hardcode icon color. If you pass a fixed color like color="blue" instead of the prop-injected color, the active/inactive tinting won't work — icon stays fixed while label changes.
