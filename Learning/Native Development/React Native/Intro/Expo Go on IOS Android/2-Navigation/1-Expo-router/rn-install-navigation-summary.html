Chapter 6.1

Expo Router — Mental Model

Concept
Built on React Navigation

Expo Router wraps React Navigation. Screen options, hooks, and styling props from React Navigation docs all apply — check both docs.

File-system routing

Same idea as Next.js — file names = routes. But mobile adds extra navigation types that web doesn't have.

📚
Stack
Push/pop screens. Back button. Most common.
⬆️
Modal
Slides up from bottom. Dismissable.
📑
Tabs
Bottom tab bar. Persistent navigation.
★ Real-world analogy: Think of the file system as your routing config file — but instead of writing { path: '/products/:id' } in a router object, you just name the file [productId].tsx. The framework infers everything else.

File System → Route Mapping

Reference
app/ index.tsx → / (root) home.tsx → /home products/ index.tsx → /products (folder index, no "index" in URL) [productId].tsx → /products/123 (dynamic route) _layout.tsx → layout for this folder (1 per folder, not a route)
💡 _layout.tsx is special — it's not a screen, it wraps all sibling screens and defines how they're displayed (Stack, Tabs, Modal). Exactly one allowed per folder.

6-Step Setup Walkthrough

Setup
1
Install libraries
npx expo install expo-router react-native-safe-area-context react-native-screens expo-linking expo-constants expo-status-bar

react-native-safe-area-context — handles iOS notch/Android cutout safe zones. Expo Router wraps screens in it automatically.

2
Change entry point in package.json
- "main": "expo/AppEntry.js" + "main": "expo-router/entry"

This switches the JS entry point from the bare App.tsx to the app/ folder that Expo Router manages.

3
Add scheme to app.json
+ "scheme": "taskly" // enables deep links: taskly://some-screen

Required because Expo Router has built-in deep linking. Without a scheme, the router can't register intent listeners on the device.

4
Move App.tsx → app/index.tsx
# create app/ folder # rename App.tsx → index.tsx # move to app/index.tsx # update any relative imports (../theme → ../../theme etc.)

The root route must be named index.tsx. All other screens can use descriptive names.

5
Restart bundler with cache reset
npx expo start --reset-cache
⚠️ PluginError? If you see Failed to resolve plugin for "expo-router" — you either skipped step 1 or didn't reset cache. Always use --reset-cache after structural changes.
6
Create app/_layout.tsx
import { Stack } from "expo-router"; // default export — not named export (Expo Router convention) export default function Layout() { return ( <Stack> // name = file name; title overrides ugly "index" default <Stack.Screen name="index" options={{ title: "Shopping list" }} /> </Stack> ); }

Without this, screens still render (default stack), but the header title will just say "index". Layout files always use export default — unlike regular components.

Scheme & Deep Linking Explained

Concept

How an intent reaches your app from a URL:

URL fired
taskly://home
→
OS broadcasts intent
"who handles taskly://"?
→
All apps check
their registered scheme
→
Your app says
"that's me!" → opens
Basic deep linking (this course)

Uses taskly:// scheme. Works app-to-app or from browser. Easy to set up. Covered in intermediate course.

Universal links (advanced)

Uses HTTPS URLs like https://taskly.com/home. Requires hosting a verification file + registering an associated domain. iOS + Android supported.

Key Distinctions to Remember

Interview Tips
export default

Layouts and screens use export default. Regular components use named exports. Different rule for routing files.

_layout ≠ screen

Layout files wrap screens — they don't create a route. Exactly one per folder. Filename must start with _.

index is mandatory

Root entry point must be index.tsx. Other screens can be named anything. Without index Expo Router can't boot.

💡 Shortcut: If you use npx create-expo-app with the default template (not blank), Expo Router + safe area context + all of this is already wired up. We did it manually to understand what's happening under the hood.
expo-router _layout.tsx safe-area-context scheme: taskly export default --reset-cache
