3 Ways to Make a Button

Concept
Button ❌ avoid

Built-in but renders a platform-native button you can't style at all. Only useful for quick local tests — never in production.

TouchableOpacity ✓

Wraps any element as a pressable. Automatically dims opacity on press. activeOpacity prop to tune the dim level (default is intense → use 0.8).

Pressable ✓ new-gen

More powerful — onPressIn, onPressOut, onHoverIn/Out, dynamic styles based on pressed state. Use when you need custom press feedback.

★ Rule of thumb: Use TouchableOpacity for 90% of buttons (simple, readable). Reach for Pressable only when you need to change the button's visual appearance during the press (e.g. background color change, scale animation).
💡 Pressable extra props from transcript: onHoverIn · onHoverOut · onPressIn · onPressOut — useful for desktop/web targets via React Native Web.

Alert Confirmation Dialog

Step 2

Alert.alert(title, message, buttons[]) — 3 arguments. Platform renders native dialog automatically.

import { Alert } from "react-native"; const handleDelete = () => { Alert.alert( "Are you sure you want to delete this?", // title "It will be gone for good", // subtitle [ { text: "Yes", onPress: () => console.log("Ok, deleting."), style: "destructive", // iOS red text }, { text: "Cancel", style: "cancel" }, ], ); }; // In JSX — clean handler reference (no wrapper arrow needed) <TouchableOpacity onPress={handleDelete} />

Alert.alert — 3rd arg button styles

style valueBehaviorPlatform
"destructive"Renders text in red — signals danger actioniOS only (Android ignores)
"cancel"Bold text, positioned as cancel actioniOS + Android
undefinedDefault button stylingBoth
★ Platform difference: Alert renders a native iOS sheet vs an Android Material dialog — same code, totally different look. This is RN's platform adaptation in action. To fully customize: build a full-screen modal with transparent background instead.
