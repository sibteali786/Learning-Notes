What & Why

Concept
ESLint — Static Analysis

Reads your code without running it and flags common bugs, unused vars, bad patterns. Like a strict code reviewer that never sleeps.

Prettier — Auto Formatter

Enforces consistent style (quotes, spacing, brackets) automatically. You stop arguing about formatting; the tool decides.

★ Real-world analogy: ESLint is the compiler warning you about logic errors. Prettier is the office style guide enforced by a robot — no more PR comments like "use single quotes."

ESLint Setup

Step 1

One command — Expo handles everything since SDK 51:

npx expo lint # installs deps + creates config file
SDK ≤ 52 output

Creates .eslintrc.js — legacy config format

SDK 53+ output ✓

Creates eslint.config.js — new Flat Config format (ESLint 8)

Run linting:

yarn lint # show errors yarn lint --fix # auto-fix all fixable issues
💡 Tip: ESLint errors/warnings don't stop your app from running — they're advisory. E.g. adding const blah = "" triggers an "unused variable" warning but the app still runs fine.

Prettier Setup

Step 2

Install 3 packages:

# yarn yarn add -D prettier eslint-config-prettier eslint-plugin-prettier # npm / pnpm / bun npx expo install -- --save-dev prettier eslint-config-prettier eslint-plugin-prettier

Then wire it into eslint.config.js (SDK 53+ Flat Config):

// eslint.config.js const { defineConfig } = require('eslint/config'); const expoConfig = require('eslint-config-expo/flat'); +const prettierPlugin = require('eslint-plugin-prettier/recommended'); module.exports = defineConfig([ expoConfig, + prettierPlugin, { ignores: ['dist/*'] }, ]);

Legacy .eslintrc.js (SDK ≤ 52):

module.exports = { extends: ['expo', 'prettier'], plugins: ['prettier'], rules: { 'prettier/prettier': 'error' }, };
