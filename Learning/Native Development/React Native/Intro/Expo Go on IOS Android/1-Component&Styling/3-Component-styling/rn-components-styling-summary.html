Chapter 5.1

Core Primitives — View & Text

Concept
View ≈ <div>

Container for positioning and styling. "Views all the way down" — you can nest as many as you want, same as divs. Never renders visible content itself.

Text ≈ <p> but stricter

ALL text in RN must be inside a <Text> component. Raw strings outside Text crash the app — no exceptions.

🚨 Common crash — falsy render trap:
{arr.length && <Text>items</Text>} — when arr.length === 0, React Native renders the number 0 on screen, which is outside a Text → instant crash.
Fix: always use a boolean: {arr.length > 0 && <Text>...</Text>}
★ Real-world analogy: Web lets you put text anywhere in the DOM. RN is like a strict type system for UI — every piece of text needs to be "typed" as a <Text> node, otherwise the native renderer doesn't know what font/size/color to use on iOS vs Android.

Styling System

Core Concept
Syntax

Plain JS objects — camelCase props. CSS knowledge transfers directly. No .css files, no Sass, no CSS modules built-in.

Units

No px, em, rem. Everything is display points, which scale with device pixel ratio (e.g. 3× on modern iPhones).

No Global Styles

Can't style "all Text elements" like CSS selectors. Pattern: shared theme.ts file + StyleSheet per component.

Display Points vs Pixels

// 1 display point on a 3× device = 3×3 = 9 physical pixels PixelRatio.get() // iOS Simulator → 3 | old Android → 1 | high-end Android → 3.5 // Practical implication for images: // High pixel ratio device needs larger source images to look crisp // Use @2x / @3x suffixed assets just like React Native recommends
★ Real-world analogy: Same as CSS rem being relative to root font size — display points are "logical pixels" relative to device density. A borderBottomWidth: 1 looks the same physical size on every device, regardless of screen resolution.

Flexbox — Web vs React Native

Gotchas
🌐 Web CSS Default
displayblock (must add flex)
flexDirectionrow
alignContentstretch
flexShrink1
📱 React Native Default
displayflex always ✓
flexDirectioncolumn ⚠️
alignContentflex-start
flexShrink0
⚠️ Biggest gotcha: flexDirection defaults to column not row. Coming from web, side-by-side layouts will stack vertically and confuse you until you add flexDirection: 'row' explicitly.

Step-by-Step

Step 1 — Inline styles (quick prototype)

Step 2 — Move to StyleSheet (convention)

const styles = StyleSheet.create({ itemContainer: { paddingVertical: 16, paddingHorizontal: 8, borderBottomColor: "#1a759f", borderBottomWidth: 1, }, itemText: { fontSize: 18, fontWeight: "200", }, });

Shared theme.ts Pattern

Best Practice

New file: theme.ts

// theme.ts — root level export const theme = { colorCerulean: "#1a759f", colorWhite: "#fff", // production: add spacing, fontSizes // spacing12: 12, spacing16: 16, ... };

Consume in StyleSheet

import { theme } from "./theme"; // before: "#1a759f" scattered everywhere // after: borderBottomColor: theme.colorCerulean, backgroundColor: theme.colorWhite,
★ Why it matters: RN has no CSS variables or global stylesheets. Rebrand the whole app (e.g. cerulean → teal) by changing one line in theme.ts instead of grep-replacing hex values across 30 files. Same principle as design tokens in a design system.

StyleSheet.create — What it Actually Does

Common Misconception
What people think

Some optimization magic that pre-processes styles at compile time or sends them to native once.

What it actually does

Validates that your style props are valid TypeScript types. That's it. Mostly a dev-time type checker, not a runtime optimizer.

💡 Convention: Every UI file has its StyleSheet.create({...}) at the bottom of the file. Think of it as CSS modules — scoped to that file, co-located with the component.
