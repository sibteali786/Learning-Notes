Why Extract Components

Concept
Problem — Everything in App.tsx

One file grows massive as the app scales. Logic, styles, and markup become impossible to maintain or reason about.

Solution — Component per concern

Each UI piece lives in its own file under components/. Reusable, independently testable, and easy to refactor.

★ Real-world analogy: Like splitting a monolith into services — App.tsx becomes an orchestrator that just composes components, not a giant file holding every implementation detail.

Creating the Component with TypeScript Props

Step by Step
// components/ShoppingListItem.tsx import { TouchableOpacity, View, Alert, StyleSheet, Text } from "react-native"; import { theme } from "../theme"; // TypeScript: define the shape of props type Props = { name: string; // required — no ? = mandatory // name?: string; // optional — add ? to allow omitting }; // Named export (not default) — modern convention export function ShoppingListItem({ name }: Props) { const handleDelete = () => { Alert.alert( `Are you sure you want to delete ${name}?`, // template literal with prop "It will be gone for good", [ { text: "Yes", onPress: () => console.log("Ok, deleting."), style: "destructive" }, { text: "Cancel", style: "cancel" }, ], ); }; return ( <View style={styles.itemContainer}> <Text style={styles.itemText}>{name}</Text> // render prop in JSX <TouchableOpacity onPress={handleDelete} style={styles.button} activeOpacity={0.8}> <Text style={styles.buttonText}>Delete</Text> </TouchableOpacity> </View> ); }

Consuming in App.tsx — now just 3 lines:

import { ShoppingListItem } from "./components/ShoppingListItem"; // Same component, different data — no copy-paste <ShoppingListItem name="Coffee" /> <ShoppingListItem name="Tea" /> <ShoppingListItem name="Milk" />

TypeScript Props — Required vs Optional

TypeScript
Required prop (no ?)

TypeScript errors if caller omits it. Use for data the component cannot render without.

type Props = { name: string; }
Optional prop (with ?)

Caller can omit it. Component must handle undefined. Use for non-critical data like subtitle, icon, etc.

type Props = { name?: string; }
★ First TypeScript in the course. It's lightweight — just annotate the type Props object and destructure it. All JS is valid TS, so there's no steep learning curve here.

eslint-plugin-react-native · no-unused-styles

DX Tooling

After refactoring, styles from App.tsx may still exist but no longer be used. This plugin red-underlines them automatically.

# install yarn add -D eslint-plugin-react-native

Add to .eslintrc.js (legacy) or eslint.config.js (flat):

// .eslintrc.js module.exports = { extends: ["expo", "prettier"], plugins: ["prettier", "react-native"], rules: { "prettier/prettier": "error", "react-native/no-unused-styles": "error", }, };
💡 Why it matters during refactors: When you move styles from App.tsx to a child component, you inevitably leave dead styles behind. Without this rule, they silently bloat the file. With it, you get red underlines immediately — safe to delete.

StyleSheet.create — Full Truth

Myth Busting
Production

Just creates a plain JS object. No optimization, no deduplication, no native bridging magic whatsoever.

Development

Validates style prop names are valid. Leftover from early RN days when invalid styles crashed native renderers.

Utility methods

StyleSheet.flatten() · StyleSheet.absoluteFill · StyleSheet.absoluteFillObject — these are the only useful bits.

absoluteFill vs absoluteFillObject

// absoluteFill — ready-to-use style prop (StyleSheet.absoluteFill is a StyleProp) <View style={[StyleSheet.absoluteFill, { backgroundColor: "pink" }]}/> // absoluteFillObject — raw object you can spread + override <View style={{ ...StyleSheet.absoluteFillObject, backgroundColor: "pink" }}/> // Both = { position: 'absolute', top: 0, left: 0, right: 0, bottom: 0 } // Use when you need a full-screen overlay layer (modals, loaders, backgrounds)
⚠️ Render order matters: Kadi demonstrated that elements render in JSX order — a component placed later in JSX renders on top. Important to know when using absoluteFill overlays.
