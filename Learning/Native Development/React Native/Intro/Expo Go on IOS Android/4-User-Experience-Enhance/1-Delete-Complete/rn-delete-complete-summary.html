Updated Type

Data Model
type ShoppingListItemType = { id: string; name: string; + completedAtTimestamp?: number; // undefined = not done | Date.now() = done + lastUpdatedTimestamp: number; // mandatory — drives sort order };
Why number not boolean?

A number timestamp lets us sort completed items by when they were done. A boolean only tells you done/not-done — no ordering info.

lastUpdatedTimestamp

Set on create AND every toggle. Keeps incomplete items ordered by most-recent interaction, not just creation time.

index.tsx — implementation:

const handleDelete = (id: string) => { setShoppingList( shoppingList.filter( (item) => item.id !== id ) ); }; // Pass into FlatList renderItem: onDelete={() => handleDelete(item.id)}
★ Pattern: Parent owns state. Child gets a callback prop — it doesn't know about state, it just calls the function. Parent decides what to do. Clean separation of concerns.
Toggle Complete

handleToggleComplete — map

index.tsx
const handleToggleComplete = (id: string) => { const newList = shoppingList.map((item) => { if (item.id !== id) return item; // leave others untouched return { ...item, lastUpdatedTimestamp: Date.now(), completedAtTimestamp: item.completedAtTimestamp ? undefined // was done → undo : Date.now(), // was not done → mark done }; }); setShoppingList(newList); }; // ShoppingListItem prop — add: onToggleComplete: () => void; // Wrap outer View as Pressable (full-row tap): - <View style={[styles.itemContainer, ...]}> + <Pressable onPress={onToggleComplete} style={[styles.itemContainer, ...]}> // Pass isCompleted dynamically: isCompleted={Boolean(item.completedAtTimestamp)} onToggleComplete={() => handleToggleComplete(item.id)}
💡 filter vs map: Use filter to remove items. Use map to update items in place. Both return new arrays without mutating state.

Sort Order

orderShoppingList — Sort by Timestamp

Array.sort
const orderShoppingList = (list: ShoppingListItemType[]) => { return [...list].sort((a, b) => { // both complete → most recently completed first if (a.completedAtTimestamp && b.completedAtTimestamp) return b.lastUpdatedTimestamp - a.lastUpdatedTimestamp; // a done, b not → b (incomplete) first if (a.completedAtTimestamp && !b.completedAtTimestamp) return 1; // b done, a not → a (incomplete) first if (!a.completedAtTimestamp && b.completedAtTimestamp) return -1; // both incomplete → most recently touched first return b.lastUpdatedTimestamp - a.lastUpdatedTimestamp; }); }; // In FlatList: data={orderShoppingList(shoppingList)}
ScenarioReturnEffect
Both completedb.ts - a.tsMore recently completed goes first
A done, B not+1B (incomplete) moves above A
B done, A not-1A (incomplete) moves above B
Both incompleteb.ts - a.tsMost recently interacted with goes first
★ Why timestamp subtraction works: sort just needs positive/negative/zero. Subtracting two timestamps gives that automatically — no conditionals for relative ordering within a group.
