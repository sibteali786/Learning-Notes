What sub-agents are

Each sub-agent gets its own isolated context window. Work it does never pollutes the main thread. It runs, returns a result, done. Context shard + isolated expertise without the cost of one giant compacted window.

Real-world pitfalls — this feature is days old

Steve's take: "I have never had it pick one on its own just yet — and honestly I don't want it to." Always name the agent explicitly.
Won't auto-activateUnless you mention the agent by name, it probably won't fire. Description-based delegation is unreliable. Name it explicitly every time.
Context lost on rejectDecline a draft → that agent's context is gone. Main agent spins up a fresh copy. Those tokens are gone too.
Black box executionNo mid-stream visibility. No clarifying questions mid-task. You wait for a lump-sum result and accept or reject it.
Token + time bloatEach agent = another context window. Serialized (not parallelized) by default — it runs them one at a time. Rate limits hit 4–5x faster with fleets.
Too many chefsOverlapping agent roles cause ping-ponging. Keep roles distinct and non-overlapping. 3–4 agents is the right starting point.
Verbose auto-prompts/agents wizard generates bloated system prompts. They eat context and still don't guarantee activation. Trim manually after generating.

Git worktrees — for true parallelization

What they are

Multiple working directories from one repo — separate branches, same filesystem, no conflicts. Each Claude instance runs in its own worktree. Tool: git worktree add. GUI: Crystal app (Electron, open source, actively improving).

Steve's honest take

He stopped using them. "I'm still the main thread, I'm still blocking." Reviewing 4 parallel code streams in parallel doesn't make you 4x faster — you're still the bottleneck. They also hit rate limits 4–5x faster and leave behind directories to clean up.

Best practices — start here

Start with 3–4 agents max. Clear non-overlapping roles. Add more as you understand the system.

Always name the agent explicitly — don't rely on auto-delegation. "Use the junior-engineer agent to review this plan."

Restrict tools per agent. Test engineer gets Playwright. Architect gets read-only + markdown. No agent touches .eslintrc except the one you designate.

Use shared files (PLAN.md, QUESTIONS.md) for handoffs — agents can write to and read from them for persistent coordination.

Version control project agents in .claude/agents/ — team benefits from and improves them over time.

The real value isn't speed — it's isolated context and the ability to get an unbiased second opinion without polluting the main thread.
