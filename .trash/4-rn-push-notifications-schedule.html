Local vs Remote Push Notifications

Concept
Remote (not covered)

Server sends notification via Apple APNs / Firebase FCM to device's push token. Requires backend server, token registration, significant setup. Not workshopable.

Local (this chapter) ✓

Scheduled from within the app, delivered to the current device only. No server needed. Works in Expo Go. What we build here.

★ Real-world use: Local notifications power reminders, alarms, recurring nudges ("You haven't checked your list today!"). Remote notifications power chat messages, breaking news alerts, order updates.

utils/registerForPushNotificationsAsync.ts

New File
import { Platform } from "react-native"; import * as Device from "expo-device"; import * as Notifications from "expo-notifications"; export async function registerForPushNotificationsAsync() { // Android 8+ requires a channel BEFORE requesting permission if (Platform.OS === "android") { await Notifications.setNotificationChannelAsync("default", { name: "default", importance: Notifications.AndroidImportance.DEFAULT, vibrationPattern: [0, 250, 250, 250], showBadge: false, }); } // Simulators/emulators can't receive push notifications if (!Device.isDevice) return null; // Check current status — only request if undetermined const { status: existingStatus } = await Notifications.getPermissionsAsync(); if (existingStatus !== "granted") { const { status } = await Notifications.requestPermissionsAsync(); return status; // shows native prompt if undetermined, no-op if denied } return existingStatus; }

Permission Status Values

StatusMeaningrequestPermissionsAsync() effect
undeterminedNever asked beforeShows native prompt ← only time it works
grantedUser said yesNo-op — already have permission
deniedUser said noNo-op — cannot re-ask in-app

The Ask-Once Rule

Critical
⚠️ You can only show the native permission prompt once. If the user taps "Don't Allow", you can never ask again programmatically. requestPermissionsAsync() becomes a silent no-op.

Recovery path for denied

User must go to Settings → Notifications → [Your App] and manually toggle on. In Expo Go during development: Settings → Notifications → Expo Go → toggle on.

💡 Best practice: Show your own in-app explanation screen before triggering the native prompt. If the user understands why you need notifications, they're more likely to allow — and you only get one shot.

⚠️ fontWeight must be a string. fontWeight: 700 (number) crashes on Android. Always use fontWeight: "bold" or "700" (string). Works fine on iOS but crashes Android silently.
Android channel — why it's required

Android 8.0+ groups notifications by channel. Android 13+ requires at least one channel to exist before the permission prompt will even appear. The utility handles this automatically with setNotificationChannelAsync before requesting permission.
